CUDA Study Order

CUDA Study Order

CUDA를 공부할 때는 문법부터 외우기보다, CPU와 GPU가 일을 나누는 방식부터 잡는 것이 좋다. 아래 순서는 CUDA C/C++ 기준으로 핵심 개념을 먼저 익히고, 이후 Python CUDA(Numba, CuPy, PyTorch extension 등)로 확장하는 흐름이다.

0. 선수 지식

CUDA는 병렬 프로그래밍, 메모리 계층, C/C++ 포인터 개념이 같이 쓰인다.

먼저 확인할 것:

  • C/C++ 기본 문법
  • 포인터와 배열
  • stack / heap 메모리
  • CPU cache 개념
  • thread, process 차이
  • 행렬 연산 기초
  • Python + NumPy 배열 연산

실습:

  • C/C++에서 1차원 배열과 2차원 배열을 포인터로 접근해보기
  • NumPy로 vector add, matrix multiplication 구현하기
  • 같은 연산을 Python loop와 NumPy vectorized 연산으로 비교하기

1. GPU가 빠른 이유

GPU는 하나의 복잡한 일을 빠르게 처리하는 장치라기보다, 같은 연산을 많은 데이터에 동시에 적용하는 장치다.

핵심 개념:

  • CPU: 적은 수의 강한 core
  • GPU: 많은 수의 작은 core
  • SIMD / SIMT
  • data parallelism
  • latency hiding
  • throughput 중심 구조

정리할 질문:

  • 어떤 작업이 GPU에 적합한가?
  • 어떤 작업은 GPU에 올려도 느릴 수 있는가?
  • branch가 많은 코드는 왜 GPU에 불리한가?

예시로 적합한 작업:

  • vector add
  • image filtering
  • matrix multiplication
  • convolution
  • particle simulation
  • deep learning tensor operation

예시로 부적합한 작업:

  • 데이터 의존성이 강한 순차 알고리즘
  • 작은 데이터에 대한 단발성 계산
  • CPU-GPU 복사 비용이 계산 비용보다 큰 작업

2. CUDA 실행 모델

CUDA의 가장 중요한 출발점은 thread, block, grid 구조다.

핵심 개념:

  • kernel: GPU에서 실행되는 함수
  • thread: 실제 계산을 수행하는 최소 단위
  • block: thread 묶음
  • grid: block 묶음
  • warp: 보통 32개 thread 단위로 스케줄링되는 실행 단위

기본 구조:

__global__ void kernel(float* a, float* b, float* c, int n) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;

    if (idx < n) {
        c[idx] = a[idx] + b[idx];
    }
}

실행 설정:

int threadsPerBlock = 256;
int blocksPerGrid = (n + threadsPerBlock - 1) / threadsPerBlock;

kernel<<<blocksPerGrid, threadsPerBlock>>>(a, b, c, n);

공부 포인트:

  • threadIdx
  • blockIdx
  • blockDim
  • gridDim
  • 1D / 2D / 3D grid
  • boundary check가 필요한 이유

실습:

  • vector add kernel 작성
  • 2D image index를 thread index로 매핑
  • 입력 크기가 block 크기로 나누어떨어지지 않는 경우 처리

3. Host와 Device

CUDA에서는 CPU 영역을 host, GPU 영역을 device라고 부른다.

핵심 개념:

  • host memory
  • device memory
  • cudaMalloc
  • cudaMemcpy
  • cudaFree
  • host to device 복사
  • device to host 복사

기본 흐름:

  1. CPU에서 입력 데이터 준비
  2. GPU 메모리 할당
  3. CPU 데이터를 GPU로 복사
  4. CUDA kernel 실행
  5. 결과를 CPU로 복사
  6. GPU 메모리 해제

예시:

float* d_a;
cudaMalloc(&d_a, n * sizeof(float));

cudaMemcpy(d_a, h_a, n * sizeof(float), cudaMemcpyHostToDevice);

kernel<<<blocks, threads>>>(d_a);

cudaMemcpy(h_a, d_a, n * sizeof(float), cudaMemcpyDeviceToHost);

cudaFree(d_a);

주의할 점:

  • GPU 계산이 빨라도 메모리 복사가 많으면 전체 성능은 느려질 수 있다.
  • GPU에 올릴 만큼 연산량이 충분해야 한다.
  • cudaMemcpy 방향을 헷갈리지 않도록 한다.

실습:

  • vector add 전체 흐름 구현
  • cudaMemcpy 시간을 포함한 전체 시간 측정
  • CPU 버전과 GPU 버전 비교

4. CUDA 메모리 계층

CUDA 성능은 연산보다 메모리 접근 패턴에서 많이 갈린다.

메모리 종류:

  • register
  • local memory
  • shared memory
  • global memory
  • constant memory
  • texture memory

중요도 순서:

  1. global memory 접근 비용 이해
  2. shared memory 사용법
  3. coalesced memory access
  4. bank conflict
  5. register pressure

핵심 개념:

  • global memory는 크지만 느리다.
  • shared memory는 block 안의 thread들이 공유하며 빠르다.
  • 연속된 thread가 연속된 메모리를 읽으면 효율이 좋다.
  • thread마다 너무 많은 변수를 쓰면 register 부족으로 성능이 떨어질 수 있다.

실습:

  • global memory만 사용하는 matrix transpose 구현
  • shared memory를 사용하는 matrix transpose 구현
  • 두 버전의 실행 시간 비교

5. 동기화와 Race Condition

GPU thread는 동시에 실행되므로 같은 메모리를 여러 thread가 수정하면 문제가 생긴다.

핵심 개념:

  • race condition
  • __syncthreads()
  • atomic operation
  • block 내부 동기화
  • block 간 동기화는 kernel 하나 안에서 직접 하기 어렵다는 점

예시:

__shared__ float tile[256];

tile[threadIdx.x] = input[idx];
__syncthreads();

주의할 점:

  • __syncthreads()는 같은 block 안에서만 동작한다.
  • 조건문 안에서 일부 thread만 __syncthreads()를 만나면 deadlock이 생길 수 있다.
  • atomic은 편하지만 많이 쓰면 병목이 된다.

실습:

  • parallel reduction 구현
  • atomic add로 histogram 구현
  • atomic 버전과 reduction 버전 비교

추천 실습 순서:

7. 성능 측정과 디버깅

CUDA는 돌아가는 코드와 빠른 코드 사이의 차이가 크다. 반드시 측정하면서 공부해야 한다.

도구:

  • cudaEvent
  • NVIDIA Nsight Systems
  • NVIDIA Nsight Compute
  • nvidia-smi
  • compute-sanitizer

확인할 지표:

  • kernel execution time
  • memory bandwidth
  • occupancy
  • warp divergence
  • global memory load/store efficiency
  • shared memory bank conflict

기본 시간 측정:

cudaEvent_t start, stop;
cudaEventCreate(&start);
cudaEventCreate(&stop);

cudaEventRecord(start);
kernel<<<blocks, threads>>>(...);
cudaEventRecord(stop);

cudaEventSynchronize(stop);

float ms = 0;
cudaEventElapsedTime(&ms, start, stop);

실습:

  • block size를 64, 128, 256, 512로 바꿔가며 시간 측정
  • shared memory 적용 전후 비교
  • CPU-GPU memory copy 시간을 따로 측정

8. Python에서 CUDA 사용

CUDA C/C++을 어느 정도 이해한 뒤 Python CUDA를 보면 훨씬 쉽다.

주요 선택지:

  • Numba CUDA
  • CuPy
  • PyTorch CUDA tensor
  • PyTorch C++/CUDA extension
  • Triton

학습 순서:

  1. NumPy 연산과 GPU 연산 차이 이해
  2. Numba @cuda.jit로 직접 kernel 작성
  3. CuPy로 NumPy 스타일 GPU 배열 연산
  4. PyTorch tensor가 GPU에서 동작하는 방식 이해
  5. 필요하면 PyTorch custom CUDA extension 작성
  6. Triton으로 행렬 연산 kernel 작성

Numba 예시:

from numba import cuda

@cuda.jit
def vector_add(a, b, c):
    i = cuda.grid(1)
    if i < c.size:
        c[i] = a[i] + b[i]

실습:

  • Numba로 vector add 구현
  • Numba로 2D convolution 구현
  • CuPy와 직접 kernel 버전 비교
  • PyTorch tensor 연산과 직접 CUDA kernel 비교

  • race condition이 생기는 코드를 구분할 수 있다.
  • reduction을 직접 구현할 수 있다.
  • matrix multiplication을 naive 버전과 tiled 버전으로 구현할 수 있다.

  • Numba CUDA로 간단한 kernel을 작성할 수 있다.

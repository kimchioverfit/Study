    Git 개요 — 4개의 공간과 문서 안내

    Git은 파일의 변경 이력을 스냅샷 단위로 저장하는 분산 버전 관리 시스템(DVCS) 임. 모든 개발자가 전체 히스토리를 로컬에 통째로 복제해 두고, 필요할 때만 원격과 주고받음.

    Git이 다루는 4개의 공간

    명령어를 외우기 전에 파일이 오가는 공간을 먼저 이해하면 대부분의 명령이 “어디에서 어디로 옮기는가"로 정리됨.

    Working Directory   Staging Area(Index)   Local Repository   Remote Repository
   (작업 폴더)          (커밋 예정 목록)        (.git 안 커밋)        (GitHub 등)
       │                     │                     │                    │
       │──── git add ───────▶│                     │                    │
       │                     │──── git commit ────▶│                    │
       │                     │                     │──── git push ─────▶│
       │◀──── git restore ───│                     │                    │
       │◀──────────────── git pull / fetch ───────────────────────────│
    공간의미확인 명령
    Working Directory실제로 편집 중인 파일들git status
    Staging Area (Index)다음 커밋에 포함할 변경만 골라 담아둔 곳git status, git diff --staged
    Local Repository커밋으로 확정되어 .git에 저장된 히스토리git log
    Remote Repository서버(GitHub/GitLab 등)에 있는 공유 저장소git remote -v

    문서 안내

    문서내용
    01. 기본 명령어init·config, add·commit, log·diff
    02. 브랜치 & 원격branch·switch·merge, remote·push·pull, fetch –prune
    03. 되돌리기 & 복구restore·reset·revert, stash, reflog 복구
    04. Rebase 완전 정리merge vs rebase, 충돌, pull –rebase, interactive
    05. Cherry-pick특정 커밋만 골라 옮기기

    자주 쓰는 워크플로 예시

    # 1. 새 기능 시작
git switch main
git pull                       # main 최신화
git switch -c feature/login    # 기능 브랜치 생성

# 2. 작업 & 커밋
git add .
git commit -m "feat: 로그인 폼 추가"

# 3. 작업 도중 main이 바뀌었으면 최신 위로 rebase
git fetch origin
git rebase origin/main

# 4. 원격에 올리고 PR 생성
git push -u origin feature/login

    요약 치트시트

    하고 싶은 것명령어
    저장소 복제git clone <url>
    상태 확인git status
    스테이징git add .
    커밋git commit -m "msg"
    브랜치 생성+이동git switch -c <name>
    병합git merge <name>
    최신 위로 재정렬git rebase main
    특정 커밋만 가져오기git cherry-pick <commit>
    원격 반영git push
    원격 가져오기git pull
    원격에서 지워진 브랜치 정리git fetch --prune
    안전하게 되돌리기git revert <commit>
    임시 보관git stash / git stash pop
    실수 복구git reflog → git reset --hard <sha>

    05 Cherry Pick

    Git Cherry-pick — 특정 커밋만 골라 옮기기

    한 줄 정의

    cherry-pick = 다른 브랜치의 커밋 중 “원하는 것 하나(또는 몇 개)만” 콕 집어 현재 브랜치에 복사해 얹는 것.

    rebase 가 브랜치의 커밋 뭉치를 통째로 옮긴다면, cherry-pick은 낱개 커밋만 골라 옴. 이름 그대로 “체리(좋은 커밋)만 집어 먹음”.

    언제 쓰나

    • 급한 버그 수정 커밋을 다른 브랜치(예: 릴리스 브랜치)에도 hotfix로 반영해야 할 때
    • 다른 브랜치에서 만든 커밋 하나가 지금 내 브랜치에 필요할 때
    • 실수로 엉뚱한 브랜치에 한 커밋을, 옳은 브랜치로 옮길 때

    시각화

    feature에 D, E, F가 있는데, 그중 E만 main으로 가져오고 싶음.

    시작 상태:

    gitGraph
   commit id: "A"
   commit id: "B"
   branch feature
   checkout feature
   commit id: "D"
   commit id: "E (원하는 커밋)"
   commit id: "F"

    git cherry-pick <E의 해시> 실행 후 — E의 변경만 복사되어 main에 E'로 얹힌다:

    gitGraph
   commit id: "A"
   commit id: "B"
   commit id: "E' (E의 복사본)"
    • E의 내용만 복사되고 부모가 B로 바뀌므로 해시가 다른 새 커밋 E'가 됨 (rebase처럼 ').
    • D와 F는 따라오지 않음 — 오직 지정한 커밋만.

    사용법

    git switch main
git cherry-pick <E의 해시>          # 커밋 하나

git cherry-pick <해시1> <해시2>     # 여러 개 (나열 순서대로 적용)
git cherry-pick <시작>..<끝>        # 범위 (시작 제외 ~ 끝 포함)

    충돌이 나면 rebase와 비슷하게 처리한다:

    # 충돌 파일 수정 후
git add <해결한 파일>
git cherry-pick --continue
git cherry-pick --abort            # 포기하고 원상복구

    rebase / merge / cherry-pick 비교

    명령옮기는 단위히스토리 결과
    merge브랜치 전체를 병합 커밋으로 합침갈래 보존
    rebase브랜치의 커밋 뭉치를 통째로 재배치일직선
    cherry-pick낱개 커밋만 골라 복사원하는 커밋만 추가

    주의: cherry-pick도 커밋을 복사(새 해시 생성) 함. 원본 브랜치를 나중에 merge하면 “같은 변경이 두 번” 들어와 충돌하거나 중복될 수 있으니, 무엇을 어디로 가져왔는지 기억해 둘 것.

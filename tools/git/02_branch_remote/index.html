Git 브랜치 & 원격 저장소

4. 브랜치 (branch / switch / merge)

명령어설명
git branch브랜치 목록
git branch <name>새 브랜치 생성
git switch <name>브랜치 이동 (구버전: git checkout <name>)
git switch -c <name>브랜치 생성 + 이동
git branch -d <name>브랜치 삭제 (병합된 것만)
git branch -D <name>브랜치 강제 삭제
git merge <name>현재 브랜치에 <name>을 병합

Fast-forward vs 병합 커밋

gitGraph
   commit id: "A"
   commit id: "B"
   branch feature
   checkout feature
   commit id: "C"
   commit id: "D"
   checkout main
   merge feature id: "M"
  • main이 B 이후 갈라진 적 없다면 merge는 포인터만 앞으로 옮긴다 (fast-forward, 커밋 안 생김).
  • main도 따로 나아갔다면 위처럼 두 갈래를 잇는 병합 커밋 M 이 생긴다.
  • 병합 커밋 없이 일직선으로 정리하고 싶다면 merge 대신 04. Rebase 를 쓴다.

5. 원격 저장소 (remote / push / pull)

명령어설명
git remote -v연결된 원격 저장소 확인
git remote add origin <url>원격 저장소 등록
git push origin <branch>로컬 커밋을 원격에 업로드
git push -u origin <branch>업스트림 지정 후 push (이후엔 git push만)
git fetch원격 변경을 가져오기만 함 (병합 X)
git pullfetch + merge (또는 --rebase)

git pull = git fetch + git merge. 히스토리를 깔끔하게 유지하려면 git pull --rebase를 쓰기도 한다 (04. Rebase 참고).

fetch vs pull

  • fetch는 원격 내용을 가져와 원격 추적 브랜치에만 반영한다 — 내 작업 브랜치는 건드리지 않아 안전하게 먼저 확인할 수 있다.
  • pull은 그 fetch 결과를 곧바로 내 브랜치에 병합까지 한다.

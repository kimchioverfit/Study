Constexpr

Constexpr

constexpr은 “이 값/함수는 컴파일 타임에 평가될 수 있다“는 표시다. 결론부터: const는 “안 바꾼다"는 약속이고, constexpr은 “컴파일 타임에 값이 확정된다"는 보장이다. 이 둘은 다른 개념이다.

constexpr 함수/변수를 헤더에 둘 때의 ODR 문제와 암시적 inline 규칙은 Inline 문서에서 다룬다.

1. const vs constexpr

int runtime_val() { return 42; }

const int a = runtime_val();   // ✅ OK — 런타임에 정해지는 상수 ("한 번 정해지면 안 바꿈")
constexpr int b = runtime_val();  // ❌ 컴파일 에러 — 컴파일 타임에 값을 알 수 없음
constexpr int c = 42;          // ✅ OK — 컴파일 타임 상수
구분constconstexpr
의미초기화 후 수정 불가컴파일 타임에 값 확정 (+ 자동으로 const)
초기값런타임 값도 가능컴파일 타임 상수식만
배열 크기, 템플릿 인자, case 라벨초기값에 따라 될 수도/안 될 수도항상 가능
constexpr int N = 8;
int arr[N];                    // ✅ 배열 크기
std::array<int, N> arr2;       // ✅ 템플릿 인자
  • 배열 크기 등 “컴파일 타임 상수가 필요한 자리"에 쓸 값이라면 const가 아니라 constexpr로 선언하는 것이 의도를 정확히 드러낸다
  • C의 #define N 8 매크로 상수를 대체하는 현대 C++ 방식이기도 하다 — 타입이 있고, 스코프를 따르고, 디버거에 보인다

2. constexpr 함수 — 이중 성격

constexpr 함수는 “컴파일 타임 전용“이 아니다. 인자가 컴파일 타임 상수면 컴파일 타임에, 아니면 일반 함수처럼 런타임에 평가된다.

constexpr int square(int x) { return x * x; }

constexpr int a = square(5);   // 컴파일 타임 — a는 25로 박제됨 (기계어에 계산 코드 없음)
int n; std::cin >> n;
int b = square(n);             // 런타임 — 일반 함수 호출과 동일
  • 같은 함수를 두 벌(컴파일용/런타임용) 만들 필요가 없다는 것이 설계 의도
  • 컴파일 타임 평가를 강제하고 싶으면 결과를 constexpr 변수에 받으면 된다: constexpr int a = square(5); — 평가 불가능하면 컴파일 에러가 난다
  • C++11에선 return 한 줄만 허용됐지만, C++14부터 지역 변수·루프·분기 등 대부분의 코드 허용. C++20부터는 constexpr 안에서 new/delete, vector, string까지 가능 (컴파일 타임 안에서 할당·해제가 완결되는 조건)

실전 활용 — 룩업 테이블 컴파일 타임 생성:

constexpr std::array<int, 256> make_table() {
    std::array<int, 256> t{};
    for (int i = 0; i < 256; i++)
        t[i] = /* 미리 계산해둘 값 */ i * i % 251;
    return t;
}

constexpr auto TABLE = make_table();   // 바이너리에 완성된 테이블이 박힘 — 런타임 초기화 비용 0

CRC 테이블, 감마 보정 테이블, 삼각함수 근사 테이블 등 — 예전엔 스크립트로 생성해서 소스에 붙여넣던 것들을 컴파일러가 만들게 할 수 있다.

3. if constexpr (C++17) — 컴파일 타임 분기

일반 if는 양쪽 브랜치가 모두 컴파일되어야 하지만, if constexpr는 선택되지 않은 브랜치를 컴파일 대상에서 제외한다. 템플릿에서 타입에 따라 다른 코드를 쓸 때 필수.

template <typename T>
std::string stringify(T x) {
    if constexpr (std::is_arithmetic_v<T>)
        return std::to_string(x);      // T가 string일 때 이 줄은 컴파일 자체를 안 함
    else
        return x;
}

stringify(42);              // to_string 브랜치만 존재
stringify(std::string("hi")); // return x 브랜치만 존재
  • 일반 if였다면 to_string(std::string)이 없어서 양쪽 다 인스턴스화하려다 컴파일 에러
  • 템플릿 특수화나 SFINAE로 하던 분기를 훨씬 읽기 쉽게 대체한다
  • 주의: 템플릿 밖의 if constexpr는 버려지는 브랜치도 문법 검사를 받는다 — 템플릿 안에서만 “컴파일 제외” 효과가 완전하다

4. consteval / constinit (C++20)

constexpr 함수의 “컴파일도 되고 런타임도 되는” 유연함이 오히려 문제일 때를 위한 키워드들.

consteval int square_ct(int x) { return x * x; }  // 컴파일 타임 전용

constexpr int a = square_ct(5);   // ✅
int n; std::cin >> n;
int b = square_ct(n);             // ❌ 컴파일 에러 — 런타임 호출 자체가 금지
키워드평가 시점용도
constexpr 함수컴파일 타임 가능, 런타임도 가능범용
consteval 함수컴파일 타임 전용 (immediate function)런타임으로 새면 안 되는 것 — 컴파일 타임 해시, 포맷 문자열 검증 등
constinit 변수초기화만 컴파일 타임 보장, 값은 변경 가능전역 변수의 초기화 순서 문제 해결

constinit의 용도 — 전역/static 변수의 초기화 순서 미정의 문제(static initialization order fiasco)를 컴파일 타임에 차단:

constinit int counter = compute_initial();  // compute_initial이 constexpr이 아니면 컴파일 에러
// → "이 전역 변수는 동적 초기화가 아니다"를 보장. 이후 counter++ 는 자유 (const가 아님)
  • constexpr 변수 = 컴파일 타임 초기화 + 불변
  • constinit 변수 = 컴파일 타임 초기화만 (변경 가능)

템플릿 내 타입별 분기if constexpr
컴파일 타임 전용 함수consteval
전역 변수 초기화 순서 문제 방지constinit
  • constexpr로 컴파일 타임에 확정된 값은 data 영역 초기화조차 필요 없는 경우가 많다 — 리터럴처럼 코드에 직접 박히거나 rodata에 놓인다 (Static 의 메모리 배치 그림과 비교)
  • constexpr 함수는 암시적으로 inline이라 헤더에 정의해도 ODR 위반이 없다. 헤더에 두는 constexpr 변수는 그렇지 않아서 inline constexpr로 써야 프로그램 전체에 하나가 된다 — 자세한 내용은 Inline 참고
  • 템플릿 메타프로그래밍으로 하던 컴파일 타임 계산의 대부분이 constexpr 함수로 단순해졌다 — 재귀 템플릿 대신 그냥 for 루프를 쓰면 된다

Inline

inline은 이름 때문에 가장 오해가 많은 키워드다. 결론부터: 현대 C++에서 inline의 실제 의미는 “인라인 확장 힌트"가 아니라 “여러 번역 단위에 같은 정의가 있어도 하나로 취급하라”(ODR 완화)다. 최적화는 컴파일러가 inline 키워드와 무관하게 알아서 한다.

1. 전제 — ODR (One Definition Rule)

프로그램 전체에서 하나의 함수/변수는 정의가 정확히 한 번이어야 한다.

// util.h
int add(int a, int b) { return a + b; }   // 정의를 헤더에 둠

// a.cpp, b.cpp 둘 다 util.h를 include
// → add의 정의가 두 번역 단위에 존재
// → 링크 에러: multiple definition of `add(int, int)`
  • 헤더는 여러 .cpp에 include되므로, 헤더에 (비-inline) 정의를 쓰면 링크가 깨진다
  • 그래서 전통적으로 헤더에는 선언만, 정의는 .cpp에 두는 것이 규칙이었다

2. inline의 진짜 의미 — ODR 완화

// util.h
inline int add(int a, int b) { return a + b; }   // ✅ 어느 .cpp에 몇 번 include돼도 OK

inline이 붙으면: “이 정의는 여러 번역 단위에 나타나도 된다. 모두 동일하며, 링커야, 하나만 골라 써라.”

  • 링커가 중복 정의를 에러로 삼는 대신 하나로 접는다(fold)
  • 헤더 온리 라이브러리가 가능한 이유가 바로 이것
  • 클래스 정의 안에 몸체를 쓴 멤버 함수는 자동으로 inline — 헤더의 클래스 몸체 안 함수가 링크 에러를 안 내는 이유

“인라인 확장 힌트"로서의 inline은 사실상 죽은 의미다:

  • 현대 컴파일러는 inline 키워드 유무와 무관하게 비용/이득을 계산해 스스로 인라인 확장을 결정한다 (키워드가 없어도 하고, 있어도 무시한다)
  • 확장을 정말 강제하고 싶을 때 쓰는 것은 컴파일러 확장인 __attribute__((always_inline)) (GCC/Clang), __forceinline (MSVC) — 표준 inline이 아니다
  • static 함수와의 차이: static은 번역 단위마다 별개의 사본(internal linkage)을 만들고, inline은 하나로 합쳐질 동일 정의(external linkage 유지)다. 함수 주소를 비교하면 static은 .cpp마다 다르고 inline은 같다

3. inline 변수 (C++17)

C++17부터 변수에도 inline을 붙일 수 있다. 헤더에 전역 변수/상수를 정의하는 문제의 최종 해법.

// config.h — C++17 이전의 고민
const int max_size = 100;          // internal linkage — .cpp마다 사본 (상수라 대개 무해하지만 주소가 다름)
extern const int timeout;          // 선언만 하고 정의는 .cpp에 — 두 파일 관리

// C++17 — 한 줄로 끝
inline constexpr int max_size = 100;   // 프로그램 전체에서 단 하나의 개체
inline int global_counter = 0;         // 가변 전역도 헤더에 정의 가능 (하나로 접힘)
  • inline constexpr — 요즘 라이브러리 헤더에서 흔히 보는 관용구. 컴파일 타임 상수(Constexpr )이면서 프로그램 전체에 하나만 존재
  • 모든 번역 단위에서 주소가 같다는 것이 핵심 (사본 방식은 주소 비교, ODR-use 시 문제가 될 수 있음)

4. constexpr과의 관계

규칙의미
constexpr 함수는 암시적으로 inline헤더에 정의해도 ODR 위반 없음 — constexpr 함수를 헤더에 두는 이유. 컴파일 타임 평가를 하려면 각 번역 단위가 함수의 몸체를 볼 수 있어야 하므로 설계상 필연
constexpr static 멤버 변수는 C++17부터 암시적 inline클래스 밖 별도 정의(const int C::N;)가 필요 없어졌다
constexpr 일반 변수는 inline이 아님헤더의 constexpr int x = 1;은 번역 단위마다 사본 → 하나로 만들려면 명시적으로 inline constexpr
struct Config {
    static constexpr int N = 8;    // C++17부터 이 한 줄로 정의까지 완료 (암시적 inline)
};

// C++14 이전엔 ODR-use 시 .cpp에 추가로 필요했다:
// constexpr int Config::N;

5. 정리

상황선택
헤더에 함수 정의를 두고 싶다inline (또는 constexpr이면 자동)
헤더에 컴파일 타임 상수를 두고 싶다inline constexpr 변수
헤더에 가변 전역 변수를 두고 싶다inline 변수 (C++17) — 정말 전역이 필요한지는 별개 문제
.cpp 내부 전용 헬퍼static 또는 익명 namespace — inline과 목적이 다름
인라인 확장을 강제하고 싶다표준 방법 없음 — always_inline/__forceinline (컴파일러 확장), 그 전에 컴파일러를 믿을 것
  • inline = “하나로 접어라”(링크 의미론), 인라인 확장 = 컴파일러의 최적화 결정. 이 둘을 분리해서 기억하면 혼란이 없다
  • 클래스 몸체 안 멤버 함수, constexpr 함수, 템플릿은 모두 사실상 inline 취급 — “헤더에 정의가 살아도 되는 것들"의 목록이다

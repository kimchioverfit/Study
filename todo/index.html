    P1BERT논문encoder-only. 기존 Transformer 문서를 그대로 재활용할 수 있어 싸게 먹힘

    1. 논문 공부

    상태논문우선순위메모
    ✅EoMT—작성 완료
    ⬜MaskFormerP0mask classification 으로 틀을 바꾼 지점. EoMT 를 이해하려면 여기부터
    ⬜Mask2FormerP0masked attention + self/cross 순서 교체. 순서 얘기는 Cross-Attention §5.1 에 이미 정리해 둠
    ⬜RoPEP0회전 행렬로 상대 위치를 넣는 방식. 기존 sinusoidal 과 비교표로 쓰면 됨
    ⬜CLIPP1이미지·텍스트 공동 임베딩. 3·4번 트랙이 전부 여기 기댐
    ⬜seq2seqP1RNN encoder-decoder + Bahdanau attention. 짧게
    ⬜BERTP1MLM/NSP, encoder-only. GPT 계열과의 갈림길까지
    ⬜SAMP2promptable segmentation. MaskFormer 계열을 본 뒤가 순서상 맞음
    ⬜HieraP2계층적 ViT. Swin 과 비교하면서 쓰면 수월함
    ⬜DINOP2⚠️ 어느 쪽인지 정해야 함 (아래 참고)

    ⚠️ DINO 는 전혀 다른 논문 두 개가 같은 이름을 씀.

    내용계보
    DINO (2021)self-distillation 기반 자기지도 학습DINOv2 로 이어짐
    DINO (2022)DETR 개선 검출기 (denoising anchor box)DETR → Deformable DETR → DINO

    목록의 다른 항목이 segmentation·detection 쪽에 몰려 있어서 2022 쪽일 가능성이 높아 보이는데, 확정은 보류함. 2022 쪽이면 P1 로 올려야 함 — DETR 문서가 이미 있어서 바로 이어지기 때문임.

    2. CUDA — 동기화

    상태항목우선순위메모
    ⬜__syncthreads() 와 블록 내 동기화P1Kernel 문서에 이어 붙이면 됨
    ⬜warp 단위 동기화 (__syncwarp, warp divergence)P2Volta 이후 independent thread scheduling 때문에 필요해진 부분
    ⬜stream 과 event — 커널 간 비동기·순서 보장P2추론 파이프라인 최적화와 직결됨
    ⬜host-device 동기화 (cudaDeviceSynchronize, 암묵적 동기화 지점)P2프로파일링할 때 “왜 여기서 멈추지” 의 대부분이 여기임
    ⬜atomic 연산과 race conditionP3Atomic 문서의 CPU 쪽 내용과 비교하면 좋음

    동기화는 “안 하면 틀린 값” 과 “너무 하면 느림” 양쪽이라, 정확성 먼저 잡고 성능으로 가는 순서가 맞음.

    3. GEN AI

    상태항목우선순위메모
    ⬜이미지 생성 방식 조사P1GAN / VAE / Diffusion / Flow 를 한 장에 비교. VAE 가 이미 있어서 거기서 출발
    ⬜관련 논문 리스트업P2위 비교표를 먼저 만든 뒤, 칸마다 대표 논문을 채우는 순서
    ⬜Local 모델 종류 조사P2실행 가능한 것 위주 — 단일 GPU·Windows 에서 뭐가 도는지가 기준

    순서를 이렇게 둔 이유 — “어떤 방식들이 있나” 를 먼저 세워야 논문 리스트업과 로컬 모델 조사가 분류 가능한 작업이 됨. 반대로 하면 모델 이름만 잔뜩 모이고 정리가 안 됨.

    Local 모델 조사는 Multi-GPU Training 에 적어 둔 제약(단일 GPU + Windows)을 그대로 기준으로 삼으면 됨. VRAM 요구량과 양자화 지원 여부가 실질 기준임.

    4. VLM — 기초 논문 조사

    상태항목우선순위메모
    ⬜CLIPP1 (1번과 공유)여기가 출발점. 1번 트랙에서 쓰면 이 트랙도 같이 열림
    ⬜이미지 토큰을 LLM 에 넣는 방식 조사P2projection / Q-Former / cross-attention 세 갈래 비교
    ⬜대표 모델 계보 정리P3위 분류가 선 뒤에 채우는 게 맞음

    VLM 은 1번(CLIP)과 3번(생성 방식)이 선행이라 마지막에 둠. 먼저 손대면 용어가 계속 막힘.

    분류 기준

    등급뜻
    P0이미 공개된 문서가 참조하거나 전제하는데 비어 있음. 지금 메워야 기존 글이 완결됨
    P1여러 트랙의 공통 전제이거나, 기존 문서를 재활용해 싸게 쓸 수 있음
    P2독립적으로 쓸 수 있고 분량이 큼
    P3앞 단계의 분류가 선 뒤에야 작업이 정의되는 것

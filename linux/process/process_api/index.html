Process API

Linux Process API

프로세스의 생성 이후 — 실행 이미지 교체, 식별, 대기/회수, 종료까지 담당하는 대표 함수들 정리. 프로세스 생성(fork/vfork/clone)은 Fork 문서 참고.

1. exec 계열 — 실행 이미지 교체

1-1. exec의 본질

exec는 새 프로세스를 만들지 않는다. 현재 프로세스의 주소 공간(code/data/heap/stack)을 새 실행 파일의 이미지로 통째로 교체하는 것이다.

  • PID는 그대로 유지된다 (같은 프로세스)
  • 성공하면 절대 리턴하지 않는다 — 기존 코드는 이미 사라졌으므로 돌아올 곳이 없다
  • 리턴했다면 그것은 무조건 실패한 경우다 (-1 반환, errno 설정)
execve("/bin/ls", argv, envp);
perror("execve failed");   // 여기 도달했다면 exec 실패
_exit(127);

1-2. exec 6형제 구분법

이름에 붙는 접미사로 구분한다. l vs v (인자 전달 방식), e (환경 지정), p (PATH 탐색).

함수인자 전달PATH 탐색환경 지정
execl(path, arg0, ..., NULL)나열 (list)❌❌ (부모 것 상속)
execv(path, argv)배열 (vector)❌❌
execle(path, arg0, ..., NULL, envp)나열❌✅
execve(path, argv, envp)배열❌✅
execlp(file, arg0, ..., NULL)나열✅❌
execvp(file, argv)배열✅❌
  • 진짜 시스템 콜은 execve() 하나뿐이고, 나머지 5개는 전부 이를 감싼 라이브러리 함수다
  • p 계열은 ls처럼 파일명만 줘도 $PATH에서 찾아준다. 단, 신뢰할 수 없는 환경에서는 PATH 조작 공격 위험이 있으므로 절대 경로 + execve가 안전하다
// 같은 동작의 세 가지 표현
execl("/bin/ls", "ls", "-al", (char *)NULL);
char *argv[] = { "ls", "-al", NULL };
execv("/bin/ls", argv);
execvp("ls", argv);   // PATH에서 ls를 찾음

1-3. exec 후에도 유지되는 것

주소 공간은 교체되지만 프로세스라는 그릇 자체는 그대로이므로, 다음은 exec를 넘어 유지된다.

유지되는 것비고
PID, PPID같은 프로세스이므로 당연히 유지
열린 파일 디스크립터FD_CLOEXEC 플래그가 없는 한 유지 — 리다이렉션 구현의 핵심 원리
현재 작업 디렉토리, umask유지
시그널 무시(SIG_IGN) 설정유지. 단 커스텀 핸들러는 코드가 사라졌으므로 SIG_DFL로 리셋
// 셸의 리다이렉션 (ls -al > out.txt) 구현 원리
if (fork() == 0) {
    int fd = open("out.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    dup2(fd, STDOUT_FILENO);   // stdout을 파일로 교체
    close(fd);
    execvp("ls", argv);        // fd는 exec 후에도 유지됨
    _exit(127);
}

1-4. posix_spawn() — fork+exec의 대안

fork() + exec() 조합을 한 번에 수행해주는 표준 함수. 멀티스레드 환경에서 fork의 lock 문제(Fork 문서 2장 참고)를 피할 수 있고, 내부적으로 vfork/clone(CLONE_VM|CLONE_VFORK) 최적화 경로를 쓰는 구현이 많아 성능도 좋다.

#include <spawn.h>

pid_t pid;
posix_spawn(&pid, "/bin/ls", NULL, NULL, argv, envp);
waitpid(pid, &status, 0);
  • fork-exec 사이에서 하던 커스터마이징(리다이렉션 등)은 posix_spawn_file_actions_t로 선언적으로 지정한다
  • 멀티스레드 프로그램에서 자식 프로세스를 띄울 때의 실무 표준 선택지

2. 프로세스 식별 — getpid(), getppid(), gettid()

#include <unistd.h>

pid_t getpid(void);    // 내 프로세스 ID
pid_t getppid(void);   // 부모 프로세스 ID
pid_t gettid(void);    // 내 스레드 ID (Linux 고유)
함수반환값비고
getpid()프로세스(스레드 그룹) ID같은 프로세스의 모든 스레드가 같은 값
getppid()부모의 PID부모가 먼저 죽으면 재부모화(reparenting)되어 값이 바뀜 (전통적으로 1번 init, 현대 리눅스는 subreaper 또는 systemd)
gettid()커널 태스크 ID스레드마다 다른 값. main thread는 getpid() == gettid()
  • getpid()가 스레드마다 같은 이유: pthread는 clone(CLONE_THREAD)로 만들어져 같은 스레드 그룹(TGID)에 속하기 때문 (Fork 문서 4장 참고)
  • 실패하지 않는 시스템 콜이다 (에러 리턴 없음)
  • fork 직후 부모/자식 구분에 쓰는 값은 getpid()가 아니라 fork()의 반환값임에 주의

3. 자식 대기와 회수 — wait(), waitpid(), waitid()

3-1. 왜 wait가 필요한가 — 좀비 프로세스

자식이 종료해도 커널은 종료 상태(exit status)를 부모에게 전달하기 위해 프로세스 테이블 엔트리를 즉시 지우지 않는다. 부모가 wait 계열 함수로 상태를 읽어갈 때까지 남아있는 이 상태가 좀비(zombie, defunct) 다.

상태정의문제점
좀비 (zombie)자식은 죽었는데 부모가 wait를 안 한 상태메모리는 거의 안 쓰지만 PID를 점유 — 방치하면 PID 고갈
고아 (orphan)부모가 자식보다 먼저 죽은 상태init(systemd)이 새 부모가 되어 대신 wait 해주므로 자동 정리됨

즉 좀비는 “wait를 안 한 부모"의 문제이고, 고아는 시스템이 알아서 처리해준다.

3-2. wait()와 waitpid()

#include <sys/wait.h>

pid_t wait(int *status);                          // 아무 자식이나 하나 기다림
pid_t waitpid(pid_t pid, int *status, int options); // 대상/동작 지정 가능

waitpid의 pid 인자:

값의미
> 0해당 PID의 자식만 기다림
-1아무 자식이나 (wait와 동일)
0나와 같은 프로세스 그룹의 자식
< -1프로세스 그룹 ID가 `

options:

  • WNOHANG — 종료된 자식이 없으면 블록하지 않고 0을 즉시 반환. 이벤트 루프 안에서 폴링하거나 SIGCHLD 핸들러에서 쓰는 핵심 옵션
  • WUNTRACED / WCONTINUED — 정지/재개된 자식도 보고받음

3-3. 종료 상태 해석 매크로

status는 그냥 int가 아니라 비트필드이므로 반드시 매크로로 해석한다.

int status;
pid_t pid = waitpid(-1, &status, 0);

if (WIFEXITED(status)) {
    printf("정상 종료, exit code = %d\n", WEXITSTATUS(status));
} else if (WIFSIGNALED(status)) {
    printf("시그널로 종료, signal = %d\n", WTERMSIG(status));
}
매크로의미
WIFEXITED(s) / WEXITSTATUS(s)정상 종료 여부 / exit 코드 (하위 8비트만)
WIFSIGNALED(s) / WTERMSIG(s)시그널에 의한 종료 여부 / 해당 시그널 번호
WIFSTOPPED(s) / WSTOPSIG(s)정지 여부 / 정지시킨 시그널
WCOREDUMP(s)코어 덤프 생성 여부

3-4. 좀비를 만들지 않는 패턴

// 패턴 1: SIGCHLD 핸들러에서 논블로킹으로 전부 회수
void reap(int sig) {
    while (waitpid(-1, NULL, WNOHANG) > 0)
        ;   // 종료된 자식이 여러 개일 수 있으므로 루프 필수
}

// 패턴 2: 아예 회수를 포기한다고 커널에 선언 (자식이 좀비가 되지 않음)
signal(SIGCHLD, SIG_IGN);

시그널 상세는 Signal 문서 참고.

4. 프로세스 종료 — exit(), _exit(), atexit(), abort()

4-1. exit() vs _exit()

구분exit() (stdlib.h)_exit() (unistd.h)
계층C 라이브러리 함수시스템 콜 (raw)
atexit 핸들러 실행✅❌
stdio 버퍼 플러시✅❌
용도일반적인 프로그램 종료fork/vfork 자식, 시그널 핸들러 등 “정리 없이 즉시 종료"해야 할 때

fork 자식에서 exit()를 쓰면 안 되는 대표적 이유 — 버퍼 이중 출력:

printf("hello");        // 개행 없음 → stdio 버퍼에만 존재
if (fork() == 0) {
    _exit(0);           // OK: 버퍼 플러시 안 함
    // exit(0)이었다면: 부모에게서 COW로 복사된 버퍼를 자식도 플러시
    //                → "hello"가 두 번 출력됨
}

vfork에서는 더 심각하다 — 부모와 메모리를 공유하므로 exit()의 정리 작업이 부모 상태를 직접 파괴할 수 있다 (Fork 문서 5장 참고).

4-2. atexit()

정상 종료(exit() 또는 main 리턴) 시 실행될 핸들러를 등록한다.

void cleanup(void) { remove("/tmp/myapp.pid"); }
atexit(cleanup);
  • 등록 역순(LIFO)으로 실행된다
  • _exit(), 시그널에 의한 종료 시에는 실행되지 않는다 — “반드시 실행되는 보장"이 아님에 주의

4-3. abort()

SIGABRT를 자신에게 보내 비정상 종료 + 코어 덤프를 유발한다. assert() 실패 시 내부적으로 호출되는 함수. 디버깅용 스냅샷을 남기고 죽어야 할 때 사용한다.

5. 간편 실행 — system(), popen()

5-1. system()

int ret = system("ls -al > /tmp/out.txt");

내부적으로 fork() → 자식에서 execl("/bin/sh", "sh", "-c", command) → 부모는 waitpid()를 수행하는 편의 함수다.

5-2. popen()

FILE *fp = popen("ls -al", "r");   // 자식의 stdout을 파이프로 읽음
char buf[256];
while (fgets(buf, sizeof(buf), fp)) { /* ... */ }
pclose(fp);   // 내부적으로 waitpid 수행

fork + pipe + dup2 + exec를 묶은 것으로, 명령어의 출력을 읽거나("r") 입력을 넣을 때("w") 사용한다.

5-3. 실무에서 지양하는 이유

문제설명
셸 인젝션인자를 문자열로 조립하므로, 외부 입력이 섞이면 "; rm -rf /" 같은 주입 공격에 그대로 노출
셸 경유 오버헤드/bin/sh를 한 단계 더 fork+exec — 프로세스 2개 생성
시그널 간섭system()은 실행 중 부모의 SIGINT/SIGQUIT를 무시하도록 바꿔놓아 시그널 처리가 꼬일 수 있음
에러 구분 곤란“셸 실행 실패"와 “명령어 실패"의 반환값 구분이 번거로움

→ 신뢰할 수 없는 입력이 조금이라도 섞이는 경로라면 fork+execv(셸 미경유) 또는 posix_spawn으로 직접 구현하는 것이 원칙이다.

6. 요약 — fork에서 wait까지 한 사이클

pid_t pid = fork();                     // 1. 프로세스 복제
if (pid == 0) {
    execvp("ls", argv);                 // 2. 자식: 실행 이미지 교체
    _exit(127);                         //    (exec 실패 시에만 도달)
} else {
    int status;
    waitpid(pid, &status, 0);           // 3. 부모: 자식 회수 (좀비 방지)
    if (WIFEXITED(status))
        printf("exit=%d\n", WEXITSTATUS(status));
}

Autograd

Autograd (자동 미분)

Autograd = Automatic Gradient.

순전파(forward) 연산을 수행하면서 연산 그래프(computational graph) 를 자동으로 기록해두고, backward() 호출 시 그 그래프를 거꾸로 타고 내려가며 연쇄 법칙(chain rule) 으로 기울기를 계산해주는 엔진.

즉, 학습 파이프라인 의 4~6단계에서

flowchart LR
    A["Forward<br/>(그래프 기록)"] --> B["Loss"] --> C["loss.backward()<br/>(그래프 역주행)"] --> D["param.grad 채워짐"] --> E["optimizer.step()"]

Backpropagation 을 사람이 직접 미분식으로 짜지 않아도 되게 해주는 것이 autograd 의 역할이다.

1. 왜 필요한가

미분을 구하는 방법은 크게 3가지가 있다.

방법설명문제점
수치 미분 (Numerical)$\frac{f(x+h)-f(x)}{h}$파라미터 1개당 forward 2번 → 수억 개 파라미터에서는 불가능. 오차도 큼
기호 미분 (Symbolic)수식을 미분한 수식을 유도식이 폭발적으로 커짐 (expression swell)
자동 미분 (Automatic)기본 연산의 미분 규칙을 알고 있고, chain rule 로 조합정확하고, 역전파 1번이면 모든 파라미터의 기울기를 얻음

Autograd 는 세 번째 방식이며, 그중에서도 reverse mode(역방향 모드) 자동 미분이다.

출력이 스칼라 1개(loss)이고 입력(파라미터)이 매우 많은 딥러닝 구조에서는 reverse mode 가 압도적으로 유리하다. (forward mode 는 입력 개수만큼 반복해야 함)

2. 연산 그래프

import torch

x = torch.tensor(2.0, requires_grad=True)
y = torch.tensor(3.0, requires_grad=True)

z = x * y      # MulBackward
out = z + x**2 # AddBackward, PowBackward

내부적으로 아래와 같은 DAG(방향 비순환 그래프)가 만들어진다.

flowchart LR
    X["x (leaf)"] --> M["Mul"]
    Y["y (leaf)"] --> M
    X --> P["Pow(2)"]
    M --> A["Add"]
    P --> A
    A --> O["out"]
  • 노드(node) : 연산 (MulBackward0, AddBackward0 …)
  • 엣지(edge) : 텐서의 흐름
  • leaf : 사용자가 직접 만든 텐서 (모델 파라미터, 입력). 여기에 .grad 가 쌓인다.

PyTorch 는 이 그래프를 forward 를 실행하면서 그때그때 만든다(define-by-run). 그래서 if, for, 파이썬 제어문을 그대로 써도 되고, 매 iteration 마다 다른 모양의 그래프를 만들 수 있다.

Dynamic graph (define-by-run)Static graph (define-and-run)
예PyTorch, JAX(추적 시점 제외)TensorFlow 1.x, ONNX 내보내기
장점디버깅 쉬움, 파이썬 제어문 자유그래프 전체를 보고 최적화 가능
단점최적화 여지가 적음디버깅 어려움

3. 텐서의 세 가지 속성

x = torch.tensor(2.0, requires_grad=True)
z = x * 3

x.requires_grad   # True  : 이 텐서에 대한 기울기를 추적할지 여부
z.grad_fn         # <MulBackward0> : 나를 만든 연산 (leaf 는 None)
x.grad            # backward() 후에 채워지는 기울기 (leaf 에만 저장)
  • requires_grad=True 인 텐서가 하나라도 섞이면 결과 텐서도 requires_grad=True 가 된다 (전파).
  • nn.Parameter 는 기본적으로 requires_grad=True.
  • 중간 텐서의 .grad 는 메모리 절약을 위해 저장하지 않는다. 필요하면 z.retain_grad().

4. backward() 가 하는 일

x = torch.tensor(2.0, requires_grad=True)
y = torch.tensor(3.0, requires_grad=True)
out = x * y + x**2      # out = xy + x^2

out.backward()

x.grad  # y + 2x = 3 + 4 = 7
y.grad  # x         = 2

out.backward() 는

  1. out 에 seed 기울기 $\frac{\partial out}{\partial out} = 1$ 을 넣고
  2. 그래프를 위상 정렬 역순으로 순회하며
  3. 각 연산의 국소 미분(local gradient)을 곱해 내려보내고 (chain rule)
  4. leaf 텐서의 .grad 에 누적(+=) 한다
  5. 기본적으로 그래프를 해제한다 (retain_graph=False)

스칼라가 아니면?

backward() 는 스칼라에만 인자 없이 쓸 수 있다. 벡터라면 시작 기울기 $v$ 를 직접 줘야 한다.

z = x * y            # shape (3,)
z.backward(torch.ones_like(z))   # 또는 z.sum().backward()

이는 야코비안 $J$ 전체를 만들지 않고 벡터-야코비안 곱(VJP) $v^{T}J$ 만 계산하기 때문이다. loss 를 항상 스칼라로 만드는 이유이기도 하다.

5. 기울기 누적과 zero_grad

.grad 는 덮어쓰기가 아니라 누적된다. 그래서 학습 루프는 항상 이 순서다.

for x, y in loader:
    optimizer.zero_grad()        # 이전 step 의 grad 제거
    pred = model(x)
    loss = criterion(pred, y)
    loss.backward()              # grad 계산 (누적)
    optimizer.step()             # 파라미터 갱신

zero_grad() 를 빼먹으면 이전 배치의 기울기가 계속 더해져 학습이 망가진다.

반대로 이 성질을 의도적으로 쓰는 것이 gradient accumulation (GPU 메모리가 부족할 때 작은 배치를 N번 누적해 큰 배치 효과를 내는 기법).

for i, (x, y) in enumerate(loader):
    loss = criterion(model(x), y) / accum_steps
    loss.backward()
    if (i + 1) % accum_steps == 0:
        optimizer.step()
        optimizer.zero_grad()

6. 그래프를 만들지 않기

추론(inference)이나 평가 때는 그래프를 만들 필요가 없다. 메모리와 속도를 크게 아낄 수 있다.

with torch.no_grad():           # 블록 전체에서 추적 끄기
    pred = model(x)

@torch.no_grad()                # 데코레이터로도 사용 가능
def evaluate(...): ...

with torch.inference_mode():    # no_grad 보다 더 공격적인 최적화 (PyTorch 1.9+)
    pred = model(x)
방법의미
torch.no_grad()블록 안 연산을 그래프에 기록하지 않음
torch.inference_mode()no_grad + 버전 카운터 등 추가 오버헤드까지 제거. 결과를 다시 autograd 에 넣을 수 없음
tensor.detach()그래프에서 잘라낸 새 텐서 반환 (값 공유, 기울기 흐름 차단)
param.requires_grad = False해당 파라미터를 freeze (transfer learning 에서 backbone 동결)
# backbone freeze 예시
for p in model.backbone.parameters():
    p.requires_grad = False

7. 커스텀 연산 (torch.autograd.Function)

미분 규칙을 직접 정의하고 싶을 때 사용한다. (예: 미분 불가능한 연산의 근사, STE(Straight-Through Estimator), 메모리 최적화)

class MyReLU(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x):
        ctx.save_for_backward(x)     # backward 에서 쓸 값 저장
        return x.clamp(min=0)

    @staticmethod
    def backward(ctx, grad_output):
        (x,) = ctx.saved_tensors
        grad_input = grad_output.clone()
        grad_input[x < 0] = 0        # dReLU/dx = 1 if x>0 else 0
        return grad_input

y = MyReLU.apply(x)

Quantization 의 QAT 에서 round() 처럼 기울기가 0 인 연산을 통과시킬 때 이 방식(STE)을 쓴다.

8. 관련 API

# 그래프를 유지한 채 여러 번 backward
loss.backward(retain_graph=True)

# .grad 에 누적하지 않고 기울기만 받아오기 (2차 미분, GAN, meta-learning 등)
g = torch.autograd.grad(loss, model.parameters(), create_graph=True)

# 2차 미분 (create_graph=True 로 backward 그래프까지 미분 대상에 포함)
grad1 = torch.autograd.grad(y, x, create_graph=True)[0]
grad2 = torch.autograd.grad(grad1, x)[0]

# 수치 미분과 비교해 커스텀 Function 검증
torch.autograd.gradcheck(MyReLU.apply, (x.double().requires_grad_(),))

# NaN/inf 가 어디서 나왔는지 추적 (디버깅 시에만, 매우 느림)
torch.autograd.set_detect_anomaly(True)

10. 메모리 관점

Autograd 는 backward 에 필요한 중간 activation 을 전부 들고 있어야 한다. 그래서 학습 시 메모리는 대략

$$ \text{메모리} \approx \text{파라미터} + \text{기울기} + \text{옵티마이저 상태} + \textbf{중간 activation} $$

이고, 배치 크기를 키울 때 터지는 주범은 보통 마지막 항이다.

  • Gradient checkpointing : 중간 activation 을 저장하지 않고 backward 때 다시 forward 해서 재계산. 메모리 ↓, 연산량 ↑ (torch.utils.checkpoint.checkpoint)
  • no_grad 추론 : 평가 루프에서 activation 을 아예 저장하지 않음
  • gradient accumulation : 배치를 쪼개서 activation 피크를 낮춤

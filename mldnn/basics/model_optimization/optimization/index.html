    Model Optimization 개요

    Model Optimization (모델 경량화)

    학습이 끝난 모델을 실제로 돌릴 수 있게 만드는 단계. 정확도를 최대한 지키면서 크기·연산량·지연시간을 줄임. 큰 갈래가 셋 있음 — Pruning(덜어내기), Quantization(정밀도 낮추기), Knowledge Distillation(작은 모델에게 가르치기).

    1. 왜 필요한가

    학습할 때는 GPU 여러 장에 시간도 충분하지만, 배포 환경은 보통 그렇지 않음.

    제약문제
    메모리모바일·임베디드는 모델을 통째로 올릴 공간이 없음
    지연시간실시간 처리면 프레임당 예산이 수십 ms뿐임
    전력배터리 기기는 연산량이 곧 사용 시간임
    비용서버라도 처리량이 곧 요금임

    그래서 “정확도 몇 %를 내주고 무엇을 얼마나 얻을지” 교환하는 작업이 필요함.

    정확도를 전혀 안 잃는 방법은 사실상 없음. 얼마까지 허용할지 먼저 정해놓고 시작해야 함.

    2. 세 가지 갈래

    방법무엇을 하나줄어드는 것재학습
    Pruning중요도 낮은 파라미터·채널을 제거파라미터 수, 연산량보통 필요 (fine-tuning)
    QuantizationFP32를 INT8 등 낮은 정밀도로메모리, 연산 비용방식에 따라 (PTQ는 불필요, QAT는 필요)
    Knowledge Distillation큰 모델의 예측을 작은 모델에게 학습모델 크기 자체필요 (Student를 새로 학습)

    앞의 둘은 기존 모델을 손보는 방식이고, KD는 처음부터 작은 모델을 만드는 방식이라는 점이 다름.

    Pruning        큰 모델 ──✂──▶ 구멍 뚫린 큰 모델 (구조는 그대로)
Quantization   큰 모델 ──▼──▶ 같은 구조, 낮은 정밀도
Distillation   큰 모델 ──🎓─▶ 작은 모델 (구조가 다름)

    3. 무엇을 먼저 쓸까

    상황우선 고려
    재학습할 여유가 없음PTQ — 학습 없이 바로 적용 (PTQ )
    정확도 손실을 최소화해야 함QAT (QAT )
    특정 하드웨어에서 실제로 빨라져야 함Structured Pruning (Structured )
    모델 구조 자체를 바꿔도 됨KD
    모바일 / IoTInteger-only 양자화 (Integer-only )
    GPU·TPU 서버FP16 / BF16 — 거의 공짜로 얻는 이득

    같이 쓰는 것도 흔함. 보통 이 순서임.

    KD로 작은 모델 확보 → Pruning으로 더 덜어냄 → Quantization으로 정밀도 낮춤

    양자화를 가장 마지막에 두는 이유는, 정밀도를 낮춘 상태에서 프루닝·증류를 하면 학습이 불안정해지기 때문임.

    4. 자주 빠지는 함정

    • “파라미터가 줄었으니 빨라졌다"가 아님 — Unstructured Pruning 은 파라미터를 0으로 만들 뿐, 전용 sparse 커널이 없으면 실제 속도는 그대로임. 실측이 필수임
    • 벤치마크는 목표 하드웨어에서 — 서버 GPU에서 빨라진 것이 모바일에서도 빨라진다는 보장이 없음. EfficientFormer 가 이 지점을 다룸
    • 어디를 줄일지부터 확인 — Transformer는 파라미터의 2/3가 FFN 에 있음. attention을 아무리 손봐도 전체는 별로 안 줄어듦
    • 정확도 측정은 압축 후에 — 압축 전 정확도로 이야기하면 의미가 없음

    Quantization — 딥러닝 모델 양자화

    딥러닝 모델 양자화 — 수식부터 Segmentation 결과 분석까지

    결론부터 아주 쉽게: 양자화는 모델이 사용하는 숫자를 더 적은 비트로 표현하는 방법임. 가중치 1개를 FP32의 4바이트 대신 INT8의 1바이트로 저장하면 가중치 공간을 줄일 수 있음. 대신 표현 가능한 숫자의 간격이 넓어져 오차가 생김. 핵심은 어디까지 줄여도 결과 품질이 유지되는지, 그리고 배포 장치가 그 표현을 실제로 빠르게 계산하는지를 함께 확인하는 것임.

    🔷 0. 이번 공부를 시작한 계기 — 회사 프로젝트의 EoMT

    이번에 회사 프로젝트를 진행하면서 EoMT 모델을 기존 FP32에서 INT8과 FP16으로 줄여 보는 작업을 했음. Segmentation 작업에 적용한 모델이었는데, 정밀도를 줄인 뒤 원본과 결과 차이가 있었고, 실제 작업에서 유의미하게 받아들여야 하는 차이였음.

    그래서 단순히 모델 크기나 추론 속도만 확인하는 것으로 끝내지 않고, 어느 단계에서 차이가 생기고 왜 최종 segmentation 결과까지 달라지는지 원인을 분석하는 중임. 이 문서는 그 과정에서 양자화와 저정밀도 연산의 원리를 공부하며 정리하는 자료임.

    현재 확인한 사실은 정밀도 변경 후 결과 차이가 관찰되었다는 점임. 특정 계층, calibration, 후처리 중 무엇이 원인인지는 아직 확정하지 않았음. 아래의 EoMT 진단 항목은 원인 후보와 검증 계획이며, 실제 프로젝트에서 이미 확인된 분석 결과를 의미하지 않음. 여기서 유의미한 차이는 실무적으로 중요했던 차이를 뜻하며, 통계적 유의성 검정을 했다는 의미는 아님.

    INT8과 FP16은 따로 분석할 필요가 있음. INT8은 scale과 정수 격자를 사용하는 양자화이고, FP16은 더 적은 비트의 부동소수점 표현임. 두 결과가 모두 FP32와 달라졌더라도 원인이 같다고 단정할 수 없음.

    선행 지식: 신경망 구성 요소 , 학습 과정 , 모델 최적화 개요 .

    🔷 1. 먼저 잡아야 할 전체 그림

    정밀한 자의 눈금을 더 성긴 눈금으로 바꾸는 것과 비슷함. 원래 길이가 1.234cm여도 0.1cm 눈금으로는 1.2cm 정도로 표현하게 됨. 눈금을 줄인 만큼 저장과 계산 비용을 낮출 여지가 생기지만, 원래 값을 완전히 복원할 수는 없음.

    flowchart LR

    B --> D["QAT: 오차를 반영해 추가 학습"]

    PTQ와 INT8은 같은 층위의 분류가 아님. PTQ로 INT8 모델을 만들 수도 있고, QAT를 거쳐 INT8 모델을 만들 수도 있음. Integer-only 역시 학습 방식이 아니라 최종 추론 연산의 조건임.

    🔷 2. 무엇이 얼마나 작아지는가

    가중치가 $N$개이고 각 가중치가 $b$비트이면, 순수 가중치 데이터의 이론적 크기는 다음과 같음.

    $$ M_{\mathrm{weight}} = N \times \frac{b}{8}\;\mathrm{bytes} $$

    가중치가 10억 개인 모델을 가정한 계산임. GB는 $10^9$바이트 기준이며 scale·zero-point·정렬·파일 헤더는 제외함.

    저장 형식가중치당 크기10억 개 크기FP32 대비
    FP324바이트4GB1배
    FP16 / BF162바이트2GB1/2
    INT81바이트1GB1/4
    INT40.5바이트, packing 필요0.5GB1/8

    실제 추론 메모리는 가중치 + activation + 임시 작업 공간 + 런타임 비용으로 구성됨. LLM에는 KV cache도 추가됨. 가중치 크기가 1/4이 되어도 전체 VRAM이 정확히 1/4이 되는 것은 아님.

    INT4 값을 각각 int8 원소에 담기만 하면 원소당 1바이트를 사용함. 두 개의 4비트 값을 한 바이트에 넣는 packing과 이를 읽는 커널이 있어야 표의 저장 이득에 가까워짐.

    FP16 / BF16과 정수 양자화의 차이

    형식비트 구성해석
    FP32부호 1 + 지수 8 + 가수부 23일반적인 단정밀도 부동소수점
    FP16부호 1 + 지수 5 + 가수부 10FP32보다 범위와 정밀도가 줄어듦
    BF16부호 1 + 지수 8 + 가수부 7FP32와 지수 비트 수가 같고 유효숫자 정밀도는 낮음
    INT8정수 8비트실수 해석을 위해 별도의 scale 등이 필요함

    FP16·BF16은 지수부가 있으므로 아래에서 설명하는 균일한 정수 눈금과는 다름. BF16은 FP16보다 범위가 넓지만 같은 크기 부근의 숫자를 더 촘촘하게 표현하는 것은 아님. FP8도 부동소수점이며 INT8과 구분해야 함.

    🔷 3. 핵심 수식 — scale과 zero-point

    기본 대상은 uniform affine quantization, 즉 일정한 간격의 정수 격자로 실수를 표현하는 방식임.

    $$ q = \operatorname{clip}\left(\operatorname{round}\left(\frac{x}{s}\right)+z,\;q_{\min},\;q_{\max}\right) $$$$ \hat{x} = s(q-z) $$
    기호뜻
    $x$원래 실수 값
    $q$저장되는 정수 값
    $\hat{x}$정수에서 복원한 근삿값
    $s>0$scale, 실수 눈금의 간격
    $z$zero-point, 실수 0에 대응하는 정수
    $q_{\min},q_{\max}$허용되는 정수 범위

    범위가 $[x_{\min},x_{\max}]$일 때의 기본적인 비대칭 min/max 설정은 다음과 같음. 관측 범위를 필요하면 확장해 실수 0이 포함되도록 함.

    $$ s=\frac{x_{\max}-x_{\min}}{q_{\max}-q_{\min}},\qquad z=\operatorname{clip}\left(\operatorname{round}\left(q_{\min}-\frac{x_{\min}}{s}\right),q_{\min},q_{\max}\right) $$

    모든 값이 0인 텐서는 scale이 0이 되지 않도록 별도 처리가 필요함. 반올림 규칙과 끝점 처리도 런타임마다 확인해야 함.

    손으로 계산하는 UINT8 예제

    실수 범위를 $[-1,2]$, 정수 범위를 $[0,255]$로 두면 $s=3/255=1/85$, $z=85$임.

    원래 값 $x$정수 $q$복원 값 $\hat{x}$설명
    -10-1아래 끝점
    0850실수 0이 정확히 표현됨
    0.3111약 0.305882최근접 반올림, 동률은 짝수 선택
    22552위 끝점
    32552범위 밖이어서 clipping됨

    정수 0과 실수 0이 항상 같은 것은 아님. 이 예제에서는 정수 85가 실수 0임. CNN의 zero padding도 양자화된 표현에서는 이 점을 고려해야 함. 기본 표현식과 zero-point의 역할은 ONNX Runtime 공식 문서 에서도 확인할 수 있음.

    🔷 4. 오차의 두 종류 — 반올림과 clipping

    표현 범위 안에서는 가장 가까운 눈금으로 이동하면서 반올림 오차가 생김. 최근접 반올림이고 clipping이 없으면 $|x-\hat{x}|\le s/2$임.

    범위 밖에서는 끝점에 붙여 버리는 clipping 오차가 생김. 앞의 $x=3$은 2로 복원되므로 오차가 1이며 $s/2$보다 훨씬 큼.

    대부분의 값이 $[-1,1]$ 안에 있고 단 하나가 100이라면, 대칭 INT8에서 100을 포함하기 위해 눈금이 $100/127\approx0.7874$가 됨. 작은 값들이 구분되지 않기 쉬움. 범위를 $[-1,1]$로 줄이면 눈금은 약 0.007874로 정밀해지지만 100은 크게 잘림.

    범위를 넓히면 무조건 좋은 것도, outlier를 제거하면 무조건 좋은 것도 아님. 자주 나오는 값의 정밀도와 드물지만 중요한 값의 보존 사이에서 결정하는 문제임. Weight의 MSE가 작더라도 작은 출력 차이가 분류 경계나 마스크 threshold를 넘으면 최종 결과는 달라질 수 있음.

    🔷 5. Symmetric / Asymmetric

    구분SymmetricAsymmetric
    실수 범위0을 중심으로 대칭데이터의 비대칭 범위에 맞춤
    zero-pointsigned 정수에서는 보통 0일반적으로 0이 아닐 수 있음
    직관양수와 음수에 같은 폭 배정실제 값이 몰린 쪽에 범위 배정
    자주 보는 적용weight비대칭 activation

    대칭 INT8의 한 구성은 $a=\max|x|$, $s=a/127$, $z=0$, 정수 범위 $[-127,127]$임. 저장 dtype은 $[-128,127]$을 지원하더라도 이 설명에서는 대칭성을 위해 -128을 사용하지 않음.

    ReLU 출력처럼 음수가 없는 값에 대칭 signed 범위를 쓰면 음수 쪽 공간을 활용하지 못함. 다만 수학적으로 유리한 설정이어도 배포 커널이 지원하는지 확인해야 함.

    🔷 6. Per-tensor / Per-channel / Per-group

    같은 INT8이어도 하나의 scale을 몇 개의 값이 공유하는지에 따라 오차가 달라짐.

    방식scale을 공유하는 단위장점비용
    Per-tensor텐서 전체처리가 단순함다른 분포를 한 범위로 표현함
    Per-channel채널별채널 간 범위 차이를 반영함채널별 scale이 필요함
    Per-group일정 개수의 원소 묶음국소 분포를 반영함그룹별 메타데이터·커널 지원이 필요함
    Per-tokenactivation의 토큰별토큰 간 크기 차이를 반영함동적 범위 계산 비용이 생길 수 있음

    PyTorch Linear weight는 [out_features, in_features]임. output channel 기준이면 행마다 scale 하나가 있음. Conv weight [out_channels, in_channels/groups, kH, kW]에서는 output channel별 scale 구성이 흔함. 축은 텐서 배치에 따라 확인해야 함.

    두 output channel의 최대 절댓값이 0.1과 10이면 per-tensor의 눈금은 $10/127\approx0.07874$임. 작은 채널은 몇 개의 눈금밖에 쓰지 못함. per-channel에서는 해당 채널에 $0.1/127\approx0.0007874$를 사용할 수 있음.

    가중치 128개를 INT4로 packing하면 64바이트임. 그룹당 FP16 scale 2바이트만 추가한다고 가정하면 총 66바이트이며, 평균 비트 수는 $4+16/128=4.125$임. zero-point와 padding을 넣으면 더 커짐. 작은 group size는 분포에 잘 맞출 여지가 있지만 메타데이터 비용도 늘어남.

    🔷 7. PTQ, Static, Dynamic, Weight-only

    **PTQ(Post-Training Quantization)**는 학습된 모델에 양자화를 적용하는 접근임. 일반적으로 모델 전체를 gradient 기반으로 재학습하지 않지만, calibration이나 층별 오차 보정에 데이터와 계산이 필요할 수 있음.

    PTQ 구성weightactivation대표적인 추가 작업
    Weight-onlyINT8·INT4 등으로 저장FP16·BF16 등 유지weight 범위·그룹 결정, 방식에 따라 calibration
    Dynamic INT8미리 양자화연산 시점의 입력 범위로 양자화추론 중 activation scale 계산
    Static INT8미리 양자화미리 정한 범위로 양자화대표 데이터로 calibration

    Dynamic 모듈의 입출력이 FP32여도 내부 Linear에 들어가는 activation은 동적으로 정수화될 수 있음. Dynamic을 weight-only와 같은 것으로 보면 안 됨. Static과 Dynamic은 activation 양자화 파라미터를 언제 결정하는지로 구분됨. ONNX Runtime의 Static·Dynamic 설명 을 기준으로 한 구분임.

    Weight-only 커널은 압축된 weight를 읽고 필요한 부분을 복원하면서 부동소수점 activation과 계산할 수 있음. W4A16은 보통 weight 4비트, activation 16비트를 뜻하며 곱셈과 누산까지 모두 4비트라는 뜻은 아님.

    🔷 8. Calibration — 범위를 정하는 데이터

    Static PTQ의 기본 흐름은 다음과 같음.

    1. 평가 모드의 학습된 모델과 실제 전처리를 준비함.
    2. backend에 맞게 연산을 정리하고 observer를 배치함. Conv와 BatchNorm을 합치는 fusion 등이 들어갈 수 있음.
    3. 대표 입력을 forward하여 activation 통계를 수집함. 일반적인 gradient 학습은 아님.
    4. 통계에서 scale·zero-point를 정하고 지원되는 양자화 연산으로 변환함.
    5. calibration에 사용하지 않은 평가 데이터로 품질을 측정함.

    MinMax는 극단값을 포함하고, percentile은 일부 꼬리를 제외하며, MSE·entropy 기반 접근은 후보 범위의 오차나 분포 차이를 기준으로 범위를 선택함. 어느 방식이 최선인지는 모델과 입력 분포에 따라 달라짐.

    이미지 모델이면 밝기·해상도·전처리·클래스 분포를, 언어 모델이면 언어·도메인·문맥 길이를 고려해야 함. 실제 서비스가 긴 한국어 문서를 받는데 짧은 영어 문장만으로 범위를 정하면 대표성이 부족할 수 있음.

    샘플 수에 보편적인 정답은 없음. 수와 다양성을 늘리면서 범위와 품질이 안정되는지 확인해야 함. Calibration에는 보통 정답 label이 필요 없지만 최종 정확도 평가에는 별도 정답이나 평가 기준이 필요함.

    prepare() 다음에 대표 입력을 통과시키지 않고 convert()만 호출하면 정상적인 static calibration 과정을 거친 것이 아님.

    🔷 9. QAT — 양자화 오차를 겪으면서 학습함

    **QAT(Quantization-Aware Training)**는 forward에 fake quantization을 넣어 반올림·clipping 오차를 모사하는 접근임.

    $$ \operatorname{FakeQuant}(x)=s\left[\operatorname{clip}\left(\operatorname{round}(x/s)+z,q_{\min},q_{\max}\right)-z\right] $$

    값은 격자에 맞게 바뀌지만 텐서는 보통 부동소수점으로 유지됨. 따라서 fake quantization을 켠 학습 모델 자체가 작은 INT8 배포 모델인 것은 아님.

    round의 미분은 거의 모든 곳에서 0이므로 보통 **STE(Straight-Through Estimator)**로 backward에 대체 gradient를 흘려 줌. 단순한 설명으로는 표현 범위 안에서 미분을 1처럼 통과시키고 clipping 영역에서는 차단하는 식임. 구체적 규칙은 구현에 따라 달라짐.

    이미 학습된 모델에서 fine-tuning하는 방식도 가능함. 학습 때의 비트 수·대칭 여부·granularity가 최종 backend와 맞아야 함. QAT만으로 품질 회복이나 가속이 보장되지는 않음. 준비 → 학습 → 변환 흐름은 torchao QAT 문서 를 참고할 수 있음.

    🔷 10. INT8 곱셈인데 왜 INT32가 나오는가

    Linear의 한 output channel은 $y_j=\sum_i x_iw_{ji}+b_j$임. Activation scale을 $s_x$, 채널별 weight scale을 $s_{w,j}$로 두면 다음처럼 근사함.

    $$ y_j\approx s_xs_{w,j}\sum_i(q_{x,i}-z_x)(q_{w,ji}-z_{w,j})+b_j $$

    INT8 입력을 곱하고 많은 항을 더하면 INT8 범위를 금방 넘으므로 INT32 누산이 흔함. Integer-only 경로에서는 bias도 $q_{b,j}=\operatorname{round}(b_j/(s_xs_{w,j}))$로 INT32에 표현할 수 있음.

    다음 계층의 INT8 입력으로 넘기려면 출력 scale $s_y$에 맞추는 requantization이 필요함.

    $$ q_{y,j}=\operatorname{clip}\left(\operatorname{round}\left[\frac{s_xs_{w,j}}{s_y}\left(\sum_i(q_{x,i}-z_x)(q_{w,ji}-z_{w,j})+q_{b,j}\right)\right]+z_y,q_{\min},q_{\max}\right) $$

    위는 개념식이며 실제 integer-only 구현은 scale 비율을 정수 multiplier와 shift 등으로 근사할 수 있음. Integer-only는 중간 결과까지 전부 INT8이라는 뜻이 아님. 관련 원리는 Jacob 등의 논문 에서 다룸.

    Residual add도 두 입력의 scale이 다르면 정수끼리 바로 더할 수 없음. 공통 scale로 맞추거나 이를 처리하는 커널이 필요함. Softmax·LayerNorm 등은 backend에 따라 더 높은 정밀도로 남을 수 있음.

    🔷 11. 실습 1 — 양자화 공식을 직접 구현함

    Python 표준 라이브러리만 사용하는 예제임. 실제 INT8 고속 커널이 아니라 범위·반올림·복원·clipping을 확인하는 실습임.

    import math


def choose_qparams(x_min, x_max, qmin=0, qmax=255):
    if not (math.isfinite(x_min) and math.isfinite(x_max)):
        raise ValueError("Range must be finite")
    if x_min > x_max or qmin >= qmax:
        raise ValueError("Invalid range")
    x_min, x_max = min(x_min, 0.0), max(x_max, 0.0)
    if x_min == x_max:  # all-zero range
        return 1.0, min(qmax, max(qmin, 0))
    scale = (x_max - x_min) / (qmax - qmin)
    zero_point = min(qmax, max(qmin, round(qmin - x_min / scale)))
    return scale, zero_point


def quantize(x, scale, zero_point, qmin=0, qmax=255):
    return min(qmax, max(qmin, round(x / scale) + zero_point))


scale, zero_point = choose_qparams(-1.0, 2.0)
values = [-1.0, 0.0, 0.3, 2.0, 3.0]
q = [quantize(x, scale, zero_point) for x in values]
restored = [scale * (v - zero_point) for v in q]
print("scale:", scale, "zero_point:", zero_point)
print("q:", q)
print("restored:", [round(x, 6) for x in restored])

assert q == [0, 85, 111, 255, 255]
assert restored[1] == 0.0
assert all(abs(x - y) <= scale / 2 + 1e-12
           for x, y in zip(values[:4], restored[:4]))
assert abs(values[-1] - restored[-1]) == 1.0
assert choose_qparams(0.0, 0.0) == (1.0, 0)
    scale: 0.011764705882352941 zero_point: 85
q: [0, 85, 111, 255, 255]
restored: [-1.0, 0.0, 0.305882, 2.0, 2.0]

    단순히 int(x)로 cast하면 소수부를 버릴 뿐임. 위 코드의 정수도 Python 객체이므로 실제로 원소당 1바이트에 저장되는 것은 아님.

    🔷 12. 실습 2 — CPU에서 실제 Dynamic INT8 Linear 실행

    원본과 양자화 모델의 변환 여부, 입출력 shape, 출력 오차를 확인하는 예제임. 작은 무작위 모델이므로 EoMT의 정확도나 실서비스 가속을 검증하는 실험은 아님.

    기존 eager API인 torch.ao.quantization.quantize_dynamic을 사용함. 2026-10-21 확인 기준으로 공식 문서는 양자화 개발을 torchao로 옮기는 방향을 안내하고 있음. 새 구현은 PyTorch 양자화 안내 와 torchao 추론 workflow 를 함께 확인해야 함. 아래는 로컬 PyTorch 2.12.1+cpu, onednn에서 실행 확인한 학습용 예제임.

    import copy
import torch
from torch import nn
from torch.ao.quantization import quantize_dynamic

torch.manual_seed(7)
engines = torch.backends.quantized.supported_engines
engine = next((e for e in ("x86", "fbgemm", "onednn", "qnnpack")
               if e in engines), None)
if engine is None:
    raise RuntimeError(f"No supported quantized CPU backend: {engines}")
torch.backends.quantized.engine = engine

model_fp32 = nn.Sequential(
    nn.Linear(64, 128), nn.ReLU(), nn.Linear(128, 16)
).eval()
model_int8 = quantize_dynamic(
    copy.deepcopy(model_fp32), {nn.Linear}, dtype=torch.qint8
)
x = torch.randn(32, 64)
with torch.inference_mode():
    y_fp32 = model_fp32(x)
    y_int8 = model_int8(x)

error = y_fp32 - y_int8
relative_l2 = error.norm() / y_fp32.norm().clamp_min(1e-12)
print("torch:", torch.__version__, "backend:", engine)
print("module:", type(model_int8[0]).__name__)
print("weight dtype:", model_int8[0].weight().dtype)
print("input/output dtype:", x.dtype, y_int8.dtype)
print("shape:", tuple(y_int8.shape))
print("MSE:", error.square().mean().item())
print("relative L2:", relative_l2.item())

assert model_int8[0].weight().dtype == torch.qint8
assert y_fp32.shape == y_int8.shape == (32, 16)
assert torch.isfinite(y_int8).all()

    확인할 결과는 weight가 torch.qint8, 모듈 입출력이 torch.float32, 출력 shape이 (32, 16)이라는 점임. 오차 수치는 backend·버전에 따라 달라질 수 있음. .cuda()로 옮긴다고 GPU INT8 커널로 바뀌지는 않음. 적용 대상은 quantize_dynamic 공식 문서 에 정리되어 있음.

    Static PTQ로 확장하려면 대상 backend의 prepare → 대표 입력 calibration → convert/export 절차와 양자화 경계를 설정해야 함.

    🔷 13. EoMT Segmentation 결과 차이를 어떻게 추적할 것인가

    이 절은 현재 프로젝트의 원인을 단정하는 설명이 아니라 분석을 위한 가설과 실험 설계임. 실제 사용한 INT8 변환 방식, runtime, segmentation 유형, 데이터 분포에 맞춰 조정해야 함.

    작은 수치 차이가 최종 마스크 차이로 바뀌는 경로

    마스크 확률에 0.5 threshold를 적용하는 가상의 예에서 0.5002가 0.4998로 바뀌면 숫자 차이는 0.0004이지만 픽셀 label은 바뀜. Logit에 threshold 0을 사용하는 경우에도 같은 원리임. 이 수치는 원리 설명용이며 회사 실험에서 측정한 값이 아님.

    클래스 점수가 [0.501, 0.499]에서 [0.498, 0.502]로 바뀌면 argmax 결과도 뒤집힘. 경계 픽셀, 얇은 구조, 작은 객체는 이런 차이가 최종 형태에 영향을 줄 가능성이 있음. Instance·panoptic 후처리에서는 score cutoff와 마스크 간 경쟁이 객체의 선택 여부까지 바꿀 수 있음. 실제 후처리가 어떤 규칙을 쓰는지 먼저 확인해야 함.

    flowchart LR
    A["동일하게 전처리한 입력"] --> B["Backbone·query feature"]
    B --> C["Class logits·mask logits"]
    C --> D["Resize·확률 변환·후처리"]
    D --> E["최종 label·instance mask"]

    FP16과 INT8의 원인 후보를 나누어 확인함

    구분점검할 후보확인 방법
    공통전처리·resize·padding·후처리 설정 차이같은 입력 텐서와 후처리 코드로 비교함
    FP16반올림 누적, 표현 범위, overflow·underflow중간 텐서의 범위·NaN·Inf와 원본 대비 오차를 확인함
    FP16cast와 autocast의 적용 연산 차이실제 연산 dtype과 누산 정밀도를 기록함
    INT8calibration 대표성 부족, activation clipping실패 샘플의 범위와 calibration 범위를 비교함
    INT8per-tensor 범위가 채널별 분포를 충분히 표현하지 못함지원 범위에서 per-channel·group 구성을 비교함
    공통export·fusion·커널 변경에 따른 수치 차이같은 배포 runtime의 FP32 변환 모델도 기준선에 추가함

    FP16에 NaN·Inf가 없다고 결과가 원본과 같다는 의미는 아님. PyTorch도 연산 순서와 backend, 저정밀도 축약 연산에 따라 수치 결과가 달라질 수 있음을 설명함. PyTorch 수치 정확도 문서 를 참고할 수 있음.

    현재 분석에 적용할 비교 순서

    1. 같은 체크포인트·입력·eval() 상태·전처리·후처리를 고정하고, FP32 반복 실행 자체의 변동부터 확인함.
    2. 원본 FP32와 배포 runtime의 FP32를 비교해 export·runtime 변경의 영향을 먼저 분리함.
    3. FP16과 INT8을 각각 FP32 기준선과 비교함. 한 경로의 관찰을 다른 경로의 원인으로 일반화하지 않음.
    4. 가능하면 block 출력 → query feature → class/mask logits 순서로 대응 텐서의 MAE·최대 절대 오차·relative L2를 기록함. shape뿐 아니라 query·공간 위치의 대응도 맞아야 함.
    5. 후처리 전 logit 차이와 후처리 후 마스크 차이를 나눠 봄. 값의 오차가 커진 지점과 최종 결정이 바뀐 지점은 다를 수 있음.
    6. 의심되는 block이나 head만 FP32로 유지하는 대조 실험을 함. 품질 회복 여부와 추가 지연시간을 함께 측정함.
    7. Calibration 개선·양자화 단위 변경으로 충분하지 않으면 QAT를 검토함. 한 번에 하나의 조건을 바꿔 비교함.

    무엇을 결과표로 남길 것인가

    관찰 대상기록할 지표와 주의점
    최종 task 품질Semantic이면 mIoU·클래스별 IoU, instance이면 mask AP, panoptic이면 PQ 등 실제 task에 맞춤
    경계와 작은 구조경계 영역 차이, 작은 객체별 실패 사례, 면적 구간별 지표를 따로 봄
    원본과의 일치도픽셀 변경 비율, 대응 마스크의 IoU 등을 기록함. 정답 대비 품질과 구분함
    Query·instance 대응숫자 ID만 바뀐 결과를 오류로 세지 않도록 매칭 후 비교함
    연속 출력Logit 오차, threshold 근처 픽셀 비율, 클래스 점수 간 margin을 확인함
    속도·메모리품질을 만족한 구성에서 실제 배포 이득을 비교함

    두 모델의 마스크가 다르다는 사실만으로 어느 모델이 더 정확한지는 알 수 없음. 정답 mask가 있는 평가셋과 실제 실패 사례를 함께 봐야 함. 배경이 대부분인 데이터에서는 전체 픽셀 일치도가 높아도 작은 전경 객체의 품질이 크게 달라질 수 있음.

    분석 기록은 관찰한 현상 → 원인 가설 → 통제한 비교 조건 → 측정 결과 → 다음 실험 순서로 남길 예정임. 아직 특정 원인을 찾았거나 해결했다고 결론내린 상태는 아님.

    🔷 14. LLM에서 자주 만나는 이름

    이름핵심 아이디어구분할 점
    RTN가까운 격자로 weight를 반올림함기본 비교 기준
    GPTQ입력에서 얻은 근사 2차 정보로 층별 weight 양자화 오차를 보정함저비트 weight PTQ
    AWQactivation 통계로 중요한 weight channel을 찾고 scaling으로 보호함activation을 참고하지만 weight-only임
    SmoothQuant등가 scaling으로 activation outlier의 부담을 weight 쪽으로 옮김주요 목표는 W8A8 PTQ임

    원 논문인 GPTQ , AWQ , SmoothQuant 를 기준으로 한 요약임. 이 방법을 EoMT에 그대로 적용하면 같은 이득이 난다는 의미는 아님.

    작은 batch의 autoregressive decode에서는 매 토큰마다 큰 weight를 읽는 비용이 병목이 될 수 있음. 이때 weight-only가 대역폭 측면에서 유리할 수 있음. 긴 prompt를 처리하는 prefill이나 큰 batch는 병목이 달라질 수 있음.

    일반적인 decoder self-attention의 KV cache 크기는 대략 다음과 같음.

    $$ M_{\mathrm{KV}}\approx2\times L\times B\times T\times H_{\mathrm{KV}}\times D\times\text{bytes per element} $$

    $L$은 층 수, $B$는 batch, $T$는 cache 길이, $H_{\mathrm{KV}}$는 KV head 수, $D$는 head 차원임. GQA에서는 query head가 아니라 KV head 수를 사용함. 32층·batch 1·길이 4096·KV head 8개·차원 128·FP16이면 메타데이터 제외 512MiB임. Weight를 INT4로 바꿔도 FP16 cache가 자동으로 INT4가 되지 않음.

    🔷 15. 실제 배포에서 속도까지 검증함

    측정 대상기록할 내용
    품질동일한 평가셋의 task metric, 클래스·객체 크기별 실패
    지연시간warm-up 후 p50·p95, 동일 batch·입력 shape·thread 수
    처리량images/s 또는 tokens/s, 동시 요청 수
    메모리모델 파일, CPU 메모리, GPU peak memory를 각각 기록함
    실행 조건체크포인트, 전처리, 장치, runtime 버전, 양자화 설정

    GPU는 비동기로 실행되므로 CUDA event나 적절한 synchronize로 측정해야 함. Compile·engine build·첫 실행 비용은 정상 상태의 반복 추론과 분리함. Accuracy가 80.0%에서 79.5%로 변한 것은 0.5%p 하락이며, 허용 기준은 실제 요구에 맞춰 정해야 함.

    양자화해도 느려질 수 있는 이유는 다음과 같음.

    • 저정밀도 커널이 지원되지 않아 고정밀도 연산으로 fallback됨.
    • 작은 텐서에서는 quantize/dequantize 비용이 절감 효과보다 큼.
    • 지원되지 않는 연산 사이를 오가면서 변환 경계가 많아짐.
    • 잘 최적화된 FP16/BF16 커널과 비교하면 정수 경로의 이점이 작을 수 있음.
    • 전처리·전송·후처리가 병목이어서 모델 계산 감소가 전체 시간에 적게 반영됨.

    전체 10ms 중 모델 계산이 4ms인데 그 부분만 2배 빨라지면 전체는 $6+2=8$ms임. 최종 가속은 2배가 아니라 1.25배임.

    Q/DQ 노드가 있어도 runtime이 패턴을 저정밀도 커널로 합칠 수 있음. 그래프 모양만 보지 말고 실제 실행 provider와 profiler를 확인해야 함.

    🔷 16. 자주 헷갈리는 질문과 다음 공부

    Q. INT8이면 정확도가 항상 많이 떨어짐?

    모델, 범위, granularity, 데이터, 제외 계층에 따라 달라짐. 비트 수만으로 하락 폭을 단정할 수 없음.

    Q. FP16인데도 segmentation 결과가 바뀔 수 있음?

    가능함. 부동소수점의 반올림과 표현 범위가 바뀌고, 작은 연속 값 차이가 threshold·argmax 같은 불연속 결정으로 이어질 수 있음. 다만 현재 프로젝트의 실제 원인은 비교 실험으로 확인해야 함.

    Q. QAT는 INT8 파라미터를 직접 미분하는 학습임?

    일반적인 fake-quant QAT는 실수 파라미터를 유지하고 forward의 양자화 효과와 backward의 대체 gradient를 사용함. 실제 배포 표현으로 변환하는 단계가 따로 있음.

    Q. 모든 계층을 같은 비트 수로 바꿔야 함?

    그럴 필요 없음. 민감한 계층을 높은 정밀도로 남길 수 있음. 변환 비용과 backend 지원도 함께 확인해야 함.

    Q. Pruning이나 distillation과는 어떻게 다름?

    Pruning 은 연결·채널 등을 줄이고, distillation 은 teacher의 정보를 student에게 학습시키는 접근임. 양자화는 숫자 표현을 줄이는 접근임.

    이해 확인용으로 다음을 설명해 볼 수 있음.

    1. 실수 0이 정수 85로 저장되어도 문제가 없는 이유는 무엇임?
    2. Outlier 하나 때문에 작은 weight의 정밀도가 나빠지는 이유는 무엇임?
    3. Dynamic INT8의 출력이 FP32인 것과 내부 정수 연산은 어떻게 양립함?
    4. INT8 입력을 쓰는데 INT32 accumulator가 필요한 이유는 무엇임?
    5. 평균 logit 오차가 작아도 작은 객체의 마스크가 달라질 수 있는 이유는 무엇임?

    이어 읽을 문서: PTQ , QAT , Integer-only , FP16 / BF16 , EoMT 구조 .

    직접 확장할 실험으로는 실습 1을 4비트 범위로 바꾸기, per-tensor와 per-channel 오차 비교하기, 학습된 모델에서 정답 대비 품질과 원본 대비 일치도를 각각 측정하기가 있음.

    한 줄 요약: 양자화는 숫자를 적게 저장하는 기술이면서, 그 오차가 최종 결과에 미치는 영향을 분석하고 지원되는 커널로 실제 이득을 얻는 배포 과정임.

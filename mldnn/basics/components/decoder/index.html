    Decoder

    🧠 딥러닝에서 디코더(Decoder)란?

    디코더는 딥러닝 모델에서 **잠재 벡터(latent vector)**를 받아서, 이를 기반으로 원하는 출력 형태로 복원 또는 변환하는 부분.
    인코더가 입력을 요약하는 역할이라면, 디코더는 그 요약된 정보를 풀어내는 역할을 함.

    ✅ 디코더의 위치 및 역할

    flowchart LR
    I["Input"] --> E["Encoder"] --> Z["Latent vector z"] --> D["Decoder"] --> O["Output"]
    • 입력(Input): 원시 데이터 (이미지, 텍스트 등)
    • 인코더(Encoder): 입력을 잠재 벡터 z로 변환
    • 디코더(Decoder): z로부터 출력 생성
    • 출력(Output): 예측된 결과 (복원 이미지, 번역된 문장 등)

    📦 예시: Autoencoder

    flowchart TD
    A["Latent vector z"] --> B["Linear → ReLU<br/>디코더 hidden layer"] --> C["Linear → Sigmoid<br/>디코더 출력"] --> D["784차원 복원된 이미지 벡터"]

    수학적으로:

    \[ \hat{x} = f_{\text{dec}}(z) = \sigma(W_d z + b_d) \]

    🧱 디코더 내부 구성 요소

    구성 요소설명
    Linear Layerz를 출력 공간으로 맵핑
    Activation출력 형태에 맞는 활성화 함수 사용
    Upsampling이미지 복원 시, 해상도 확장에 사용
    ConvTranspose이미지 업샘플링에 사용되는 역컨볼루션
    Attention (NLP)문맥을 반영하며 출력 생성 (Transformer 디코더)

    🧠 디코더 vs 일반 히든 레이어

    • 디코더는 히든 레이어 집합이지만 “출력 생성을 위한 역할"에 집중된 블록
    • 인코더의 반대 방향 흐름을 가짐

    🧠 PyTorch 예시 코드

    import torch.nn as nn

class Decoder(nn.Module):
    def __init__(self):
        super().__init__()
        self.layers = nn.Sequential(
            nn.Linear(64, 256),
            nn.ReLU(),
            nn.Linear(256, 784),
            nn.Sigmoid()
        )

    def forward(self, z):
        return self.layers(z)  # output reconstruction

    🔁 “디코더"라는 이름의 세 가지 뜻

    딥러닝 논문에서 “decoder"는 최소 세 가지 다른 것을 가리킴. 구조·목적이 달라서 구분하지 않으면 헷갈림.

    ① NLP Transformer 디코더② DETR류 쿼리 디코더③ Dense 디코더 (U-Net식)
    입력지금까지 생성한 출력 토큰학습된 object query N개 (이미지와 무관한 빈 자리)압축된 저해상도 feature
    핵심 연산Masked Self-Attn → Cross-Attn → FFNSelf-Attn(쿼리끼리) → Cross-Attn(쿼리→이미지) → FFNUpsampling / ConvTranspose (+ skip connection)
    Self-Attention maskcausal (미래 못 봄)없음해당 없음
    생성 방식한 토큰씩 autoregressiveN개 동시에 병렬한 번에
    목적시퀀스 생성feature에서 물체(슬롯) 추출feature → 픽셀 단위 복원
    출력다음 토큰 확률쿼리마다 (클래스, 박스/마스크)픽셀별 클래스 / 복원 이미지
    대표번역기, GPTDETR, Mask2FormerU-Net, SegFormer head, MAE decoder
    문서Transformer §10DETR이 문서의 Autoencoder 예시
    flowchart LR
    subgraph NLP["① NLP 디코더"]
      T1["이전 토큰들"] --> T2["Masked Self-Attn"] --> T3["Cross-Attn ← 인코더"] --> T4["다음 토큰"]
    end
    subgraph DETR["② 쿼리 디코더"]
      Q1["object query ×N"] --> Q2["Self-Attn (쿼리끼리)"] --> Q3["Cross-Attn ← 이미지 feature"] --> Q4["물체 N개 (병렬)"]
    end
    subgraph UNET["③ Dense 디코더"]
      U1["1/16 feature"] --> U2["Upsample ×2"] --> U3["Upsample ×2"] --> U4["픽셀 단위 출력"]
    end
    • 분류만 하는 ViT 에는 디코더가 없음. 생성할 출력 시퀀스가 없고, 인코더 self-attention만으로 패치들이 서로 정보를 교환한 뒤 [class] 토큰 하나만 꺼내면 되기 때문임
    • 최근 vision 모델이 디코더를 다시 붙이는 이유는 ViT가 부족해서가 아니라, 출력 형태가 복잡해졌기 때문임 — detection은 “무엇이 · 어디에 · 몇 개” 를 동시에, segmentation은 픽셀 단위 출력을 요구함. 인코더 = feature를 만드는 곳, 디코더 = 그 feature를 태스크 출력 구조로 바꾸는 곳
    • ②는 ①과 이름만 같음. mask도 없고 autoregressive도 아니라 사실상 “학습된 빈 자리 N개가 이미지에 질문하는 층"임. EoMT 는 이 ②마저 없애고 쿼리를 인코더 토큰 열에 직접 끼워 넣음

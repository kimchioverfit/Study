    nn Function

    1. nn.Linear 이 하는 일

    $$ y = xW^\top + b $$

    입력 벡터 하나를 받아 가중합 + 편향을 내놓음. 출력의 $j$ 번째 원소는 입력 전체와 weight 의 $j$ 번째 행을 내적한 값임.

    $$ y_j = \sum_{i} x_i\,W_{ji} + b_j = \langle x,\ W_{j:}\rangle + b_j $$

    즉 nn.Linear(in, out) 은 out 개의 서로 다른 방향으로 입력을 재는 자임. weight 의 한 행이 자 하나고, 그 행과 입력이 얼마나 같은 방향인지를 숫자 하나로 내놓음. out 을 늘린다는 건 자를 더 많이 꽂는다는 뜻임.

    ⚠️ $b \ne 0$ 이면 엄밀히는 선형변환이 아니라 아핀(affine) 변환임. 원점을 원점으로 보내지 않기 때문임 (선형 변환 — “이동(translation)은 선형 변환이 아님”).

    lin = nn.Linear(4, 2)          # bias 기본값 True
lin(torch.zeros(1, 4))         # -> 0 이 아니라 bias 값이 그대로 나옴

    2. 왜 weight 가 (out, in) 인가

    수식에는 $xW^\top$ 처럼 전치가 붙어 있는데, 이건 저장 순서 때문임.

    shape
    수학에서 쓰는 $W$ (열이 출력)$(\text{in},\ \text{out})$
    nn.Linear.weight$(\text{out},\ \text{in})$

    weight[j] 가 출력 $j$ 를 만드는 가중치 한 줄로 메모리에 연속으로 놓이게 하려고 이렇게 잡음. 행 단위로 읽는 게 캐시에 유리해서임.

    그래서 논문 수식의 $W$ 와 코드의 .weight 는 전치 관계라는 걸 늘 염두에 둬야 함. Transformer 쪽에서 $W_Q$ 를 코드로 꺼낼 때 혼동이 자주 생기는 지점임 (W_Q / W_K / W_V ).

    3. 3×4 입력으로 따라가기

    토큰(또는 샘플) 3개, 각 4차원인 입력 $X$ 를 둠.

    $$ X = \begin{bmatrix} 1 & 0 & 2 & 1\\ 0 & 1 & 1 & 3\\ 2 & 1 & 0 & 1 \end{bmatrix} \quad (3\times4), \qquad \text{rank}(X) = 3 $$

    4 → 2 (차원 축소)

    nn.Linear(4, 2) 의 weight 는 $(2, 4)$ 임.

    $$ W = \begin{bmatrix} 1 & 0 & 1 & 0\\ 0 & 1 & 0 & 1 \end{bmatrix}, \qquad Y = XW^\top = \begin{bmatrix} 3 & 1\\ 1 & 4\\ 2 & 2 \end{bmatrix} \quad (3\times2) $$

    첫 행만 손으로 따라가면 — $W$ 의 1행 $[1,0,1,0]$ 은 “1번·3번 특징을 더해라”, 2행 $[0,1,0,1]$ 은 “2번·4번을 더해라” 임.

    $$ y_{11} = 1\cdot1 + 0\cdot0 + 2\cdot1 + 1\cdot0 = 3, \qquad y_{12} = 1\cdot0 + 0\cdot1 + 2\cdot0 + 1\cdot1 = 1 $$
    shaperank
    $X$$(3, 4)$3
    $Y$$(3, 2)$2

    rank 가 3에서 2로 떨어졌음. 출력 차원이 2라서 아무리 좋은 $W$ 를 써도 rank 가 2를 넘을 수 없음. 축소는 정보를 버리는 연산이고, 버려진 성분은 되돌릴 수 없음.

    4 → 8 (차원 확장)

    up = nn.Linear(4, 8, bias=False)   # weight: (8, 4)
Z = up(X)                          # (3, 8)
    shaperank
    $X$$(3, 4)$3
    $Z$$(3, 8)$3

    shape 은 8로 커졌는데 rank 는 3 그대로임.

    4. 차원을 늘리면 뭐가 달라지나 — 정보는 안 늘어남

    $\text{rank}(XW^\top) \le \min(\text{rank}(X),\ \text{rank}(W))$ 이므로, 출력 차원을 아무리 키워도 데이터가 실제로 차지하는 부분공간의 크기는 커지지 않음.

    8차원으로 올린 $Z$ 는 8차원 공간 안에 납작하게 누운 3차원 덩어리임. 실제로 pseudo-inverse 로 되돌려 보면 원본이 그대로 나옴.

    back = Z @ torch.linalg.pinv(up.weight).T
(back - X).abs().max()      # -> 1e-06 수준 (부동소수 오차일 뿐, 손실이 아님)

    정보가 하나도 안 늘었으니 완벽히 복원되는 것임. 확장은 정보를 늘리는 게 아니라 펼쳐 놓는 것임.

    차원 축소 (4 → 2)차원 확장 (4 → 8)
    rank줄어듦 (3 → 2)그대로 (3 → 3)
    정보잃음, 복원 불가안 잃음, pinv 로 복원 가능

    그럼 왜 늘리나

    선형층만 쌓으면 아무 의미가 없기 때문임. 2개를 이어 붙여도 단일 선형층 하나와 완전히 똑같음.

    $$ W_2(W_1x) = (W_2W_1)x $$
    a = nn.Linear(4, 8, bias=False)
b = nn.Linear(8, 2, bias=False)
merged = b.weight @ a.weight            # (2, 4) — 층 2개가 1개로 합쳐짐

torch.allclose(b(a(X)), X @ merged.T)          # -> True
torch.allclose(b(F.relu(a(X))), X @ merged.T)  # -> False   ← ReLU 를 끼우면 못 합침

    4 → 8 → 2 로 늘렸다 줄여도, 사이에 비선형이 없으면 그냥 4 → 2 선형층 하나임. 넓힌 8차원 공간에서 ReLU/GELU 로 한 번 꺾어줘야 비로소 층을 쌓은 값어치가 생김 (Hidden Layer — 왜 선형 + 비선형인가).

    FFN 이 $D \to 4D \to D$ 로 부풀렸다가 되돌리는 구조인 이유가 이것임 — 넓은 공간에서 비선형을 한 번 먹이려고 잠깐 펼치는 것임.

    5. 2D 가 아닌 입력 — 마지막 축에만 적용됨

    nn.Linear 는 마지막 축만 변환하고, 앞의 축은 전부 배치로 취급함.

    x = torch.randn(2, 5, 4)      # (B, T, in)
nn.Linear(4, 8)(x).shape      # -> (2, 5, 8)

    $(B, T, D)$ 텐서를 그대로 넣으면 토큰마다 독립적으로 같은 가중치가 적용됨. Transformer 코드가 reshape 없이 self.q_proj(x) 한 줄로 끝나는 것도 이 성질 덕분임.

    6. 파라미터 수와 bias

    $$ \text{파라미터 수} = \text{in} \times \text{out} + \underbrace{\text{out}}_{\text{bias}} $$
    층파라미터 수
    Linear(4, 8)40 (= 4×8 + 8)
    Linear(4, 8, bias=False)32 (= 4×8)
    Linear(512, 2048)1,050,624

    bias 는 전체의 극히 일부라 메모리 문제는 아님. 그런데도 bias=False 를 쓰는 경우가 있음.

    • 바로 뒤에 LayerNorm/BatchNorm 이 오면 — 정규화가 평균을 빼 버려서 bias 가 무의미해짐
    • Transformer 의 $W_Q, W_K, W_V$ — $QK^\top$ 에서 상수항이 모든 토큰에 똑같이 더해져 softmax 결과를 거의 안 바꿈

    7. 기본 초기화

    nn.Linear 는 kaiming_uniform_(a=√5) 로 초기화되고, 결과적으로 범위가 $\left[-\frac{1}{\sqrt{\text{in}}},\ \frac{1}{\sqrt{\text{in}}}\right]$ 인 균등분포임.

    in_features실제 weight 범위$1/\sqrt{\text{in}}$
    4±0.49990.5000
    64±0.12500.1250
    512±0.04420.0442

    입력 차원이 클수록 좁게 뽑음. 더하는 항이 많아지니 각 항을 작게 만들어야 출력 분산이 일정하게 유지되기 때문임.

    층마다 다른 난수로 뽑힌다는 점도 중요함 — 같은 입력을 받는 q_proj/k_proj/v_proj 가 서로 다른 것을 학습하게 되는 출발점이 여기임 (W_Q / W_K / W_V ).

    9. 한 줄 요약

    nn.Linear(in, out) 은 입력을 out 개의 방향으로 재는 아핀 변환이고, out 을 키워도 rank 는 안 커짐 — 정보가 느는 게 아니라 비선형을 걸 자리가 넓어질 뿐임.

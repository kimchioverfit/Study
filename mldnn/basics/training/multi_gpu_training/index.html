    Multi-GPU Training

    Multi-GPU 학습 세팅 (DDP)

    결론부터 아주 쉽게: GPU 를 $N$ 개 쓴다는 건 모델을 $N$ 벌 복사해서 각자 다른 데이터로 돌리고, gradient 만 합치는 것임. 모델이 쪼개지는 게 아니라 배치가 쪼개짐. 코드로는 DistributedDataParallel 로 감싸고 샘플러를 바꾸는 게 거의 전부임.

    📌 먼저 밝혀 둘 것 — 회사 리소스가 부족해서 단일 GPU + Windows 환경밖에 못 썼고, 그래서 이 내용을 실무 프로젝트에서 실제로 돌려 본 적은 없음. 아래 코드는 공식 문서와 예제를 보고 정리한 것이고, 검증은 §7 처럼 CPU 2프로세스로 로직만 확인한 수준임. 그래서 여러 노드로 늘렸을 때의 네트워크 병목, NCCL 튜닝, 대규모 배치에서의 수렴 문제처럼 직접 겪어 봐야 아는 부분은 빠져 있음.

    1. 무엇이 쪼개지는가

    쪼개지는 것각 GPU 가 들고 있는 것
    Data Parallel (보통 이것)배치모델 전체 사본
    Model Parallel모델의 층모델의 일부
    Pipeline Parallel모델의 층 + 배치 조각모델의 일부

    GPU 4개에 batch 256 이면, 각 GPU 가 64개씩 받아서 forward·backward 를 돌리고 gradient 를 평균냄. 모델이 한 장에 안 올라갈 정도로 크지 않다면 거의 항상 이 방식임.

    그래서 batch_size=64 를 4-GPU 로 돌리면 실효 배치는 256 임. 로그에 찍히는 숫자와 실제로 모델이 보는 양이 다르다는 걸 계속 의식해야 함.

    2. DataParallel 말고 DistributedDataParallel

    둘 다 있지만 DataParallel(DP) 은 쓰지 않는 게 맞음.

    DataParallelDistributedDataParallel
    프로세스1개 (스레드로 분배)GPU 당 1개
    GIL 영향받음 → 병목안 받음
    0번 GPU결과를 모아서 loss 계산 → 혼자 과부하균등
    통신매 step 모델 전체 복제gradient 만 all-reduce
    다중 노드불가가능
    현재 상태사실상 레거시표준

    DP 는 0번 GPU 메모리만 꽉 차고 나머지는 노는 현상이 바로 생김. 코드가 한 줄이라 편해 보이지만 거기까지임.

    3. 최소 예시 — torchrun + DDP

    import os
import torch
import torch.distributed as dist
import torch.nn as nn
from torch.nn.parallel import DistributedDataParallel as DDP
from torch.utils.data import DataLoader, TensorDataset
from torch.utils.data.distributed import DistributedSampler


def main():
    # torchrun 이 RANK / WORLD_SIZE / LOCAL_RANK 를 환경변수로 넣어 줌
    rank = int(os.environ["RANK"])              # 전체에서 몇 번째 프로세스인가
    world_size = int(os.environ["WORLD_SIZE"])  # 전체 프로세스 수
    local_rank = int(os.environ["LOCAL_RANK"])  # 이 노드 안에서 몇 번째 GPU 인가

    dist.init_process_group(backend="nccl")     # GPU 는 nccl, CPU·Windows 는 gloo
    torch.cuda.set_device(local_rank)           # 이 줄을 빼먹으면 전부 0번에 올라감
    device = torch.device("cuda", local_rank)

    x = torch.randn(64, 10)
    y = (x.sum(dim=1, keepdim=True) > 0).float()
    ds = TensorDataset(x, y)

    # shuffle 은 샘플러가 담당. DataLoader 에 shuffle=True 를 같이 주면 에러남
    sampler = DistributedSampler(ds, num_replicas=world_size, rank=rank, shuffle=True)
    loader = DataLoader(ds, batch_size=8, sampler=sampler)

    model = nn.Sequential(nn.Linear(10, 16), nn.ReLU(), nn.Linear(16, 1)).to(device)
    ddp_model = DDP(model, device_ids=[local_rank])
    opt = torch.optim.SGD(ddp_model.parameters(), lr=0.1)
    lossf = nn.BCEWithLogitsLoss()

    for epoch in range(2):
        sampler.set_epoch(epoch)                # 없으면 매 epoch 같은 순서로 섞임
        total = torch.zeros(1, device=device)
        for xb, yb in loader:
            xb, yb = xb.to(device), yb.to(device)
            opt.zero_grad()
            loss = lossf(ddp_model(xb), yb)
            loss.backward()                     # 여기서 gradient all-reduce 가 일어남
            opt.step()
            total += loss.detach()

        dist.all_reduce(total, op=dist.ReduceOp.SUM)   # 로그용 집계
        if rank == 0:
            print(f"epoch {epoch}  loss 합계 {total.item():.4f}")

    if rank == 0:                               # 체크포인트는 rank 0 만 저장
        torch.save(ddp_model.module.state_dict(), "ckpt.pt")

    dist.destroy_process_group()


if __name__ == "__main__":
    main()

    4. 놓치기 쉬운 것들

    함정증상대응
    sampler.set_epoch(epoch) 누락epoch 마다 같은 순서로 섞임epoch 루프 맨 앞에서 호출
    DataLoader(shuffle=True) 를 샘플러와 같이 줌런타임 에러shuffle 은 샘플러에만
    모든 rank 가 체크포인트 저장파일이 서로 덮어씀if rank == 0
    ddp_model.state_dict() 로 저장키에 module. 접두사가 붙어 나중에 로드 실패.module.state_dict()
    rank 마다 다른 수의 배치all-reduce 에서 데드락DistributedSampler 가 패딩해 길이를 맞춰 줌 (기본 drop_last=False)
    loss 를 rank 0 것만 로그전체 평균이 아님dist.all_reduce 로 집계
    lr 을 그대로 씀실효 배치가 $N$ 배인데 lr 은 그대로linear scaling (lr × $N$) + warm-up 검토
    BatchNorm각 GPU 가 자기 배치 통계만 봄nn.SyncBatchNorm.convert_sync_batchnorm(model)

    DistributedSampler 가 데이터를 패딩해서 길이를 맞춘다는 점은 평가할 때 주의해야 함. 검증셋 크기가 world_size 로 안 나눠떨어지면 일부 샘플이 중복 계산돼서 정확도가 미세하게 틀어짐.

    5. Windows 에서 막히는 것들

    여기가 내가 실제로 부딪힌 부분임. PyTorch 의 Windows 분산 지원은 Linux 와 같지 않음.

    LinuxWindows
    nccl (GPU 통신)✅❌ 지원 안 함
    gloo✅✅ (단, GPU 지원 제한적)
    mpi빌드하면 가능❌
    rendezvousTCP / 파일파일(FileStore) 권장

    이 PC 에서 그대로 확인됨.

    import torch.distributed as dist
dist.is_nccl_available()   # -> False
dist.is_gloo_available()   # -> True

    그래서 Windows 에서는 backend="nccl" 을 쓸 수 없고, GPU 가 여러 장이어도 gloo 로 돌려야 하는데 nccl 만큼의 성능이 안 나옴. 멀티 GPU 학습을 제대로 하려면 Linux 나 WSL2 로 가는 게 사실상 전제임.

    실제로 만난 에러 두 개

    ① torchrun 이 아예 안 뜸

    torch.distributed.DistStoreError: use_libuv was requested but PyTorch was
built without libuv support, run with USE_LIBUV=0 to disable it.

    USE_LIBUV=0 을 줘도 안 고쳐짐. torch/distributed/rendezvous.py 는 그 환경변수를 읽지만, torchrun 이 쓰는 elastic/rendezvous/static_tcp_rendezvous.py 는 TCPStore 를 만들 때 그 값을 안 넘기기 때문임. 그래서 torchrun 대신 mp.spawn + FileStore 로 우회했음.

    ② FileStore 가 Unknown error 로 죽음

    torch.distributed.DistStoreError: Unknown error

    rendezvous 파일 경로에 한글이 들어가서 그랬음. 내 임시 폴더가 C:\Users\김현아\AppData\Local\Temp\... 라 경로에 비ASCII 문자가 섞였고, FileStore 가 그걸 못 염. ASCII 경로로 바꾸니 바로 해결됐음.

    6. 언제 멀티 GPU 가 의미 없나

    • 데이터 로딩이 병목일 때 — GPU 를 늘려도 DataLoader 가 못 따라가면 그대로임. num_workers·pin_memory 부터 봐야 함
    • 모델이 작을 때 — 통신 비용이 계산 이득을 잡아먹음
    • 배치를 키울 수 없을 때 — 실효 배치가 커지면 lr·스케줄을 다시 잡아야 하는데, 그게 싫으면 이득이 줄어듦

    단일 GPU 에서 먼저 해 볼 것은 AMP(mixed precision) , gradient accumulation, torch.compile 쪽임. 이쪽이 투자 대비 효과가 크고, 내 환경에서는 이것들만 쓸 수 있었음.

    7. GPU 가 하나여도 DDP 로직은 검증할 수 있음

    GPU 가 없어도 CPU + gloo 로 프로세스 2개를 띄우면 샘플러 분할, all-reduce, 체크포인트 분기 같은 로직은 그대로 확인됨. 성능 측정은 안 되지만, 위 표의 함정 대부분은 여기서 잡힘.

    import os, torch.distributed as dist, torch.multiprocessing as mp
from torch.nn.parallel import DistributedDataParallel as DDP

def worker(rank, world_size, init_file):
    dist.init_process_group(
        backend="gloo",
        init_method=f"file:///{init_file}",   # Windows + gloo 는 파일로 랑데부
        rank=rank, world_size=world_size,
    )
    # ... 위 §3 과 동일. device 만 CPU, DDP(model) 에 device_ids 없이 ...
    dist.destroy_process_group()

if __name__ == "__main__":
    world_size = 2
    f = "C:/Users/Public/claude_ddp/init_store"   # ASCII 경로여야 함
    os.makedirs(os.path.dirname(f), exist_ok=True)
    if os.path.exists(f):
        os.remove(f)
    mp.spawn(worker, args=(world_size, f), nprocs=world_size, join=True)

    64개가 32/32 로 갈림DistributedSampler 가 동작함
    각 rank 가 배치 4개$32 / 8 = 4$, 길이가 맞음
    학습 후 두 rank 의 가중치가 동일gradient all-reduce 가 제대로 됨

    마지막 줄이 핵심임. 두 프로세스가 서로 다른 데이터를 봤는데도 가중치가 같다는 것이, DDP 가 gradient 를 합쳐 주고 있다는 증거임.

    8. 한 줄 요약

    DDP 는 모델을 복사하고 배치를 쪼개서, gradient 만 all-reduce 하는 것. 코드 변경은 네 군데뿐이지만 샘플러·체크포인트·lr·BatchNorm 에서 조용히 틀리기 쉽고, Windows 에서는 nccl 이 없어서 제대로 된 멀티 GPU 학습 자체가 어려움.

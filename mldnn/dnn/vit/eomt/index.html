    EoMT (2026)

    EoMT — Your ViT is Secretly an Image Segmentation Model (2025)

    📄 논문: Your ViT is Secretly an Image Segmentation Model — Kerssies et al. (TU Eindhoven · Politecnico di Torino · RWTH Aachen), CVPR 2025 Highlight · 프로젝트 페이지 · 공식 구현 · Hugging Face

    결론부터 아주 쉽게: “ViT로 segmentation을 하려고 그동안 덕지덕지 붙이던 부가 장치(adapter, pixel decoder, Transformer decoder)는 모델이 충분히 크고 사전학습이 충분하면 전부 필요 없음. 쿼리 토큰 몇 개만 ViT에 끼워 넣으면 ViT 자체가 segmentation 모델임.” 그 결과 ViT-L 기준 Mask2Former + ViT-Adapter 대비 4.4배 빠르면서 PQ는 1.1밖에 안 떨어짐 (COCO panoptic 57.1 → 56.0, 29 → 128 FPS). ViT 원논문이 “데이터가 많으면 CNN의 inductive bias가 필요 없다"고 한 것을, segmentation용 부가 구조의 inductive bias로 확장한 논문임. ViT 문서의 §4(inductive bias)와 §8(한계: dense prediction)을 먼저 보고 오면 이해가 빠름.

    🔷 0. 30초 요약 — 그림 한 장

    • 위 그림: 왼쪽이 기존 방식, 오른쪽이 EoMT. 박스 4개가 박스 1개로 줄었음
    • 아래 그래프: x축이 속도(FPS, 로그 스케일), y축이 정확도(PQ). 오른쪽 위일수록 좋음
      • 파란 선(기존): 모델을 키워도(S→g) 속도가 20~30 FPS에 묶여 있음. 부가 장치가 병목이기 때문임
      • 주황 선(EoMT): ViT-L이 128 FPS에 PQ 56.0 — 기존 방식의 ViT-B(32 FPS, PQ 54.4)보다 4배 빠르면서 더 정확함
    • 핵심 메시지: “부가 장치에 연산을 쓰지 말고, 그 연산으로 ViT 자체를 키워라”

    🔷 1. 배경 — ViT로 segmentation 하려면 뭐가 필요했나

    1.1 세 가지 segmentation과 평가 지표

    태스크목표지표
    Semantic픽셀마다 클래스 하나 (같은 클래스 물체는 구분 안 함)mIoU
    Instance셀 수 있는 물체(사람, 차)를 개체별로 분리AP
    Panoptic둘을 합침 — things(개체별) + stuff(하늘, 도로는 클래스별)PQ (Panoptic Quality)

    이 논문은 셋 다 다루지만 주로 COCO panoptic PQ로 이야기함.

    1.2 ViT가 segmentation에 불리했던 이유

    ViT 문서 §3.4에서 본 것처럼, ViT는 처음부터 끝까지 해상도 하나(1/16), 차원 하나만 유지함. 반면 CNN은 층을 지날수록 1/4 → 1/8 → 1/16 → 1/32로 줄어드는 피라미드를 만들고, segmentation 모델들은 이 다중 스케일 feature를 전제로 설계되어 왔음. 그래서 “ViT는 dense prediction에 약하다"는 것이 통념이었음.

    1.3 기존 SOTA 파이프라인: ViT-Adapter + Mask2Former

    이 통념 때문에 ViT로 SOTA를 내려면 세 덩어리를 더 얹어야 했음.

    구성 요소하는 일왜 필요하다고 봤나
    ViT-AdapterCNN을 ViT 옆에 병렬로 두고, deformable attention으로 CNN feature를 ViT에 넣었다 뺐다 하며 1/4·1/8·1/16·1/32 다중 스케일 feature를 만듦ViT에 없는 지역성·다중 스케일 inductive bias 주입
    Pixel Decoder다중 스케일 feature를 deformable attention으로 섞어 정제서로 다른 층에서 온 feature를 일관되게 통합
    Transformer Decoder학습되는 object query K개가 feature에 cross-attention → 쿼리마다 마스크 + 클래스 예측쿼리 기반 통합 segmentation (Mask2Former 방식)

    여기에 Mask2Former의 핵심 기법인 masked attention이 있음: 디코더 각 층에서 중간 마스크를 먼저 예측하고, 쿼리가 자기 마스크 안쪽 픽셀에만 attention하도록 제한함. 정확도는 오르지만 매 층마다 마스크를 예측하고 attention을 마스킹해야 해서 느림.

    정리: ViT 하나 쓰려고 CNN + deformable attention + 디코더 + 마스킹을 더 붙인 셈임. 파라미터도 늘고, 무엇보다 이 모듈들은 FlashAttention 같은 Transformer 최적화의 혜택을 못 받아서 FLOPs 대비 실제 속도가 훨씬 느림.

    🔷 2. 가설 — 이 장치들은 정말 필요한가

    논문의 출발점은 ViT 원논문의 결론과 같은 논리임.

    ViT 원논문: 데이터가 충분히 크면 CNN의 inductive bias(지역성, 이동 등변성)는 모델이 스스로 배울 수 있음 EoMT: 모델이 충분히 크고 사전학습이 충분하면 segmentation 부가 장치의 inductive bias(다중 스케일, 지역 처리, 전용 디코더)도 ViT가 스스로 배울 수 있음

    근거 두 가지:

    1. 사전학습의 질 — DINOv2, EVA-02 같은 최신 vision foundation model은 masked image modeling으로 학습되어, 패치 단위의 조밀하고 세밀한 의미 정보를 이미 잘 뽑아냄. adapter가 도와줄 필요가 없음
    2. 모델 용량 — ViT-L, ViT-g 정도면 파라미터가 충분해서 segmentation에 필요한 표현을 추가 모듈 없이 내부에서 만들 수 있음

    가설이 맞다면, 부가 장치를 떼어내도 정확도는 거의 안 떨어지고 속도만 크게 오를 것임. 그래서 하나씩 떼어내면서 측정함.

    🔷 3. 하나씩 떼어내기 — Mask2Former에서 EoMT까지

    DINOv2 ViT-L, COCO panoptic, 640×640 입력, H100 기준:

    단계제거한 것ParamsGFLOPsFPSPQ
    (0)— (ViT-Adapter + Mask2Former)349M8302957.1
    (1)ViT-Adapter342M7003656.7 (−0.4)
    (2)Pixel Decoder337M6856156.9 (+0.2)
    (3)다중 스케일 feature328M6736456.7 (−0.2)
    (4)Transformer Decoder (쿼리를 ViT 안으로)316M8286156.2 (−0.5)
    (5)추론 시 masked attention (= EoMT)316M66912856.0 (−0.2)

    읽는 법:

    • (1)~(3): adapter, pixel decoder, 다중 스케일을 다 빼도 PQ −0.4에 속도 2.2배. “다중 스케일이 필수"라는 통념이 큰 모델 + 좋은 사전학습에서는 안 맞음
    • (4): 디코더를 없애고 쿼리를 ViT 안으로 넣음. 이때 masked attention용 중간 마스크를 매 블록 예측해야 해서 FLOPs가 일시적으로 다시 오름 (upscale이 비쌈)
    • (5): mask annealing(§5)으로 추론 시 masked attention 자체를 없앰 → 속도 2.1배 추가 상승
    • 전체: PQ 57.1 → 56.0 (−1.1), 속도 29 → 128 FPS (4.4배)

    ⚠️ FLOPs는 830 → 669로 19%밖에 안 줄었는데 FPS는 4.4배임. 부가 장치들이 FLOPs에 비해 실제로는 훨씬 느린 (최적화 안 된 deformable attention, reshape, 작은 커널 conv 등) 연산이었다는 뜻임. EfficientFormer 가 지적한 “FLOPs ≠ latency"와 같은 교훈임.

    🔷 4. EoMT 아키텍처 — ViT에 쿼리를 끼워 넣기

    4.1 흐름

    1. 앞 $L_1$개 블록: 보통의 ViT와 완전히 같음. 패치 토큰만 처리 (ViT-L이면 $L_1 = 20$)
    2. 쿼리 삽입: 학습되는 벡터 $K$개(panoptic/instance는 200, semantic은 100)를 패치 토큰 열 앞에 concat. ViT 의 [class] 토큰을 1개가 아니라 K개 붙인 것과 같은 모양임
    3. 뒤 $L_2$개 블록: 쿼리 + 패치를 한 시퀀스로 같이 처리 (ViT-L이면 $L_2 = 4$). 블록 구조는 ViT 그대로이고 바뀐 건 시퀀스 길이뿐임
    4. Mask Module (작음):
      • 클래스 로짓 = Linear(쿼리 토큰) → $\mathbb{R}^{C}$
      • 마스크 로짓 = MLP(쿼리 토큰) · Upscale(패치 feature) → 1/16 해상도 feature를 1/4로 upscale한 뒤 쿼리 임베딩과 내적

    4.2 왜 이게 “디코더를 대체"하나

    Mask2Former 디코더가 하던 일은 두 가지였음.

    디코더가 하던 일EoMT에서는
    쿼리끼리 self-attention (어느 쿼리가 어느 물체를 맡을지 조율)ViT 블록의 self-attention 안에서 query→query 부분이 담당
    쿼리가 이미지 feature에 cross-attention (물체 정보 수집)같은 self-attention 안에서 query→patch 부분이 담당

    원래는 이 둘을 별도 층에서 순차적으로 했는데, EoMT는 ViT의 self-attention 한 번으로 둘을 동시에 함. 덤으로 patch→query 방향(패치가 쿼리 정보를 참고)도 생김.

    💡 “[class] 토큰을 K개 넣으면 object query 아닌가?” — 맞음. DETR 은 쿼리를 디코더에 따로 두고 이미지 feature에 cross-attention 시켰고, EoMT는 그 쿼리를 ViT 토큰 열에 그냥 concat함. 쿼리 벡터 자체(nn.Embedding(K, D))와 loss(헝가리안 1:1 매칭)는 DETR·Mask2Former와 같고, 바뀐 건 “쿼리가 어디서 이미지를 보느냐"뿐임. 단 concat만 하고 매칭 loss를 안 걸면 쿼리 K개가 전부 같은 것을 배워 collapse함 — ViT Q&A “[class] 토큰을 100개 넣으면?” 참고.

    4.3 비용은 얼마나 느나

    640×640 입력, 패치 16 → 패치 토큰 1,600개. 여기에 쿼리 200개를 붙이면 뒤 $L_2$개 블록에서만 토큰이 12.5% 늘어남. ViT-L은 $L_1 = 20, L_2 = 4$이므로 전체 ViT가 처리하는 토큰 수는 2.1%만 증가함. 사실상 공짜임.

    4.4 텐서 shape로 보기 (ViT-L, 640×640, K=200)

    단계shape설명

    패치 임베딩 + 위치 임베딩(B, 1600, 1024)40×40 패치, D=1024
    블록 1~20(B, 1600, 1024)보통 ViT
    쿼리 concat(B, 1800, 1024)200 + 1600

    [class] 토큰 하나 자리에서 클래스 하나를 뽑던 ViT 와 비교하면, 쿼리 200개 자리에서 (클래스, 마스크) 200쌍을 뽑는 것이 전부임.

    4.5 학습

    • 손실은 Mask2Former와 동일: 클래스 CE + 마스크 BCE + Dice. 헝가리안 매칭으로 GT 세그먼트 ↔ 쿼리 1:1 할당
    • 사전학습 가중치: DINOv2 (timm vit_large_patch14_reg4_dinov2). 패치 14를 16으로 리사이즈해 사용 (FlexiViT 방식), 위치 임베딩은 bicubic 보간
    • AdamW lr 1e-4, layer-wise lr decay 0.8, COCO 12 epoch / ADE20K 31 / Cityscapes 107
    • 데이터 증강은 Mask2Former와 동일 (large-scale jitter 등)

    🔷 5. Mask Annealing — 학습 때만 masked attention 쓰기

    5.1 학습 중 masked attention

    Mask2Former의 masked attention이 정확도를 올려준다는 건 알려져 있으므로, EoMT도 학습 중에는 이걸 씀. 뒤 $L_2$개 블록 각각 앞에서 (가중치 공유하는) Mask Module로 중간 마스크를 예측하고, 그 마스크로 self-attention 행렬의 query→patch 구역만 가림.

    문제는 추론 때임. 매 블록마다 마스크 예측(특히 upscale)을 해야 해서 느림 (§3 표의 (4)단계, 61 FPS).

    5.2 그냥 끄면 안 되나 → 안 됨. 그래서 annealing

    학습추론FPSPQ
    마스킹 O마스킹 O6156.2
    마스킹 O마스킹 X12827.4 (−28.8) ← 학습/추론 불일치로 붕괴
    마스킹 X마스킹 X12853.2 (−3.0) ← 수렴은 하지만 정확도 손해
    Mask annealing마스킹 X12856.0 (−0.2)

    Mask annealing: 각 블록에서 쿼리마다 마스크를 적용할 확률 $P_{mask}$를 두고, 1.0에서 시작해 앞 블록부터 순서대로 0.0까지 줄임 (polynomial decay).

    • 초반: masked attention의 도움으로 빠르게 수렴
    • 후반: 마스크 없이 동작하는 법을 점진적으로 학습
    • 종료 시: 마스크 확률 0 → 추론에서 중간 마스크 예측도, attention 마스킹도 전혀 필요 없음

    결과적으로 정확도는 유지(56.2 → 56.0)하면서 속도는 2.1배(61 → 128 FPS). 이 기법이 EoMT를 “진짜 순수 ViT"로 만들어 주는 핵심 부품임.

    Swin, ConvNeXt 같은 비-ViT backbone은 DINOv2 가중치를 못 씀. EoMT는 순수 ViT라 foundation model을 그대로 초기화에 써서 OOD에서 +7.8 mIoU.

    (2) ViT용 최적화 기법이 그대로 먹힘 — Token merging (Table 9) 의미가 비슷한 토큰을 합쳐 연산을 줄이는 ALGM을 적용하면

    FLOPsThroughput
    ViT-Adapter + M2F5200 → 30319 → 9 (+0%) — adapter 상호작용 때문에 토큰을 다시 풀어야 해서 병목
    EoMT4350 → 118329 → 38 (+31%)

    FlashAttention, torch.compile, 전용 하드웨어 등 Transformer 생태계의 발전을 병목 없이 흡수할 수 있다는 것이 순수 ViT 구조의 실질적 장점임.

    🔷 7. 최소 구현 (PyTorch)

    ViT §7의 VisionTransformer를 그대로 가져와서 쿼리 삽입 + Mask Module만 얹은 구조 이해용 코드임. (실제 EoMT는 DINOv2 가중치, register 토큰, masked attention/annealing, 헝가리안 매칭 손실이 추가됨.)

    import torch
import torch.nn as nn
# ViT.md §7 의 VisionTransformer 가 정의되어 있다고 가정


class EoMT(nn.Module):
    """plain ViT + K개의 쿼리 토큰 + 작은 mask module."""
    def __init__(self, vit: "VisionTransformer", num_queries=100, num_classes=150,
                 l2=4, patch_size=16):
        super().__init__()
        D = vit.pos_embed.shape[-1]
        self.vit, self.K, self.l2, self.p = vit, num_queries, l2, patch_size
        self.queries = nn.Parameter(torch.zeros(1, num_queries, D))      # 학습되는 쿼리 (ViT의 cls 토큰 K개 버전)
        nn.init.trunc_normal_(self.queries, std=0.02)

        # --- Mask Module ---
        self.class_head = nn.Linear(D, num_classes + 1)                   # +1: "no object"
        self.mask_mlp = nn.Sequential(nn.Linear(D, D), nn.GELU(),
                                      nn.Linear(D, D), nn.GELU(), nn.Linear(D, D))
        self.upscale = nn.Sequential(                                     # 1/16 -> 1/4
            nn.ConvTranspose2d(D, D, 2, stride=2), nn.GELU(),
            nn.ConvTranspose2d(D, D, 2, stride=2),
        )

    def forward(self, x):
        B, _, H, W = x.shape
        h, w = H // self.p, W // self.p

        # 1) 패치 임베딩 + 위치 임베딩 (cls 토큰은 안 씀 -> pos_embed[:, 1:])
        x = self.vit.patch_embed(x) + self.vit.pos_embed[:, 1:]           # (B, N, D)

        # 2) 앞 L1 블록: 보통 ViT
        for blk in self.vit.blocks[:-self.l2]:
            x = blk(x)

        # 3) 쿼리 concat 후 뒤 L2 블록: 쿼리 + 패치 공동 처리
        q = self.queries.expand(B, -1, -1)                                # (B, K, D)
        x = torch.cat([q, x], dim=1)                                      # (B, K+N, D)
        for blk in self.vit.blocks[-self.l2:]:
            x = blk(x)              # 학습 중이라면 여기서 query->patch attention 을 중간 마스크로 마스킹 (annealing)

        # 4) Mask Module
        q, feat = x[:, :self.K], x[:, self.K:]                            # (B,K,D), (B,N,D)
        class_logits = self.class_head(q)                                 # (B, K, C+1)
        feat = feat.transpose(1, 2).reshape(B, -1, h, w)                  # (B, D, H/16, W/16)
        feat = self.upscale(feat)                                         # (B, D, H/4,  W/4)
        mask_emb = self.mask_mlp(q)                                       # (B, K, D)
        mask_logits = torch.einsum("bkd,bdhw->bkhw", mask_emb, feat)      # (B, K, H/4, W/4)
        return class_logits, mask_logits


if __name__ == "__main__":
    vit = VisionTransformer(img_size=224, patch_size=16, dim=768, depth=12, heads=12)
    model = EoMT(vit, num_queries=100, num_classes=150, l2=3)          # ViT-B 는 논문에서 L2=3
    cls, masks = model(torch.randn(2, 3, 224, 224))
    print(cls.shape, masks.shape)                                      # (2, 100, 151) (2, 100, 56, 56)

    핵심은 forward의 3)임 — ViT 블록을 한 줄도 안 고치고 입력 시퀀스에 토큰 K개를 더 붙였을 뿐임.

    의의

    항목내용
    ViT 논문의 결론을 segmentation으로 확장“충분한 규모 + 사전학습이면 inductive bias는 학습됨"이 분류뿐 아니라 dense prediction에서도 성립함을 보임
    속도–정확도 프론티어 이동같은 정확도에서 3~4배, 같은 속도에서 훨씬 높은 PQ. 실시간 segmentation의 현실적 선택지
    단순함구현이 ViT + 쿼리 + 작은 head. Mask2Former 재현에 필요하던 deformable attention 커스텀 커널 등이 없음

    Mask annealing학습·추론 구조가 달라도 되게 하는 범용 기법. 논문은 ViT-Adapter + M2F에 적용해도 효과 있음을 보임

    한계

    • 작은 모델에서는 여전히 부가 장치가 유리함 — ViT-S/B에서는 PQ 손실이 4~6. 엣지 디바이스용 소형 모델에는 그대로 적용하기 어려움
    • 사전학습 의존 — supervised ImageNet 가중치로는 손실이 큼. 좋은 foundation model이 있는 도메인에서만 이점이 큼
    • instance segmentation / 작은 물체 — 다중 스케일 부재의 영향이 남아 있음 (AP 손실이 PQ·mIoU보다 큼)

    🔷 9. 자주 헷갈리는 점 Q&A

    Q. 쿼리 토큰이 정확히 뭔가? ViT의 [class] 토큰과 뭐가 다른가? 같은 종류의 물건임 — 이미지 내용과 무관한 학습 가능한 벡터로, attention을 통해 패치 정보를 끌어모으는 “빈 그릇”. [class] 토큰은 1개라서 “이미지 전체 = 클래스 하나"를 담고, EoMT 쿼리는 K개라서 각각 “세그먼트 하나 = (클래스, 마스크)“를 담음. 어떤 쿼리가 어떤 물체를 맡을지는 학습 중 헝가리안 매칭으로 정해지고, 쿼리끼리 self-attention하면서 서로 겹치지 않게 조율함.

    Q. 같은 클래스 물체가 두 개면 (공 2개) 어떤 쿼리가 어느 공을 맡는지 어떻게 정해지나? 클래스 head의 softmax는 “쿼리 하나가 클래스 하나"만 보장함 (class exclusivity). 필요한 건 “정답 세그먼트 하나에 쿼리 하나” (instance exclusivity)이고, 이건 학습 중 헝가리안 매칭이 정함: 200개 예측과 정답 k개를 (클래스 확률 + 마스크 유사도) 비용으로 1:1 짝짓고, 짝지어진 쿼리만 그 세그먼트 loss를 받으며 나머지는 “no object” loss를 받음. 두 쿼리가 같은 공을 잡으면 하나는 반드시 no object에 배정되어 벌을 받으므로, 학습이 진행되면 서로 다른 공으로 갈라짐. 추론 때는 매칭이 없고 각 쿼리가 독립적으로 (클래스, 마스크)를 냄. 자세한 건 DETR §3.

    Q. 쿼리를 concat한 직후 첫 블록에서, 아직 이미지를 안 본 쿼리끼리 self-attention이 무슨 의미가 있나? 쿼리 200개는 서로 다른 학습된 벡터라 identity가 다름. 첫 블록의 query→query attention은 이 identity 관계만 다루고, query→patch 부분에서 각 쿼리가 이미지 정보를 처음 가져옴. 그다음 블록부터는 각 쿼리가 “무엇을 보고 있는지"까지 포함해 서로 비교하므로, 같은 물체를 두 쿼리가 중복해서 맡지 않도록 조율하는 역할이 생김. EoMT는 이걸 self-attention 한 번 안에서 query→query, query→patch를 동시에 함 (§4.2). DETR은 두 단계를 별도 층으로 나눔.

    Q. 왜 처음부터 쿼리를 넣지 않고 $L_1$개 블록 뒤에 넣나? 앞부분 블록은 이미지 feature를 만드는 단계라 쿼리가 있어 봐야 의미 없는 토큰이 늘 뿐임. 뒤 몇 블록만 쓰면 비용이 2.1%만 늘고 (§4.3), 부록 실험(Table D)에서 ViT-L은 $L_2 = 4$가 최적이었음.

    Q. 마스크 로짓을 “내적"으로 만든다는 게 무슨 뜻인가? 쿼리 임베딩 $\hat{q}_i \in \mathbb{R}^D$와 각 위치의 feature $F_4[:, y, x] \in \mathbb{R}^D$의 내적이 그 위치가 세그먼트 $i$에 속할 로짓임. 즉 “이 픽셀의 feature가 이 쿼리와 얼마나 닮았나"를 픽셀마다 계산하는 것. Mask2Former와 같은 방식이고, 파라미터가 없어서 매우 쌈.

    Q. 학습 때 masked attention을 쓰다 추론 때 끄면 왜 27.4로 붕괴하나? 학습 내내 쿼리가 “자기 마스크 안의 패치만” 보는 환경에서 가중치가 맞춰졌는데, 추론에서 갑자기 모든 패치가 보이면 attention 분포가 완전히 달라짐. 학습/추론 분포 불일치의 전형적인 예임. annealing은 이 전환을 학습 후반에 서서히 겪게 해서 문제를 없앰.

    Q. 그럼 ViT-Adapter, Mask2Former는 이제 안 쓰나? 작은 모델·약한 사전학습·작은 물체 위주 태스크에서는 여전히 유효함 (§6.2, Table 3의 S/B 결과). 논문의 주장은 “필요 없다"가 아니라 “규모가 커지면 필요성이 사라지니, 그 연산을 ViT를 키우는 데 쓰는 게 낫다” 임.

    🔷 10. 한 줄 요약

    충분히 크고 잘 사전학습된 ViT에는 쿼리 토큰 몇 개만 끼워 넣으면 adapter·pixel decoder·Transformer decoder 없이도 SOTA급 segmentation이 되고, 그 덕에 4배 빠름. ViT 원논문의 “규모가 inductive bias를 대체한다"를 dense prediction에서 재확인한 논문임.

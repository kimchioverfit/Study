    ViT (2020)

    ViT — An Image is Worth 16x16 Words (2020)

    📄 논문: An Image is Worth 16x16 Words: Transformers for Image Recognition at Scale — Dosovitskiy et al. (Google Research, Brain Team), ICLR 2021 · 공식 구현 · Google Research 블로그 소개글

    결론부터 아주 쉽게: “이미지를 16×16 조각(패치)으로 잘라 단어처럼 한 줄로 세운 뒤, NLP에서 쓰던 Transformer 인코더에 거의 그대로 넣었더니 CNN 없이도 이미지 분류가 된다” 는 것을 보인 논문임. 단, 조건이 있음. 데이터가 아주 많아야 함. ImageNet(130만 장)만으로 학습하면 ResNet보다 못하지만, JFT-300M(3억 장)으로 사전학습하면 당시 SOTA를 넘어섬 (ImageNet top-1 88.55%). 모바일 지연시간 관점의 후속 개선은 EfficientFormer 참고.

    🔷 0. 30초 요약 — 한 장으로 보는 ViT

    위 그림 하나가 논문 전부라고 봐도 됨. 순서대로 읽으면

    1. 이미지를 같은 크기의 패치로 자름 (그림 왼쪽 아래, 9조각)
    2. 각 패치를 한 줄 벡터로 펴서(flatten) 선형 변환 → 패치 하나 = 토큰 하나
    3. 맨 앞에 [class] 토큰(0번)을 하나 끼워 넣고, 각 토큰에 위치 임베딩을 더함
    4. 이 토큰 열을 Transformer 인코더에 통과시킴 (오른쪽 블록을 L번 반복)
    5. 출력 중 [class] 토큰 자리만 꺼내 MLP head로 클래스 예측

    NLP Transformer와 다른 부분은 1~2번뿐임. 나머지는 BERT와 사실상 같음.

    🔷 1. 문제의식 — 왜 비전에도 Transformer인가

    NLP에서는 2017년 Attention Is All You Need 이후 Transformer가 표준이 되었고, BERT/GPT처럼 “대규모 코퍼스로 사전학습 → 작은 데이터로 미세조정” 하는 패턴이 자리잡았음. Transformer의 큰 장점은 모델과 데이터를 키울수록 성능이 계속 오르고(scalability), 아직 포화 조짐이 없다는 점이었음.

    반면 비전에서는 여전히 CNN 계열(ResNet 등)이 지배적이었음. attention을 비전에 쓰려는 시도는 있었지만 대부분

    접근문제
    CNN 안에 attention 블록을 섞기 (Non-local 등)여전히 CNN 구조에 의존
    CNN을 통째로 self-attention으로 대체 (Ramachandran 2019 등)특수한 attention 패턴 → 하드웨어 가속기에서 효율적으로 구현하기 어려움
    픽셀 단위로 Transformer 적용 (iGPT 등)픽셀 수가 너무 많아 $O(N^2)$ attention 비용을 감당 못 함 → 저해상도만 가능

    이 논문이 던지는 질문은 단순함.

    “NLP에서 쓰던 표준 Transformer를 최소한의 수정만으로 이미지에 그대로 적용하면 어떻게 되는가?”

    🔷 2. 핵심 아이디어 — 이미지를 “패치의 문장"으로 바꿈

    2.1 왜 “문장"으로 바꿔야 하나

    Transformer는 원래 토큰(단어)이 한 줄로 늘어선 시퀀스를 입력으로 받는 구조임. 이미지는 2D 격자라서 그대로는 못 넣음. 가장 단순한 방법은 픽셀 하나를 토큰 하나로 보는 것인데, 그러면 $224\times224$ 이미지 한 장이 50,176개 토큰이 됨. self-attention은 토큰 수 $N$에 대해 $O(N^2)$ 비용이라 50,176² ≈ 25억 쌍을 계산해야 하고, 이건 현실적으로 불가능함.

    그래서 픽셀 여러 개를 한 덩어리(패치)로 묶어서 토큰 하나로 취급함.

    2.2 숫자로 따라가 보기 (ViT-B/16 기준)

    입력 이미지          : 224 × 224 × 3   (H × W × C)
패치 크기 P          : 16
패치 개수 N          : (224/16) × (224/16) = 14 × 14 = 196개
패치 하나를 편 길이   : 16 × 16 × 3 = 768  (P·P·C)

    즉 이미지 한 장이 “768차원 벡터 196개짜리 문장” 으로 바뀜. NLP로 치면 단어 196개짜리 문장이고, 각 단어가 768차원 벡터인 셈임. 제목의 “16×16 words"가 정확히 이 뜻임.

    💡 비유: 신문 한 면을 통째로 읽는 대신, 가로세로 14칸으로 격자를 그어 196개 칸을 순서대로 읽는 것. 각 칸이 “단어” 하나임.

    2.3 패치 → 토큰: Linear Projection

    편 벡터(768차원)를 그대로 쓰지 않고, 학습되는 행렬 $\mathbf{E} \in \mathbb{R}^{768 \times D}$ 를 곱해 모델 차원 $D$ 로 바꿈 (ViT-B는 $D=768$이라 우연히 같은 수임. ViT-L은 1024).

    $$ \text{토큰}_i = \mathbf{x}^i_p \, \mathbf{E} \qquad (\mathbf{x}^i_p \in \mathbb{R}^{768},\ \mathbf{E} \in \mathbb{R}^{768\times D}) $$
    • 모든 패치가 같은 행렬 $\mathbf{E}$ 를 공유함 (단어 임베딩 테이블을 공유하는 것과 같음)
    • 구현상으로는 kernel=16, stride=16인 Conv2d 하나와 완전히 동일함. 16칸씩 건너뛰며 16×16 필터를 한 번씩 찍는 것 = 패치 자르기 + 행렬 곱

    2.4 [class] 토큰 — “문장 전체의 요약” 자리

    토큰 196개 앞에 학습 가능한 벡터 하나를 더 끼워 넣어 197개로 만듦. 이것이 $\mathbf{x}_{class}$ (그림의 0번 토큰).

    • 이미지 내용과 무관한 “빈 자리"인데, 인코더를 지나면서 attention으로 모든 패치 정보를 끌어모음
    • 마지막 층에서 이 자리의 출력만 꺼내 분류에 씀 → 이미지 전체를 대표하는 벡터가 됨
    • BERT의 [CLS] 토큰과 완전히 같은 아이디어임

    ❓ 왜 그냥 196개 토큰을 평균 내지 않나? 그래도 됨 (Global Average Pooling). 논문 부록에서 둘 다 실험했고 learning rate만 맞추면 성능 비슷함. [class] 토큰을 쓴 건 “NLP Transformer와 최대한 똑같이” 라는 논문 취지 때문임.

    2.5 위치 임베딩 — attention은 순서를 모름

    self-attention은 집합(set) 연산임. 토큰 순서를 바꿔 넣어도 결과가 똑같이 바뀔 뿐, “1번 토큰이 2번 옆에 있다"는 정보는 없음. 그래서 197개 토큰 각각에 자기 자리를 나타내는 벡터 $\mathbf{E}_{pos}$ 를 더해 줌.

    • $\mathbf{E}_{pos} \in \mathbb{R}^{197 \times D}$ — 자리마다 하나씩, 학습되는 파라미터
    • 원조 Transformer처럼 sin/cos 공식으로 만들지 않고 그냥 랜덤 초기화 후 학습시킴
    • 1D 임베딩임. 즉 “왼쪽에서 3번째, 위에서 2번째” 같은 2D 좌표를 알려주지 않고, “17번째 토큰"이라는 번호표만 줌 → 2D 구조는 모델이 스스로 알아내야 함 (§6에서 실제로 알아냄을 확인)

    여기까지 정리하면 인코더에 들어가는 입력은

    $$ \mathbf{z}_0 = [\,\mathbf{x}_{class};\; \mathbf{x}^1_p\mathbf{E};\; \mathbf{x}^2_p\mathbf{E};\; \cdots;\; \mathbf{x}^N_p\mathbf{E}\,] + \mathbf{E}_{pos} \qquad \in \mathbb{R}^{(N+1)\times D} $$

    🔷 3. Transformer 인코더 — 토큰들이 서로를 보게 함

    flowchart LR
    I["Image<br/>224×224×3"] --> P["Split into<br/>16×16 patches<br/>(N=196)"]
    P --> E["Linear Projection<br/>(768 → D)"]
    E --> A["+ [class] token<br/>+ Position Embedding<br/>(197 × D)"]
    A --> T["Transformer Encoder<br/>× L"]
    T --> C["[class] token<br/>output (D)"]
    C --> H["MLP Head"]
    H --> O["Class"]

    3.1 블록 하나의 동작

    인코더 블록은 두 단계로 되어 있고, 각 단계 앞에 LayerNorm, 뒤에 residual 연결이 붙음.

    $$ \mathbf{z}'_\ell = \text{MSA}(\text{LN}(\mathbf{z}_{\ell-1})) + \mathbf{z}_{\ell-1} $$$$ \mathbf{z}_\ell = \text{MLP}(\text{LN}(\mathbf{z}'_\ell)) + \mathbf{z}'_\ell $$

    (1) Multi-Head Self-Attention (MSA) — “다른 패치들을 둘러보는” 단계

    각 토큰이 나머지 196개 토큰과 얼마나 관련 있는지 점수를 매기고, 그 점수로 가중 평균을 내서 자기 표현을 갱신함.

    $$ \text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V $$
    • 예: “강아지 귀” 패치는 “강아지 얼굴”, “강아지 몸통” 패치에 높은 점수를 주고 “배경 잔디” 패치에는 낮은 점수를 줌 → 갱신 후 “귀” 토큰에 강아지 전체 맥락이 섞임
    • 첫 번째 블록부터 이미지 전체를 볼 수 있음. CNN이 여러 층을 쌓아야 receptive field가 커지는 것과 대조적임
    • Multi-head: 이 과정을 서로 다른 관점(head)으로 여러 번 병렬 수행 (ViT-B는 12 head). 어떤 head는 색을, 어떤 head는 질감을, 어떤 head는 위치 관계를 볼 수 있음

    (2) MLP — “각 토큰을 혼자서 다듬는” 단계 (= Transformer의 FFN )

    토큰마다 독립적으로 Linear(D→4D) → GELU → Linear(4D→D) 를 적용함. 토큰 간 정보 교환은 없고, attention이 모아온 정보를 비선형으로 가공하는 역할임.

    (3) 정보가 도는 방식

    단계토큰 간 정보 교환역할
    MSA✅ 있음 (모든 토큰 쌍)문맥 수집 — “다른 패치들이 뭐라고 하나”
    MLP❌ 없음 (토큰별 독립)표현 가공 — “모은 정보를 어떻게 해석하나”

    이 두 단계를 $L$번 반복하면 (ViT-B는 12번) 각 토큰이 점점 더 넓고 추상적인 문맥을 갖게 됨.

    3.2 원조 Transformer와 다른 선택들

    항목ViT의 선택비고
    Normalization 위치Pre-LN (LN → MSA/MLP → residual)원조 논문은 Post-LN. Pre-LN이 깊은 모델 학습에 안정적
    MLP 활성함수GELU원조는 ReLU
    디코더없음 (인코더만)분류라 출력 시퀀스를 생성할 필요가 없음
    위치 임베딩학습되는 1D원조는 고정 sin/cos

    3.3 분류 — 마지막에 [class] 토큰만 꺼냄

    $$ \mathbf{y} = \text{LN}(\mathbf{z}^0_L) $$

    $\mathbf{z}^0_L$ (마지막 층 출력의 0번, 즉 [class] 자리)에 MLP head를 붙여 클래스를 예측함. 사전학습 때는 hidden layer 하나짜리 MLP, 미세조정 때는 단일 Linear 층으로 교체함.

    3.4 텐서 shape로 다시 보기

    단계shape (배치 B, ViT-B/16)설명
    입력(B, 3, 224, 224)RGB 이미지
    패치 자르기 + 펴기(B, 196, 768)196개 패치, 각 16·16·3
    Linear Projection(B, 196, 768)× E, D=768
    [class] 토큰 추가(B, 197, 768)앞에 1개
    + 위치 임베딩(B, 197, 768)같은 shape 더하기
    인코더 × 12(B, 197, 768)shape 불변 — 이게 Transformer의 특징
    [class] 자리 선택(B, 768)x[:, 0]
    MLP head(B, 1000)ImageNet 1000 클래스

    인코더를 아무리 통과해도 shape가 (197, 768) 그대로인 점이 CNN과 가장 다름. CNN은 층을 지날수록 공간 해상도가 줄고 채널이 늘어나는 피라미드 구조인데, ViT는 처음부터 끝까지 같은 해상도(14×14 토큰), 같은 차원을 유지함. 이 때문에 나중에 detection/segmentation에 쓰려면 별도 장치가 필요해짐 (§8).

    표기법: ViT-L/16 = Large 모델 + 패치 크기 16×16. Hidden $D$ 를 누가 정하는지, 키웠을 때 도메인에 따라 왜 기대만큼 안 오르는지는 Dimension 참고. 패치가 작을수록(/14, /8 …) 토큰 수 $N$이 늘어 정확도는 오르지만 연산량이 급증함 (attention은 $O(N^2)$). ViT-B/32는 토큰이 49개뿐이라 빠르지만 정확도가 낮고, ViT-H/14는 256개라 느리지만 가장 정확함.

    3.6 Hybrid 구조

    패치를 원본 픽셀에서 자르는 대신, CNN(ResNet)의 중간 feature map 을 패치로 잘라 넣는 변형도 실험함. feature map은 이미 공간이 축소되어 있으므로 패치 크기 1×1로 잘라도 토큰 수가 적당함. → 연산 예산이 작을 때는 hybrid가 유리하지만, 모델이 커지면 차이가 사라짐 (§5.4).

    🔷 4. 왜 데이터가 많이 필요한가 — Inductive Bias

    이 논문에서 가장 중요한 개념임. “ViT가 CNN보다 좋다"가 아니라 “언제 좋은가” 를 이해하는 열쇠임.

    4.1 CNN에는 “이미지에 대한 상식"이 내장되어 있음

    CNN은 구조 자체에 이미지에 대한 사전 가정(inductive bias) 이 들어 있음.

    CNN의 inductive bias의미구조에 어떻게 박혀 있나
    지역성(locality)가까운 픽셀끼리 관련이 있음3×3 같은 작은 커널 — 멀리 있는 픽셀은 애초에 못 봄
    이동 등변성(translation equivariance)물체가 이동해도 같은 특징같은 필터를 모든 위치에 공유
    계층적 2D 구조작은 특징이 모여 큰 특징이 됨층을 쌓을수록 receptive field가 커지는 피라미드

    이 가정들은 대부분의 자연 이미지에서 참임. 그래서 CNN은 “정답 힌트"를 미리 받고 시작하는 셈이고, 적은 데이터로도 잘 배움.

    4.2 ViT에는 이런 가정이 거의 없음

    • self-attention은 전역(global) 연산이라 첫 층부터 모든 패치가 모든 패치를 봄 → “가까운 게 중요하다"는 힌트 없음
    • 위치 임베딩은 1D 번호표일 뿐 → “이 패치가 저 패치 바로 옆이다"는 힌트 없음
    • 2D 구조가 들어가는 곳은 패치를 자르는 순간과 해상도 변경 시 위치 임베딩 보간 두 군데뿐임

    즉 ViT는 “이미지란 무엇인가"를 백지 상태에서 데이터만 보고 배워야 함.

    4.3 그래서 결론은 “데이터 양에 따라 승자가 바뀜”

    데이터가 적을 때: 사전 가정이 있는 CNN이 유리. ViT는 힌트가 없어 과적합함 데이터가 많을 때: 사전 가정이 오히려 제약. 데이터에서 직접 패턴을 배우는 ViT가 유리

    💡 비유: 외국어를 배울 때 문법책(inductive bias)을 먼저 보면 예문 100개로도 꽤 함. 하지만 예문 1억 개를 볼 수 있다면 문법책 없이 통째로 익히는 쪽이 더 유연하고 정확해짐. 문법책의 규칙이 모든 경우를 설명하진 못하기 때문임.

    이 가설을 실험으로 검증한 것이 §5의 핵심 결과임.

    미세조정ImageNet, CIFAR-10/100, Oxford Pets/Flowers, VTAB(19 tasks)SGD momentum, batch 512, 해상도 384 로 올림

    미세조정 시 해상도를 올리는 이유: 패치 크기는 그대로 두고 해상도만 올리면 토큰 수 $N$이 늘어 더 세밀한 정보를 볼 수 있음 (224→384면 196개→576개). 이때 사전학습된 위치 임베딩(197개)과 길이가 안 맞으므로, 원래 14×14 격자에 놓고 24×24로 2D 보간(interpolation) 해서 씀. 이 보간이 ViT에 수동으로 넣어주는 몇 안 되는 2D inductive bias 중 하나임.

    🔷 6. 모델 내부 들여다보기 — 정말 “이미지"를 배웠나

    ViT에는 CNN 같은 사전 가정이 없다고 했는데, 그러면 학습 후에 뭘 배웠는지 확인해 볼 필요가 있음. 논문 Figure 7의 세 가지 분석임.

    (1) 학습된 patch embedding 필터 (왼쪽) 첫 층 선형 변환 $\mathbf{E}$의 주성분을 시각화하면, CNN 첫 층 필터처럼 저차원의 방향성/색상 기저 함수 모양이 나옴. 아무도 “edge를 찾아라"고 알려주지 않았는데 데이터만 보고 비슷한 것을 배움.

    (2) 위치 임베딩의 유사도 (가운데) 1D 번호표만 줬는데도, 임베딩 간 코사인 유사도를 2D 격자에 그려 보면

    • 가까운 패치끼리 유사도가 높고 (각 칸의 밝은 부분이 자기 위치 주변에 몰려 있음)
    • 같은 행 / 같은 열 끼리 유사도가 높은 십자 무늬가 나타남 → “17번째 토큰은 3행 3열이다"를 스스로 학습했다는 뜻임. 2D 위치 임베딩을 넣어도 차이가 없던 이유가 이것임.

    (3) Attention distance ≈ receptive field (오른쪽) 각 head가 평균적으로 얼마나 먼 패치에 attention을 두는지(픽셀 단위) 층별로 측정하면

    • 낮은 층부터 이미 일부 head는 이미지 전체(100픽셀 이상)를 봄 — CNN 초반 층에서는 구조적으로 불가능한 일
    • 다른 head들은 낮은 층에서 지역적(local, 20~40픽셀)으로 동작 → CNN 초반 층과 비슷한 역할을 스스로 맡음
    • 층이 깊어질수록 모든 head의 attention distance가 늘어남 → CNN의 receptive field 확장과 유사한 패턴을 학습으로 획득

    (4) 실제로 어디를 보나

    [class] 토큰이 마지막에 어떤 패치를 많이 참고했는지 그려 보면, 배경이 아니라 분류 대상 물체 위에 집중됨. bounding box 없이 분류 라벨만으로 학습했는데도 “어디를 봐야 하는지"를 익힌 것임.

    🔷 7. 최소 구현 (PyTorch)

    논문 구조를 그대로 옮긴 최소 구현임. §3.4의 shape 표와 대응시키며 읽으면 됨. 패치 자르기 + 선형 변환은 kernel = stride = P인 Conv2d 하나로 동일하게 구현됨.

    import torch
import torch.nn as nn


class PatchEmbed(nn.Module):
    """(B, C, H, W) -> (B, N, D).  kernel=stride=P 인 conv가 곧 '패치 자르기 + 선형 변환'."""
    def __init__(self, img_size=224, patch_size=16, in_ch=3, dim=768):
        super().__init__()
        self.proj = nn.Conv2d(in_ch, dim, kernel_size=patch_size, stride=patch_size)
        self.num_patches = (img_size // patch_size) ** 2

    def forward(self, x):
        x = self.proj(x)                      # (B, D, H/P, W/P) = (B, 768, 14, 14)
        return x.flatten(2).transpose(1, 2)   # (B, N, D)       = (B, 196, 768)


class EncoderBlock(nn.Module):
    """Pre-LN Transformer encoder block: z' = MSA(LN(z)) + z ;  z = MLP(LN(z')) + z'"""
    def __init__(self, dim, heads, mlp_ratio=4.0, drop=0.0):
        super().__init__()
        self.norm1 = nn.LayerNorm(dim)
        self.attn = nn.MultiheadAttention(dim, heads, dropout=drop, batch_first=True)
        self.norm2 = nn.LayerNorm(dim)
        hidden = int(dim * mlp_ratio)
        self.mlp = nn.Sequential(
            nn.Linear(dim, hidden), nn.GELU(), nn.Dropout(drop),
            nn.Linear(hidden, dim), nn.Dropout(drop),
        )

    def forward(self, x):
        h = self.norm1(x)
        x = x + self.attn(h, h, h, need_weights=False)[0]   # 토큰끼리 정보 교환
        x = x + self.mlp(self.norm2(x))                     # 토큰별 독립 가공
        return x


class VisionTransformer(nn.Module):
    def __init__(self, img_size=224, patch_size=16, in_ch=3, num_classes=1000,
                 dim=768, depth=12, heads=12, mlp_ratio=4.0, drop=0.0):
        super().__init__()
        self.patch_embed = PatchEmbed(img_size, patch_size, in_ch, dim)
        N = self.patch_embed.num_patches

        self.cls_token = nn.Parameter(torch.zeros(1, 1, dim))        # x_class
        self.pos_embed = nn.Parameter(torch.zeros(1, N + 1, dim))    # E_pos (1D, 학습됨)
        nn.init.trunc_normal_(self.pos_embed, std=0.02)
        nn.init.trunc_normal_(self.cls_token, std=0.02)

        self.blocks = nn.Sequential(*[EncoderBlock(dim, heads, mlp_ratio, drop) for _ in range(depth)])
        self.norm = nn.LayerNorm(dim)
        self.head = nn.Linear(dim, num_classes)                      # MLP head (미세조정 시 zero-init 교체)

    def forward(self, x):
        B = x.shape[0]
        x = self.patch_embed(x)                                      # (B, 196, 768)
        cls = self.cls_token.expand(B, -1, -1)                       # (B, 1, 768)
        x = torch.cat([cls, x], dim=1) + self.pos_embed              # z_0: (B, 197, 768)
        x = self.blocks(x)                                           # z_L: (B, 197, 768)  shape 불변
        x = self.norm(x[:, 0])                                       # y = LN(z_L^0): (B, 768)
        return self.head(x)                                          # (B, 1000)


if __name__ == "__main__":
    # ViT-B/16
    model = VisionTransformer()
    print(sum(p.numel() for p in model.parameters()) / 1e6, "M params")   # ≈ 86M
    print(model(torch.randn(2, 3, 224, 224)).shape)                        # (2, 1000)

    실무에서는 timm 의 vit_base_patch16_224 등 사전학습 가중치가 있는 구현을 쓰는 것이 일반적임. 위 코드는 구조 이해용.

    🔷 8. 의의와 한계

    의의

    항목내용
    패러다임 전환“비전 = CNN” 공식을 깨고, NLP와 같은 아키텍처를 비전에서도 쓸 수 있음을 증명 → 이후 멀티모달(CLIP 등)의 토대
    스케일링 법칙 확인데이터·모델을 키우면 CNN보다 더 잘 커진다는 것을 실측. “inductive bias vs 데이터 양” 트레이드오프를 명확히 제시
    단순함특수한 attention 패턴이나 CNN 결합 없이 표준 Transformer 그대로 → 기존 NLP 인프라/최적화를 재사용 가능
    연산 효율같은 성능을 ResNet 대비 2~4배 적은 사전학습 연산으로 달성

    한계

    • 데이터 의존성: ImageNet-1k만으로는 ResNet에 밀림. JFT-300M은 비공개 데이터라 재현 불가
    • $O(N^2)$ attention: 해상도를 올리면 토큰 수가 제곱으로 늘어남 → detection/segmentation처럼 고해상도가 필요한 dense prediction에 바로 쓰기 어려움
    • 단일 스케일 feature: §3.4에서 본 것처럼 끝까지 14×14 토큰 하나의 해상도만 있음. CNN처럼 계층적(multi-scale) feature map이 없어 FPN 류 구조와 궁합이 안 맞음 (→ 이 통념을 뒤집은 것이 EoMT )
    • 분류만 다룸: detection, segmentation 등 다른 태스크로의 적용은 후속 과제로 남김
    • 실기기 속도: 큰 커널 patch embedding, LayerNorm, reshape 등이 모바일에서 병목 → EfficientFormer 가 다룸

    이후 흐름

    후속해결한 한계

    Swin Transformer (2021)Window attention으로 $O(N)$ 복잡도 + 계층적 feature map → detection/segmentation backbone으로 사용 가능

    🔷 9. 자주 헷갈리는 점 Q&A

    Q. 패치 크기를 16 대신 8로 하면?

    A. 토큰 수가 196 → 784로 4배, attention 비용은 16배 늘어남. 대신 더 세밀하게 봐서 정확도는 오름. ViT-H/14가 /16보다 정확한 이유임.

    Q. CNN 없이 어떻게 edge 같은 저수준 특징을 잡나?

    A. 첫 층 선형 변환 $\mathbf{E}$가 학습을 통해 edge/색상 필터 역할을 하게 됨 (§6-(1)). 그리고 낮은 층의 일부 attention head가 지역적으로 동작하며 CNN 초반 층 역할을 함 (§6-(3)).

    Q. 위치 임베딩이 없으면 어떻게 되나?

    A. 모델이 패치 순서를 전혀 모르게 됨 (bag of patches). 논문 실험에서 약 3%p 하락. 완전히 망가지지는 않는 이유는 패치 하나하나의 내용만으로도 분류 단서가 꽤 있기 때문임.

    Q. 왜 ImageNet만으로는 안 되나? DeiT는 됐다던데?

    A. ViT 원논문 학습 레시피로는 안 됐음. DeiT는 강한 data augmentation, regularization, 그리고 CNN teacher로부터의 distillation으로 사실상 inductive bias를 “데이터와 학습 방법"으로 보충해서 ImageNet-1k만으로 성공함. 즉 데이터가 부족하면 다른 방법으로 사전 지식을 넣어줘야 한다는 §4의 결론과 일치함.

    Q. 미세조정 때 해상도를 바꾸면 위치 임베딩은?

    A. 사전학습 때의 14×14 격자 임베딩을 새 격자(예: 24×24)로 2D 보간함. 패치 크기는 그대로라 $\mathbf{E}$는 재사용 가능함.

    Q. 왜 원조 Transformer와 달리 디코더가 없나?

    A. 디코더는 “출력 시퀀스를 한 토큰씩 생성"하기 위한 장치임 (Transformer §10 ). 분류는 생성할 시퀀스가 없고, 인코더 self-attention만으로 패치 196개가 서로 정보를 다 교환하므로 마지막에 [class] 토큰 하나만 꺼내면 됨. 최근 모델이 디코더를 붙이는 건 ViT가 부족해서가 아니라 출력 형태가 복잡해져서임 — detection은 “무엇이·어디에·몇 개"를 동시에 요구하고 (DETR ), segmentation은 1/16 해상도 feature를 픽셀 단위로 되돌려야 함 (EoMT ). Decoder 개념 문서 의 “세 가지 디코더” 참고.

    Q. [class] 토큰을 100개 넣고 각각 물체 하나씩 맡기면 detection이 되지 않나?

    A. 구조만 보면 맞음 — 실제로 EoMT 가 정확히 그렇게 함 (쿼리 K개를 토큰 열에 concat). 하지만 loss가 같으면 100개가 전부 같은 것을 배워도 손해가 없어서 collapse함. 패치 Key가 $K = \begin{bmatrix}1&0\\0&1\\1&1\end{bmatrix}$이고 토큰 두 개가 똑같이 $[1,1]$이면 $QK^\top$의 두 행이 같고, softmax·가중합 결과도 같음. 처음에 조금 다르게 시작해도 둘 다 “이 이미지는 코끼리"라는 같은 loss를 받으면 gradient가 같은 방향이라 서로 달라질 이유가 없음. 서로 다른 물체를 맡게 하려면 “정답 물체 하나당 토큰 하나"를 강제하는 loss(헝가리안 1:1 매칭)가 필요하고, 그것이 DETR §3의 핵심임. 즉 object query의 본질은 벡터 모양이 아니라 매칭 loss임. 세 모델의 흐름 분기도와 공 2개 예시는 DETR §2.5~2.6에 그림으로 있음.

    Q. 물체 하나가 패치 2개에 걸쳐 분할되면 어떻게 하나의 물체로 인식하나?

    A. 먼저 원조 ViT에서 패치끼리는 겹치지 않음 (kernel = stride = P). 여기서 겹친다는 것은 패치가 겹치는 게 아니라, 물체가 패치 경계를 넘어 여러 패치에 걸쳐 있다는 뜻임.

    처음에는 각 패치 토큰이 물체의 일부만 봄. 예를 들어 강아지 얼굴이 두 패치로 나뉘면 한 토큰에는 귀와 얼굴 왼쪽, 다른 토큰에는 눈과 얼굴 오른쪽의 특징이 들어감. 하지만 이 두 조각을 따로 분류하는 것이 아님. 위치 임베딩이 두 패치의 위치를 알려 주고, self-attention이 모든 패치의 정보를 주고받게 하므로 층을 지날수록 각 토큰은 다른 조각의 정보까지 포함한 문맥 표현으로 바뀜. 마지막에는 [class] 토큰이 관련 패치들의 증거를 모아 이미지 전체를 분류함.

    즉 모델이 경계에서 잘린 두 조각을 픽셀 수준으로 다시 붙이는 별도 알고리즘을 쓰는 것은 아님. 학습 과정에서 “이 위치들의 조각이 함께 나타나면 강아지” 같은 관계를 attention으로 배우는 것임. detection이나 segmentation에서는 object query·decoder가 여러 패치 토큰을 함께 읽어 하나의 물체나 마스크를 출력함.

    다만 패치가 클수록 작은 물체나 정확한 경계 정보가 거칠어지는 한계는 있음. 이 경우에는 더 작은 패치, 겹치는 patch embedding, multi-scale feature, 고해상도 decoder 등을 사용해 보완함. 패치를 줄이면 세밀해지는 대신 토큰 수와 attention 비용이 크게 늘어나는 trade-off는 §9 첫 질문과 같음.

    Q. 패치 하나 안에 물체가 두 개 걸쳐 있으면?

    A. 그 패치는 토큰 하나 = 벡터 하나 $\mathbf{z}_i \in \mathbb{R}^{768}$로 표현되므로, 둘의 특징이 섞여서 들어감. patch별 classifier를 붙이면 출력도 하나뿐이라 둘 중 하나만 고르게 됨 (multi-label sigmoid로 “둘 다 있음"까지는 가능하지만 각각의 위치는 못 냄). DETR 처럼 쿼리 여러 개가 같은 토큰을 각자 다른 비율로 읽어 가면 물체별 출력을 따로 낼 수 있음. 단 patchify 단계에서 이미 잃은 위치 정보는 뒤에서 복구 못 하므로, 작은 물체를 다루려면 패치를 줄이거나(§9 첫 질문) multi-scale feature가 필요함.

    Q. (B, 197, 768)에서 768은 RGB 채널 3 × 256 같은 건가? 197 앞의 4나 5는 채널 수인가?

    A. 아님. 768은 논문이 정한 임베딩 차원 $D$이고, 패치 픽셀 수 $16 \times 16 \times 3 = 768$과 우연히 같을 뿐임 ($\mathbf{E}$가 768 → D 선형변환이므로 D는 512든 1024든 상관없음). 시퀀스 길이(197 = 196 패치 + [class])와 차원(768)은 완전히 다른 축임 — LLM에서도 토큰 수와 $d_{model}$은 별개임. 작은 예시에 나오는 [4, 768] → [5, 768]의 4는 패치 4개이고 채널과 무관함.

    🔷 10. 한 줄 요약

    이미지를 16×16 패치 토큰의 문장으로 보고 표준 Transformer 인코더에 넣으면, 데이터가 충분히 클 때 CNN의 inductive bias 없이도 더 적은 연산으로 SOTA를 넘을 수 있음.

    DETR (2020)

    DETR — End-to-End Object Detection with Transformers (2020)

    📄 논문: End-to-End Object Detection with Transformers — Carion, Massa, Synnaeve, Usunier, Kirillov, Zagoruyko (Facebook AI), ECCV 2020 · 공식 구현

    결론부터 아주 쉽게: “물체 검출을 ‘후보 박스를 잔뜩 뽑고 걸러내는 문제’가 아니라 ‘집합(set)을 한 번에 예측하는 문제’로 바꿈.” 학습되는 벡터 N개(object query)를 Transformer 디코더에 넣으면 각 벡터가 물체 하나씩을 맡아 (클래스, 박스)를 내놓음. anchor도, NMS도, region proposal도 없음. ViT 의 [class] 토큰이 “이미지 전체 → 클래스 하나"를 담는 빈 그릇이었다면, DETR의 object query는 “물체 하나 → (클래스, 박스)“를 담는 빈 그릇 N개임. 이 아이디어가 Mask2Former를 거쳐 EoMT 까지 이어짐.

    🔷 0. 30초 요약 — 그림 한 장

    • 입력: 이미지 → CNN → feature map → 토큰 열
    • 출력: 고정 개수 N=100개의 (클래스, 박스) 쌍. 물체가 2개면 2개는 진짜 클래스, 98개는 no object
    • 학습: 예측 100개와 정답 k개를 헝가리안 매칭으로 1:1 짝지은 뒤, 짝마다 loss 계산
    • 결과: COCO에서 Faster R-CNN과 같은 AP 42.0을 anchor·NMS 없이 달성. 큰 물체는 더 잘 잡고 작은 물체는 못 잡음

    🔷 1. 문제의식 — 검출은 원래 “집합 예측"인데 왜 우회했나

    이미지 안의 물체 목록은 순서가 없는 집합임. 그런데 기존 검출기(Faster R-CNN 등)는 이걸 직접 예측하지 않고 우회함.

    단계하는 일문제
    anchor / proposal위치마다 후보 박스를 수천 개 깔아 둠크기·비율·개수를 사람이 설계
    후보마다 분류·회귀각 후보가 물체인지, 박스를 어떻게 고칠지같은 물체를 여러 후보가 중복 검출
    NMS겹치는 박스 중 점수 높은 것만 남김학습과 무관한 후처리, 임계값 튜닝 필요

    비유: 사람 10명이 사진 속 물체를 각자 외치고, 마지막에 사회자가 겹치는 답을 지우는 방식임. DETR은 처음부터 “자리 100개를 만들고, 자리마다 물체 하나씩만 앉혀라” 라고 학습시킴.

    이렇게 하려면 두 가지가 필요함.

    1. 출력 100개가 서로 겹치지 않게 예측하도록 만드는 loss → 이분 매칭 loss (§3)
    2. 출력 100개가 서로를 보면서 조율할 수 있는 구조 → Transformer 디코더의 self-attention (§4)

    🔷 2. 핵심 아이디어 — Object Query: 물체를 담을 빈 자리 N개

    2.1 구현은 그냥 학습되는 벡터 N개임

    query_embed = nn.Embedding(100, 256)   # (N, d) — 이게 object query 전부임

    처음엔 랜덤 벡터 100개이고, 학습이 끝나도 “쿼리 1번 = 사람, 2번 = 자동차” 같은 클래스 의미는 없음. 각 쿼리는 그저 “물체 하나를 담당할 후보 자리"임. 클래스가 Ball 하나뿐인 데이터셋이어도 쿼리는 100개임 — 쿼리 개수 = 최대 검출 개수이지 클래스 개수가 아님.

    2.2 쿼리가 이미지를 “조회"함

    디코더의 cross-attention 에서 쿼리가 Q가 되고, 인코더가 만든 이미지 feature가 K, V가 됨.

    $$ \text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right)V, \qquad Q = \text{object queries},\ K = V = \text{image features} $$

    쿼리 하나가 “내가 맡을 물체가 feature 어디에 있지?“라고 묻고, 닮은 위치의 feature를 가중합으로 가져오는 것임. 그래서 이름이 object query임.

    2.3 숫자로 보기 — 쿼리 2개, 패치 4개, d=2

    인코더 출력 4개와 쿼리 2개가 있다고 함.

    P1 = [1.0, 0.0]    ← 왼쪽 물체
P2 = [0.9, 0.1]    ← 왼쪽 물체
P3 = [0.0, 1.0]    ← 오른쪽 물체
P4 = [0.1, 0.9]    ← 오른쪽 물체

q1 = [0.8, 0.2]
q2 = [0.2, 0.8]

    $QK^\top$ (내적):

    P1P2P3P4
    q10.800.740.200.26
    q20.200.260.800.74

    softmax 후 q1은 P1·P2 쪽을, q2는 P3·P4 쪽을 주로 가져옴 → q1' ≈ 왼쪽 물체 표현, q2' ≈ 오른쪽 물체 표현. 실제로는 이 값들을 사람이 정하지 않고 학습이 만들어 냄. 같은 feature를 여러 쿼리가 각자 다른 비율로 읽어 갈 수 있음 — 이것이 patch별 classifier와 다른 점임 — 패치 하나에 물체 두 개가 걸쳐 있어도 출력은 쿼리마다 따로 나옴.

    2.4 디코더 층을 지나며 쿼리가 정제됨

    한 층은 쿼리끼리 self-attention → 이미지에 cross-attention → FFN이고, 이걸 6번 반복함.

    초기 쿼리 (learned)                     → "물체 하나를 맡을 빈 자리"
  ↓ self-attn  (쿼리끼리)               → 학습된 identity로 서로 구분
  ↓ cross-attn (쿼리 → 이미지 feature)   → "왼쪽에 뭔가 있음"
  ↓ FFN
  ↓ self-attn  (쿼리끼리)               → "너는 왼쪽 걸 보고 있네, 나는 오른쪽"
  ↓ cross-attn                          → "왼쪽 물체는 코끼리, 박스는 여기"
  ↓ ...
최종 쿼리 → FFN → (클래스, 박스)

    ❓ 첫 층에서 쿼리는 이미지를 본 적이 없는데 쿼리끼리 self-attention이 무슨 의미가 있나? 쿼리 100개는 서로 다른 학습된 벡터라서 identity가 다름. 첫 self-attention은 이 identity끼리의 관계만 배움. cross-attention을 한 번 거친 뒤부터는 각 쿼리가 “어떤 물체를 보고 있는지"까지 포함해서 서로 비교하므로, 같은 물체를 두 쿼리가 중복해서 잡지 않도록 조율하는 역할이 생김. 원본 구현은 디코더 입력 content를 0으로 두고, object query를 positional encoding처럼 매 attention 층 입력에 더함.

    🔷 3. 이분 매칭 loss — 쿼리를 서로 다르게 만드는 힘

    3.1 왜 필요한가

    쿼리 100개를 넣는다고 저절로 서로 다른 물체를 맡지 않음. 정답이 코끼리 2마리일 때 loss가 그냥 “코끼리를 잘 맞혀라"이면 쿼리 세 개가 전부 왼쪽 코끼리를 검출해도 손해가 없음. “정답 하나당 쿼리 하나, 쿼리 하나당 정답 하나” 를 강제하는 것이 매칭 loss임.

    3.2 절차

    정답 $y = \{y_1, \dots, y_k\}$를 no object(∅)로 채워 N개로 만들고, 예측 $\hat{y} = \{\hat{y}_1, \dots, \hat{y}_N\}$과 짝지음.

    1단계 — 매칭: 총 비용이 최소인 순열 $\hat{\sigma}$를 헝가리안 알고리즘 으로 찾음 — 비용 행렬만 주면 1:1 배정을 $O(n^3)$ 에 풀어 주는 고전 알고리즘임.

    $$ \hat{\sigma} = \arg\min_{\sigma} \sum_{i=1}^{N} \mathcal{L}_{\text{match}}(y_i, \hat{y}_{\sigma(i)}), \qquad \mathcal{L}_{\text{match}} = -\mathbb{1}_{\{c_i \neq \varnothing\}}\hat{p}_{\sigma(i)}(c_i) + \mathbb{1}_{\{c_i \neq \varnothing\}}\mathcal{L}_{\text{box}}(b_i, \hat{b}_{\sigma(i)}) $$

    즉 “정답 클래스 확률이 높고 박스가 가까운 쿼리"를 그 정답에 배정함. ∅ 정답은 비용이 0이라 매칭에 영향 없음.

    2단계 — loss: 정해진 짝에 대해서만 loss 계산.

    $$ \mathcal{L}_{\text{Hungarian}} = \sum_{i=1}^{N}\Big[-\log \hat{p}_{\hat{\sigma}(i)}(c_i) + \mathbb{1}_{\{c_i \neq \varnothing\}}\mathcal{L}_{\text{box}}(b_i, \hat{b}_{\hat{\sigma}(i)})\Big] $$
    • 클래스: CE. ∅가 대부분이라 ∅ 항은 가중치 0.1로 줄임
    • 박스: $\mathcal{L}_{\text{box}} = 5\,\|b - \hat{b}\|_1 + 2\,\mathcal{L}_{\text{GIoU}}$. L1만 쓰면 큰 박스가 손해라 스케일 불변인 GIoU를 더함
    • auxiliary loss: 디코더 6층 각각의 출력에 같은 loss를 걸어 학습을 안정화

    3.3 예시로 보기

    정답: 왼쪽 코끼리, 오른쪽 코끼리. 쿼리 3개(N=3)가 이렇게 예측했다고 함.

    쿼리예측매칭 결과loss
    q1코끼리, 박스=왼쪽↔ 왼쪽 코끼리CE + box
    q2코끼리, 박스=왼쪽 (중복)↔ ∅CE(∅) — “너는 아무것도 맡지 마라”
    q3코끼리, 박스=오른쪽↔ 오른쪽 코끼리CE + box

    q2는 클래스만 보면 맞는 답이지만 매칭에서 ∅에 배정되어 벌을 받음. 이것이 NMS를 학습 안으로 끌어들인 것임. 이 힘이 없으면 여러 쿼리가 같은 물체로 몰림 — ViT Q&A “[class] 토큰을 여러 개 넣으면?” 참고.

    ❓ softmax로 “쿼리당 클래스 하나"를 강제하면 되지 않나? softmax는 class exclusivity(한 쿼리가 두 클래스를 동시에 말하지 않음)만 줌. 필요한 것은 instance exclusivity(정답 물체 하나를 두 쿼리가 나눠 갖지 않음)이고, 같은 클래스 물체가 여러 개일 때 둘은 완전히 다른 문제임. 후자를 해결하는 것이 매칭임.

    🔷 4. 아키텍처

    4.1 흐름

    1. Backbone: ResNet-50. 입력 $3 \times H_0 \times W_0$ → $2048 \times \frac{H_0}{32} \times \frac{W_0}{32}$
    2. 채널 축소 + 평탄화: 1×1 conv로 2048 → $d = 256$, 공간을 펴서 $HW \times 256$ 토큰 열. 고정 sine 위치 인코딩을 더함
    3. 인코더 6층: 표준 Transformer 인코더 (self-attention + FFN). 토큰끼리 전역 관계 학습
    4. 디코더 6층: object query N=100개 입력. 층마다 self-attn(쿼리끼리) → cross-attn(쿼리→인코더 출력) → FFN. 마스크 없음, autoregressive 아님 — 100개를 한 번에 병렬로 뽑음
    5. 예측 head: 쿼리마다 공유 FFN → 클래스 (C+1, +1은 ∅) 와 정규화 박스 (cx, cy, w, h)

    4.2 원조 Transformer 디코더와 다른 점

    NLP Transformer 디코더DETR 디코더
    입력지금까지 생성한 토큰학습된 object query N개 (이미지와 무관)
    self-attentioncausal mask (미래 못 봄)마스크 없음 (쿼리끼리 전부 봄)
    생성 방식한 토큰씩 autoregressiveN개 동시에 병렬
    목적다음 토큰 생성물체 추출 (feature → 물체 슬롯)

    이름은 같은 “디코더"지만 하는 일이 다름 — Decoder 개념 문서 의 “세 가지 디코더” 참고.

    • AdamW, Transformer lr 1e-4, backbone lr 1e-5, weight decay 1e-4, dropout 0.1
    • 8 heads, FFN 2048, 인코더 6층 + 디코더 6층, N=100
    • 배치 64, 300 epoch (비교용 긴 스케줄은 500 epoch). Faster R-CNN보다 훨씬 오래 걸림
    • 증강: 짧은 변 480~800 랜덤 리사이즈, 랜덤 크롭

    🔷 6. 확장 — Panoptic segmentation

    각 쿼리 출력에 작은 mask head(쿼리와 인코더 feature의 attention map → FPN식 upsampling)를 붙이면 (클래스, 박스, 마스크)가 나옴. 쿼리 하나 = 세그먼트 하나이므로 things(개체)와 stuff(하늘·도로)를 같은 방식으로 다룸. COCO panoptic PQ 43.4 (R50) / 45.1 (R101) — 당시 PanopticFPN++(42.4)·UPSNet(42.5)보다 높음. 이 “쿼리마다 마스크"가 MaskFormer → Mask2Former → EoMT 의 출발점임.

    🔷 7. 최소 구현 (PyTorch)

    논문 흐름을 shape 위주로 옮긴 것임. 실제 구현(위치 인코딩을 매 층 더하기, aux loss 등)은 공식 저장소 참고.

    import torch, torch.nn as nn
import torchvision
from scipy.optimize import linear_sum_assignment


class DETR(nn.Module):
    def __init__(self, num_classes=91, d=256, nhead=8, num_queries=100):
        super().__init__()
        r50 = torchvision.models.resnet50(weights=None)
        self.backbone = nn.Sequential(*list(r50.children())[:-2])   # → (B, 2048, H/32, W/32)
        self.proj = nn.Conv2d(2048, d, 1)
        self.transformer = nn.Transformer(d, nhead, 6, 6, 2048, dropout=0.1, batch_first=True)
        self.query_embed = nn.Embedding(num_queries, d)             # object query — 이게 전부임
        self.pos = nn.Parameter(torch.randn(1, 2500, d) * 0.02)     # 논문은 고정 sine, 여기선 단순화
        self.class_head = nn.Linear(d, num_classes + 1)             # +1 = no object
        self.box_head = nn.Sequential(nn.Linear(d, d), nn.ReLU(), nn.Linear(d, d), nn.ReLU(), nn.Linear(d, 4))

    def forward(self, x):
        f = self.proj(self.backbone(x))                 # (B, 256, h, w)
        B, d, h, w = f.shape
        src = f.flatten(2).transpose(1, 2)              # (B, h*w, 256)
        src = src + self.pos[:, : h * w]
        tgt = self.query_embed.weight.unsqueeze(0).expand(B, -1, -1)   # (B, 100, 256)
        hs = self.transformer(src, tgt)                 # 디코더 출력 (B, 100, 256), 마스크 없음
        return self.class_head(hs), self.box_head(hs).sigmoid()       # (B,100,92), (B,100,4)


@torch.no_grad()
def hungarian_match(logits, boxes, gt_labels, gt_boxes):
    """한 이미지. 비용 = -p(class) + L1(box). 반환: (쿼리 idx, GT idx)"""
    prob = logits.softmax(-1)                                   # (100, C+1)
    cost = -prob[:, gt_labels] + torch.cdist(boxes, gt_boxes, p=1)   # (100, k)
    q_idx, g_idx = linear_sum_assignment(cost.cpu())
    return torch.as_tensor(q_idx), torch.as_tensor(g_idx)


model = DETR()
logits, boxes = model(torch.randn(2, 3, 800, 1066))
print(logits.shape, boxes.shape)          # torch.Size([2, 100, 92]) torch.Size([2, 100, 4])

# 이미지 0의 정답이 2개라고 하면, 쿼리 100개 중 2개만 정답에 배정되고 98개는 no-object
q_idx, g_idx = hungarian_match(logits[0], boxes[0],
                               gt_labels=torch.tensor([22, 22]),          # 코끼리 2마리 (COCO id 22)
                               gt_boxes=torch.tensor([[0.3, 0.5, 0.4, 0.6], [0.7, 0.5, 0.3, 0.5]]))
print(q_idx, g_idx)                       # 예: tensor([23, 71]) tensor([0, 1])

    🔷 8. 의의와 한계

    의의

    • 검출을 set prediction으로 정식화하고 anchor·NMS·proposal을 전부 없앤 첫 end-to-end 검출기
    • object query + 이분 매칭이라는 조합이 이후 쿼리 기반 모델 전체의 공통 언어가 됨 (Deformable DETR, DINO, MaskFormer, Mask2Former, EoMT )
    • 같은 구조로 panoptic segmentation까지 확장됨

    한계

    • 작은 물체에 약함 (1/32 단일 해상도, 전역 attention 비용 때문에 해상도를 못 올림)
    • 학습이 매우 느림 — 500 epoch. cross-attention이 초반에 이미지 전체를 균등하게 보다가 천천히 수렴하기 때문
    • 쿼리 100개 = 검출 상한. 물체가 100개 넘는 장면은 못 다룸

    이후 흐름

    모델무엇을 고쳤나

    Conditional / DAB / DN-DETR쿼리를 박스 좌표로 해석, 노이즈 정답을 쿼리로 넣어 수렴 가속

    🔷 9. 자주 헷갈리는 점 Q&A

    Q. object query와 ViT의 [class] 토큰은 뭐가 다른가? 둘 다 “이미지와 무관한 학습된 벡터가 attention으로 정보를 끌어모으는 빈 자리"임. 차이는 (1) 개수 — 1개 vs N개, (2) 자리 — 인코더 입력에 concat vs 디코더에 따로, (3) loss — 이미지 전체 클래스 vs 물체별 (클래스, 박스) + 1:1 매칭. 셋 중 본질은 (3)임. (2)는 EoMT 가 없애도 된다는 것을 보임.

    Q. 그럼 [class] 토큰을 100개 넣고 각각 박스를 뽑게 하면 DETR인가? 매칭 loss까지 붙이면 사실상 그렇고, 그게 EoMT임. 매칭 없이 같은 classification loss만 걸면 100개가 전부 같은 것을 배워도 손해가 없어서 collapse함 (ViT Q&A 참고).

    Q. 쿼리 100개면 클래스 100개까지 검출 가능하다는 뜻인가? 아님. 쿼리 개수는 한 이미지에서 검출할 수 있는 물체 개수 상한임. 클래스 개수는 head의 출력 차원(C+1)이 정함. 클래스가 하나뿐이어도 물체가 3개면 쿼리 3개가 각각 맡음.

    Q. 패치 하나 안에 물체 두 개가 걸쳐 있으면? 인코더 출력 토큰 하나에 두 물체 정보가 섞여 있어도, 쿼리 두 개가 그 토큰을 각자 다른 방식으로 읽어 갈 수 있음 (§2.3). 단 patchify·downsampling에서 이미 잃은 위치 정보는 쿼리가 몇 개든 복구 못 함 — 그래서 작은 물체에 약하고, 후속 모델이 multi-scale·deformable attention을 넣음.

    Q. 왜 NMS가 필요 없나? 디코더 self-attention에서 쿼리들이 서로 무엇을 보고 있는지 알 수 있고, 매칭 loss가 중복 예측에 ∅를 배정해서 벌을 줌. 이 둘이 학습 중에 NMS 역할을 함. 디코더를 1층만 쓰면 중복이 늘어 NMS가 다시 필요해짐 (§5.3).

    Q. 학습이 왜 그렇게 오래 걸리나? 초기 cross-attention이 이미지 전체를 거의 균등하게 보기 때문에, 각 쿼리가 “어디를 볼지"를 익히는 데 오래 걸림. Deformable DETR·DAB-DETR은 쿼리에 위치 사전 정보를 넣어 이를 50 epoch 안쪽으로 줄임.

    🔷 10. 한 줄 요약

    검출을 “학습된 빈 자리 N개에 물체를 1:1로 앉히는 집합 예측” 으로 바꿔서 anchor·NMS 없이 Faster R-CNN을 따라잡음. object query와 이분 매칭이라는 도구는 이후 detection·segmentation 모델의 공통 기반이 됨.

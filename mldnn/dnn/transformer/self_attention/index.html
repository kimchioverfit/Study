    Self-Attention (Scaled Dot-Product Attention)

    결론부터 아주 쉽게: 각 토큰이 “나머지 토큰을 각각 얼마나 참고할지” 비율을 정하고, 그 비율대로 섞어서 자기 표현을 새로 만드는 연산임. Attention Is All You Need 의 심장이고, $Q/K/V$ 수식은 이 한 문장을 행렬로 옮긴 것일 뿐임.

    1. Attention이 뭔가 — 수식 없이

    예문 나는 사과를 먹었다 에서 먹었다 를 처리하는 상황임.

    먹었다 하나만 보면 “무엇을” 먹었는지 알 수 없음. 문장 안의 다른 토큰을 봐야 함. 그런데 전부 똑같이 볼 필요는 없음 — 참고할 정도가 다름.

    어떤 토큰을얼마나 참고할지
    나는0.2
    사과를0.6
    먹었다0.2

    이 비율이 정해지면 먹었다 의 새로운 표현은 그냥 가중합임.

    새로운 "먹었다" 표현
  = 0.2 × "나는"의 정보
  + 0.6 × "사과를"의 정보
  + 0.2 × "먹었다"의 정보

    Attention은 여기서 끝임. 남은 이야기는 전부 “그 비율을 어떻게 정하나” 하나뿐임.

    이 과정을 모든 토큰이 동시에, 서로에 대해 수행함. 그래서 Self-Attention임. 문장 안에서 자기들끼리 참고하는 구조라 RNN처럼 앞에서부터 차례로 갈 필요가 없고, 그래서 병렬화가 됨.

    2. 비율은 어떻게 정하나 — 왜 Q와 K가 따로 필요한가

    가장 자연스러운 의문은 이것임.

    임베딩 벡터끼리 그냥 내적하면 되는 것 아님?

    안 되는 이유가 세 가지 있음.

    ① 자기 자신이 항상 1등이 됨 $x_i \cdot x_i = \lVert x_i \rVert^2$ 이라서, 자기 자신과의 점수가 거의 항상 제일 큼. 그러면 다른 토큰을 참고하라고 만든 장치가 자기 자신만 보게 됨.

    ② 관계가 비대칭인데 내적은 대칭임 먹었다 는 사과를 을 강하게 참고해야 하지만, 사과를 이 먹었다 를 똑같은 세기로 참고해야 할 이유는 없음. 그런데 $x_i \cdot x_j = x_j \cdot x_i$ 라서 벡터 하나로는 대칭 점수밖에 못 만듦.

    ③ “무엇을 찾는가"와 “무엇을 가졌는가"가 다름 먹었다 가 찾는 것은 목적어고, 사과를 이 내세우는 것은 나는 명사·목적어임 이라는 성질임. 둘은 다른 정보인데 임베딩 하나에 뭉쳐 있음.

    그래서 같은 입력에서 역할이 다른 세 벡터를 따로 만들어 냄. 검색 엔진에 비유하면 이해가 빠름.

    이름역할비유
    Query이 토큰이 무엇을 찾고 있는지검색창에 친 검색어
    Key이 토큰이 무엇으로 불릴 수 있는지문서에 붙은 색인·태그
    Value이 토큰이 실제로 건네줄 내용검색 결과로 받아오는 본문

    점수는 Q와 K를 비교해서 만들고, 실제로 섞는 것은 V임. Q·K로 점수를 내면 ②의 비대칭 문제가 풀림 — $q_i \cdot k_j \ne q_j \cdot k_i$ 이기 때문임.

    $Q/K/V$ 는 토큰을 3등분하는 것이 아님. 같은 $X$ 에 서로 다른 가중치를 곱해 만든 세 개의 다른 표현임.

    3. Q / K / V 만들기

    입력 $X$ 는 토큰 $T$ 개, 각 토큰이 $d_{model}$ 차원인 행렬임 (임베딩 + Positional Encoding을 거친 결과).

    $$ Q = XW_Q, \qquad K = XW_K, \qquad V = XW_V $$
    기호shape설명
    $X$$(T, d_{model})$입력 토큰 표현
    $W_Q, W_K, W_V$$(d_{model}, d_k)$학습되는 가중치. 사람이 정하지 않음
    $Q, K, V$$(T, d_k)$세 가지 역할별 표현
    $QK^\top$$(T, T)$토큰 쌍마다의 점수

    $W$ 세 개가 학습 대상이라는 점이 중요함. “무엇을 질문으로 삼고 무엇을 색인으로 삼을지"를 사람이 정해주는 게 아니라, 모델이 데이터를 보고 알아서 잡음.

    4. 숫자로 따라가기

    $d_k = 2$ 로 두고 아주 작게 만들어 봄. 토큰 순서는 나는, 사과를, 먹었다 임.

    Q =            K =            V =
[1  0]  나는    [1  0]  나는    [1  0]  나는
[0  1]  사과를  [1  1]  사과를  [0  2]  사과를
[1  1]  먹었다  [0  1]  먹었다  [1  1]  먹었다

    ① 점수 계산 — $QK^\top$ 의 $(i, j)$ 칸은 “토큰 $i$ 가 토큰 $j$ 를 보는 점수"임.

    나는사과를먹었다
    나는110
    사과를011
    먹었다121

    먹었다 행을 보면 사과를 에 2점으로 제일 높은 점수를 줬음.

    ② Softmax — 점수를 합이 1인 비율로 바꿈.

    먹었다의 점수  [1, 2, 1]
      ↓ softmax
              [0.212, 0.576, 0.212]

    ③ V에 가중합 — 그 비율로 Value를 섞음.

    $$ 0.212 \times [1, 0] + 0.576 \times [0, 2] + 0.212 \times [1, 1] = [0.424,\ 1.364] $$

    이게 먹었다 의 새로운 표현임. 원래 $V$ 행이었던 $[1, 1]$ 에서 사과를 쪽($[0,2]$)으로 끌려간 것이 보임 — 문맥이 반영됐다는 뜻임.

    위 예제는 $\sqrt{d_k}$ 를 생략했음. 실제로는 여기에 §5의 스케일링이 들어감.

    여기서 나온 0.212 / 0.576 / 0.212 가 attention weight 임. 학습되는 가중치가 아니라 입력마다 새로 계산되는 비율이고, 임베딩과 어떻게 다른지는 Embedding Layer 에 표로 정리해 둠.

    5. 왜 $\sqrt{d_k}$ 로 나누나

    논문의 수식은 그냥 $QK^\top$ 이 아니라 $\frac{QK^\top}{\sqrt{d_k}}$ 임. 이유는 softmax가 포화되는 것을 막기 위함임.

    $q$ 와 $k$ 의 각 성분이 평균 0, 분산 1로 독립이라고 하면, 내적은 그런 곱 $d_k$ 개의 합이므로

    $$ \mathrm{Var}(q \cdot k) = d_k \quad \Longrightarrow \quad \text{표준편차} = \sqrt{d_k} $$

    논문 설정인 $d_k = 64$ 면 표준편차가 8이 됨. 점수가 $\pm 8$ 범위로 흩어진다는 뜻임. softmax는 입력 차이가 이만큼 벌어지면 거의 one-hot이 되어 버림 — 한 토큰만 1이고 나머지는 0. 그러면

    • 여러 토큰을 섞는다는 의도가 사라지고
    • 포화 구간이라 기울기가 거의 0이 되어 학습이 안 됨

    $\sqrt{d_k}$ 로 나누면 분산이 다시 1로 돌아와서 점수가 적당한 범위에 머무름.

    §4의 예제로 차이를 보면 ($d_k=2$ 라 효과가 작지만 방향은 같음):

    나는사과를먹었다
    스케일링 없음0.2120.5760.212
    $\div \sqrt{2}$ 적용0.2480.5030.248

    나눠주면 분포가 덜 뾰족해짐. $d_k$ 가 64, 128로 커질수록 이 차이가 결정적으로 벌어짐.

    6. 전체 수식

    지금까지를 한 줄로 합치면 논문의 식이 됨.

    $$ \text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V $$
    X ─┬─ ×W_Q ─▶ Q ─┐
   ├─ ×W_K ─▶ K ─┴─▶ QKᵀ ─▶ ÷√d_k ─▶ softmax ─┐
   └─ ×W_V ─▶ V ───────────────────────────────┴─▶ ×V ─▶ 출력
   (§3)          (§4-①)   (§5)      (§4-②)         (§4-③)

    디코더 에서는 여기에 mask $M$ 이 하나 더 붙어 미래 토큰을 가림.

    7. Multi-Head Attention

    위 연산을 한 번만 하면 토큰 쌍마다 관계를 하나씩밖에 못 잡음. 그래서 $W_Q, W_K, W_V$ 세트를 $h$ 개 두고 병렬로 돌린 뒤 이어 붙임.

    $$ \text{head}_i = \text{Attention}(XW_Q^i,\ XW_K^i,\ XW_V^i), \qquad \text{MultiHead} = \text{Concat}(\text{head}_1, \dots, \text{head}_h)\,W_O $$
         ┌─ head 1 ─┐
X ───┼─ head 2 ─┼── Concat ── ×W_O ──▶ 출력
     ├─  ...    ┤
     └─ head h ─┘

    논문은 $h = 8$, $d_k = d_v = d_{model}/h = 64$ 로 잡음. head마다 차원을 $1/h$ 로 줄이기 때문에 연산량은 single-head와 비슷함 — 공짜로 여러 관점을 얻는 구조임.

    흔한 오해: “head 1은 문법, head 2는 의미를 담당한다"처럼 역할이 깔끔히 나뉘지는 않음. 사람이 역할을 지정하지 않고, 학습 과정에서 각 head가 서로 다른 projection을 잡을 뿐임. 실제로 해석해 보면 역할이 겹치거나 아예 기여가 없는 head도 있음.

    8. 코드

    import torch
import torch.nn as nn
import torch.nn.functional as F


class MultiHeadSelfAttention(nn.Module):
    def __init__(self, d_model=512, num_heads=8):
        super().__init__()
        assert d_model % num_heads == 0
        self.h = num_heads
        self.d_k = d_model // num_heads        # 512 / 8 = 64
        self.qkv = nn.Linear(d_model, d_model * 3)   # W_Q, W_K, W_V를 한 번에
        self.proj = nn.Linear(d_model, d_model)      # W_O

    def forward(self, x, mask=None):           # x: (B, T, d_model)
        B, T, D = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)               # 각 (B, T, D)
        # (B, T, D) -> (B, h, T, d_k) : head를 배치 축으로 올려 병렬 처리
        q, k, v = (t.view(B, T, self.h, self.d_k).transpose(1, 2) for t in (q, k, v))

        scores = (q @ k.transpose(-2, -1)) / self.d_k ** 0.5  # (B, h, T, T)
        if mask is not None:
            scores = scores.masked_fill(mask == 0, float('-inf'))
        out = F.softmax(scores, dim=-1) @ v                   # (B, h, T, d_k)

        out = out.transpose(1, 2).reshape(B, T, D)            # Concat
        return self.proj(out)                                 # (B, T, d_model)

    실제 학습 코드에서는 위 식을 직접 쓰기보다 F.scaled_dot_product_attention 을 씀. 수식은 같지만 FlashAttention 계열 커널로 내려가서 메모리를 훨씬 적게 씀.

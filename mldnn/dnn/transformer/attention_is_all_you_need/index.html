    Attention Is All You Need

    Attention is all you need (Transformer)

    📄 논문: Attention Is All You Need — Vaswani et al., NeurIPS 2017

    트랜스포머 구조가 처음 등장한 논문

    목표

    RNN이나 CNN 없이, 오직 어텐션 메커니즘만으로 시퀀스-투-시퀀스(seq2seq) 문제를 푸는 것. 번역(translation), 요약(summarization), 질의응답 등 다양한 NLP 작업에 적용 가능함.

    기존 접근법의 문제점

    방식문제점
    RNN / LSTM순차 처리라 병렬화가 안 됨. 멀리 떨어진 토큰끼리 정보를 주고받으려면 중간 단계를 전부 거쳐야 해서 긴 문장을 기억하기 어려움 (vanishing gradient)
    CNN병렬화는 되지만 커널 크기만큼씩만 봄. 먼 토큰을 연결하려면 층을 깊게 쌓아야 함

    논문이 이 문제를 정량화한 것이 maximum path length 임 — 두 토큰의 정보가 서로 만나기까지 거쳐야 하는 연산 단계 수.

    레이어 종류레이어당 복잡도순차 연산maximum path length
    Self-Attention$O(n^2 \cdot d)$$O(1)$$O(1)$
    Recurrent$O(n \cdot d^2)$$O(n)$$O(n)$
    Convolutional$O(k \cdot n \cdot d^2)$$O(1)$$O(\log_k n)$

    ($n$ = 시퀀스 길이, $d$ = 표현 차원, $k$ = 커널 크기)

    Self-Attention은 어떤 두 토큰이든 한 단계로 연결됨($O(1)$). 이게 “긴 문맥을 잘 잡는다"의 실제 근거임. 대신 $n^2$ 이라 시퀀스가 길어지면 비용이 제곱으로 늘어남 — 이후의 efficient attention 연구가 전부 여기서 출발함.

    핵심 아이디어: 트랜스포머 (Transformer)

    🔥 “시퀀스 모델링은 오직 Attention만으로도 충분함!”

    Self-Attention으로 입력의 모든 토큰 쌍 관계를 한 번에 계산함. 순차 의존이 없으므로 한 레이어 안의 모든 토큰을 동시에 처리할 수 있음 — 학습이 빠르고 문맥 파악이 뛰어남.

    “병렬"은 학습 때, 한 레이어 내부 이야기임. 추론 때 디코더는 토큰을 하나씩 만들어야 해서 여전히 순차적임 (§10.1).

    트랜스포머 구조

    [입력 임베딩 + 위치 임베딩] → 인코더 × N → 디코더 × N → 출력

    • 인코더(Encoder): 입력의 각 토큰을 주변 토큰 정보가 반영된 contextual representation으로 변환함
    • 디코더(Decoder): 인코더 출력을 참조하면서 출력 토큰을 하나씩 생성함

    인코더 출력은 문장 전체를 뭉친 벡터 하나가 아님. 입력 토큰 수만큼의 벡터열 $z_1, \dots, z_n$ 임. RNN seq2seq의 단일 context vector와 혼동하기 쉬운 지점임 — “압축"보다 “토큰별 재표현"에 가까움.

    핵심 수식 하나만 꼽으면 이것임.

    $$ \text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V $$

    이 식이 왜 이렇게 생겼는지는 Self-Attention 문서 에서 직관 → Q/K/V → 숫자 예제 순서로 따로 풀어 씀.

    전체 구조 상세

    1. 개요

    여기부터는 입력 문장이 실제로 어떤 순서로 처리되는지를 단계별로 따라감. 입력 문장 → 토큰화 → 임베딩 → Q/K/V 생성 → Self-Attention → Multi-head → Encoder/Decoder 구조 순서임.

    2. 입력 처리: Tokenizer → Token ID → Token 문서

    2.1 문장 입력

    예시:

    나는 학교에 간다

    2.2 토큰화(Tokenization)

    subword 토크나이저(BPE / WordPiece / SentencePiece)로 문장을 토큰 단위로 분할함. 토큰이 무엇인지, 왜 단어 단위로 자르지 않는지, tokenizer가 회사마다 다른 이유는 Token 문서에 정리함.

    ["나", "##는", "학교", "##에", "간", "##다"]

    ## 은 WordPiece(BERT) 표기로 “앞 토큰에 이어붙는 조각"이라는 뜻임. SentencePiece는 대신 ▁(공백 표시)를 써서 ["▁나", "는", "▁학교", "에", "▁간", "다"] 처럼 나옴. 원 Transformer 논문은 BPE 계열을 썼음. 표기법이 도구마다 다르니 섞어 쓰지 않도록 주의.

    2.3 토큰 → 정수 ID 매핑 (Vocabulary)

    토크나이저는 사전(vocabulary)을 보유하며 각 토큰을 정수 ID로 변환함.

    TokenID
    나102
    ##는450
    학교630
    ##에231
    간901
    ##다250

    ID는 의미가 없음.
    의미는 임베딩 레이어가 학습함.

    3. 임베딩: Token ID → N차원 벡터

    3.1 임베딩 레이어의 정체

    임베딩 레이어는 크기가 다음과 같은 거대한 행렬:

    [vocab_size × embedding_dim] = W

    예:

    (50,000 × 512)

    3.2 변환 방식

    토큰 ID = 임베딩 테이블의 row index.

    예:
    토큰 “나”(ID=102) → W[102] (512차원 벡터)

    즉:

    Token ID → Lookup → d_model 차원의 벡터

    3.3 사람이 만드는가?

    • Vocabulary 내용 자체는 코퍼스에서 학습됨 — BPE/WordPiece가 말뭉치의 빈도를 보고 어떤 조각을 토큰으로 쓸지 자동으로 정함
    • 사람이 정하는 것은 토크나이저 알고리즘과 vocab size(예: 32,000개) 같은 설정값임
    • 임베딩 행렬 W의 값은 학습으로 자동 생성

    4. Positional Encoding → 상세 문서

    attention은 내적만 하므로 토큰 순서를 전혀 모름. 입력을 뒤섞어도 결과가 같음. 그래서 위치를 벡터로 만들어 임베딩에 더해 줌.

    입력 = Embedding + PositionalEncoding
    $$ PE_{(pos,\ 2i)} = \sin\!\left(\frac{pos}{10000^{2i/d_{model}}}\right) \qquad PE_{(pos,\ 2i+1)} = \cos\!\left(\frac{pos}{10000^{2i/d_{model}}}\right) $$

    차원마다 주기를 다르게 준 sin/cos을 겹쳐 씀. 덕분에

    • 값이 항상 $[-1, 1]$ 이라 임베딩을 덮지 않음
    • 학습 때 본 적 없는 긴 위치도 그냥 계산됨
    • 두 위치 벡터의 내적이 상대 거리에만 의존함
    • $k$ 칸 이동이 선형 변환(회전) 으로 표현됨

    왜 하필 sin/cos인지, 단순한 대안들이 왜 실패하는지는 Positional Encoding 문서 에서 다룸.

    5. Self-Attention: Q, K, V 생성 → Self-Attention 문서

    입력 $X$ $(T \times d_{model})$ 에서 역할이 다른 세 표현을 만들어 냄.

    Q = X W_Q        "무엇을 찾는가"
K = X W_K        "무엇으로 불릴 수 있는가"
V = X W_V        "실제로 건네줄 내용"
    기호shape비고
    $X$$(T, d_{model})$임베딩 + Positional Encoding 결과
    $W_Q, W_K, W_V$$(d_{model}, d_k)$학습되는 가중치
    $Q, K, V$$(T, d_k)$역할별 표현

    $Q/K/V$ 는 토큰을 3등분한 것이 아니라, 같은 $X$ 에 다른 가중치를 곱해 만든 세 개의 다른 표현임.

    왜 하나가 아니라 셋이어야 하는지는 Self-Attention §2 에서 다룸.

    6. Self-Attention 계산 과정 → Self-Attention 문서

    $$ \text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V $$
    단계연산shape의미
    ① 점수$QK^\top$$(T, T)$토큰 $i$ 가 토큰 $j$ 를 보는 점수
    ② 스케일링$\div \sqrt{d_k}$$(T, T)$softmax 포화 방지
    ③ 비율화softmax (행 방향)$(T, T)$합이 1인 “참고 비율”
    ④ 가중합$\times V$$(T, d_k)$그 비율로 Value를 섞음

    즉 토큰 간 “누가 누구를 얼마나 참고할지” 정하고, 그대로 섞는 연산임.

    $\sqrt{d_k}$ 로 나누는 이유($d_k=64$ 면 점수 표준편차가 8까지 벌어져 softmax가 one-hot으로 포화됨)와 실제 숫자를 넣어 따라가는 예제는 Self-Attention §4~5 에 있음.

    7. Multi-Head Attention → Self-Attention 문서

    $W_Q, W_K, W_V$ 세트를 $h$ 개 두고 병렬로 돌린 뒤 이어 붙임.

    head_i = Attention(X W_Q^i, X W_K^i, X W_V^i)
MultiHead = Concat(head_1, ..., head_h) W_O
    • head마다 차원을 $d_{model}/h$ 로 줄이므로 연산량은 single-head와 거의 같음
    • 서로 다른 표현 공간에서 여러 관계를 동시에 잡을 수 있음
    • head별 역할을 사람이 지정하지는 않음. 학습으로 각자 다른 projection을 잡을 뿐임

    8. Position-wise Feed-Forward Network (FFN) → FFN 문서

    각 토큰의 벡터에 대해 독립적으로 적용되는 2-layer MLP. 자세한 내용은 FFN 참고.

    FFN(x) = max(0, xW1 + b1) W2 + b2

    9. Encoder 구조 (N회 반복)

    한 블록:

    (1) Multi-Head Self-Attention
(2) Add & LayerNorm
(3) Feed-Forward Network
(4) Add & LayerNorm

    전체 인코더:

    Input → (EncoderBlock × N) → Output

    Add & LayerNorm의 순서 주의 — 원 논문은 Post-LN 임.

    $$\text{LayerNorm}\left(x + \text{Sublayer}(x)\right)$$

    residual을 더한 뒤에 정규화함. 반면 ViT·GPT-2 이후 대부분의 구현은 Pre-LN ($x + \text{Sublayer}(\text{LayerNorm}(x))$)을 씀 — 깊게 쌓을 때 학습이 훨씬 안정적이기 때문임. Post-LN은 learning rate warm-up 없이는 발산하기 쉬움. 비교는 ViT 참고.

    10. Decoder 구조 (N회 반복)

    Decoder는 “Encoder 결과를 받아서 출력하는 층"이 아니라, 지금까지 생성한 출력 토큰을 보고 다음 토큰을 하나씩 예측하는 autoregressive 생성기임. 그래서 Encoder 블록에는 없는 두 가지가 있음 — Masked Self-Attention과 Cross-Attention.

    한 블록:

    (1) Masked Multi-Head Self-Attention   ← 지금까지 생성한 출력 토큰끼리
(2) Add & LayerNorm
(3) Encoder-Decoder (Cross) Attention  ← Q = 디코더 상태, K·V = 인코더 출력
(4) Add & LayerNorm
(5) Feed-Forward Network
(6) Add & LayerNorm

    전체 디코더:

    TargetInput → (DecoderBlock × N) → Output

    디코더 블록 하나를 그림으로 보면 — 어디서 Q, K, V가 오는지가 핵심임:

    • ②만 Q와 K·V의 출처가 다름 — 디코더가 인코더 출력에 “질문"하는 자리 (§10.3)
    • ③ FFN은 인코더와 동일 (FFN 문서 )

    10.1 Decoder는 무엇을 입력받나 — 한 토큰씩 생성

    번역 I love machine learning → 나는 머신 러닝을 좋아한다를 예로 들면, 디코더는 두 종류의 정보를 받음.

    ① 지금까지 생성한 출력 토큰      ② 인코더가 만든 입력 문장의 representation
    step 1:  <BOS>                  → "나는"
step 2:  <BOS> 나는              → "머신"
step 3:  <BOS> 나는 머신         → "러닝을"
step 4:  <BOS> 나는 머신 러닝을   → "좋아한다"
    $$ P(y_t \mid y_1, \dots, y_{t-1}, X) $$

    다음 토큰 $y_t$는 입력 문장 $X$ 와 이미 생성한 출력 $y_{ 둘을 보고 결정됨. 학습 때는 정답 문장 전체를 한 번에 넣고(teacher forcing) 병렬로 계산하지만, 추론 때는 정말 한 토큰씩 생성함.

    추론 때의 반복 구조:

    flowchart TB
    X["입력 문장<br/>I love machine learning"] --> ENC["Encoder<br/>(한 번만 실행)"]
    ENC --> H["인코더 출력 H"]

    S["&lt;BOS&gt; + 지금까지 생성한 토큰"] --> DEC["Decoder ×N"]
    H -. "K, V (매 step 재사용)" .-> DEC
    DEC --> P["Softmax → 다음 토큰 y_t"]
    P -- "y_t를 뒤에 붙여서 다시 입력" --> S
    P -- "&lt;EOS&gt;가 나오면" --> END["종료<br/>나는 머신 러닝을 좋아한다"]

    인코더는 한 번만 돌고, 디코더는 토큰 하나 만들 때마다 다시 실행됨. 그래서 생성 길이가 길수록 디코더 쪽 비용이 선형으로 늘고, 이 반복을 줄이려고 KV cache 같은 기법을 씀.

    10.2 Masked Self-Attention — 미래를 못 보게 함

    학습 때 정답 문장 전체를 넣으므로, 머신을 예측하는 자리에서 뒤에 오는 러닝을, 좋아한다를 미리 보면 안 됨. 그래서 attention score 행렬에 mask를 씌움.

                    (보는 쪽)
              나는  머신  러닝을  좋아한다
나는           O     X     X       X
머신           O     O     X       X
러닝을         O     O     O       X
좋아한다       O     O     O       O

    X 자리에 $-\infty$를 더하면 softmax 이후 확률이 0이 됨 (causal mask, look-ahead mask).

    $$ \text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}} + M\right)V, \qquad M_{ij} = \begin{cases} 0 & j \le i \\ -\infty & j > i \end{cases} $$

    10.3 Cross-Attention — 원문을 참조함 → 상세 문서

    디코더가 나는 머신까지 만들었다면, 다음 단어를 정하려면 원문도 봐야 함. 이때 Q, K, V의 출처가 갈라짐.

    $$ Q = \text{디코더 상태 (지금까지 생성한 것)}, \qquad K, V = \text{인코더 출력 (입력 문장)} $$
    디코더 상태 "나는 머신"
        │ Query
        ↓
   Cross-Attention   ←  Key / Value: 인코더 출력 "I love machine learning"
        ↓
   "원문의 어디를 봐야 다음 단어가 정해지지?"

    예를 들어 attention이 I 0.05 / love 0.10 / machine 0.20 / learning 0.65처럼 learning에 몰리면 다음 토큰 러닝을이 나옴. Self-Attention은 Q·K·V가 전부 같은 시퀀스에서 나오지만, Cross-Attention은 Q만 디코더, K·V는 인코더라는 점이 유일한 차이임.

    그래서 $QK^\top$ 이 정사각형이 아니라 $(T_{dec}, T_{enc})$ 직사각형이 되고, causal mask도 쓰지 않음. Self-Attention과의 비교표 와 수치 예제는 Cross-Attention 문서 참고.

    Encoder 블록Decoder 블록

    Self-Attention mask없음 (전부 봄)causal (과거만 봄)

    역할입력을 이해해 context 표현 생성context를 참조하며 출력 토큰 생성

    ⚠️ “디코더"라는 이름은 모델마다 뜻이 다름. 위는 NLP Transformer의 autoregressive 디코더이고, DETR 의 디코더는 mask 없이 N개를 병렬로 뽑는 물체 추출기, U-Net의 디코더는 해상도 복원기임. Decoder 개념 문서 의 “세 가지 디코더” 참고. ViT 는 분류만 하므로 디코더 자체가 없음.

    11. 출력 단계 (Decoder → Softmax)

    디코더의 출력에 선형 변환 + Softmax 적용하여 다음 토큰 확률 예측.

    P(token | previousTokens) = softmax(W_out · h)

    12. 전체 프로세스 요약 (한 줄)

    문장 → 토큰화 → Token ID → 임베딩 → Q/K/V → Self-Attention → Multi-head → FFN → (반복) → Decoder → Softmax → 다음 단어 예측

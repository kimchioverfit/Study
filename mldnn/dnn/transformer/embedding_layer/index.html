    Embedding Layer

    임베딩 레이어란?

    Token 을 n Dimension으로 변환하는 과정.

    왜 필요할까?

    컴퓨터는 문자열을 직접 이해하지 못하므로, 거리나 유사도 개념이 없어서 학습이 불가능함.

    이런 상황에서, 각 Token에 대한 ID를 이용하여 key-value 구조로 Vector값을 갖게 하는 것.

    이걸 해줘야 Model 이 Token을 이해 가능.

    "페페" 라는 Token ID : 1234
Value[1234] = [0.23, 0.17, ...] (weight들)

    이런 식의 변환이라고 보면 됨.

    임베딩 차원이 높을 수록 더욱 다양한 정보를 저장 가능함. 그 차원을 누가 어떻게 정하는지, 키우면 무엇을 내주는지는 Dimension 참고.

    임베딩 vs Attention weight — 같은 “weight"가 아님

    위에서 임베딩 값을 (weight들) 이라고 적었는데, 이것 때문에 Attention weight와 같은 것으로 착각하기 쉬움. 둘은 종류가 아예 다름.

    영어 weight가 “학습되는 가중치” 와 “섞는 비중” 두 가지 뜻으로 쓰여서 생긴 혼동임.

    임베딩Attention weight
    정체학습되는 파라미터입력마다 계산되는 값
    언제 정해지나학습이 끝나면 고정forward 할 때마다 새로
    입력에 따라안 변함 — ID가 같으면 항상 같은 벡터다 변함 — 문장이 바뀌면 전부 다시 계산
    크기$(\text{vocab\_size} \times d)$ 하나$(T \times T)$, 레이어·헤드마다 따로
    제약없음. 아무 실수나 가능행마다 합이 1, 전부 0~1 (softmax 결과라서)
    체크포인트저장됨저장 안 됨
    학습역전파로 직접 갱신됨직접 갱신되지 않음. $W_Q, W_K$ 가 갱신되면서 결과적으로 달라짐

    한 줄로 줄이면 — 임베딩은 모델이 가지고 있는 것, attention weight는 모델이 그때그때 만들어 내는 것임.

    역할로 보면: 재료 vs 배합비

    임베딩            "나", "사과를", "먹었다" 각각의 벡터      ← 섞일 재료
attention weight  0.212 / 0.576 / 0.212                    ← 얼마씩 섞을지
                            ↓
결과              [0.424, 1.364]                           ← 섞고 난 새 벡터

    attention weight는 벡터가 아니라 비율임. 저 숫자 자체에는 단어의 뜻이 담겨 있지 않고, “어느 재료를 얼마나 쓸지"만 들어 있음.

    위 숫자는 Self-Attention §4 의 예제 그대로임. 먹었다 가 사과를 을 57.6% 참고한다는 뜻이고, 같은 단어라도 문장이 바뀌면 이 비율은 완전히 달라짐. 반면 사과를 의 임베딩 벡터는 어느 문장에 있든 똑같음.

    “임베딩"이라는 말이 두 군데 쓰임

    혼동의 나머지 절반은 이것임. 같은 이름이 두 가지를 가리킴.

    부르는 말무엇문맥에 따라
    입력 임베딩 (이 문서)임베딩 행렬에서 꺼낸 벡터안 변함
    문맥 임베딩 (contextual embedding)attention 블록을 통과한 뒤의 벡터변함

    bank 를 예로 들면, 입력 임베딩은 “강둑"이든 “은행"이든 하나뿐임. 그 둘을 갈라 주는 것이 attention이고, 갈라진 결과가 문맥 임베딩임.

    그래서 순서는 이렇게 됨.

    입력 임베딩  ──(attention weight로 섞음)──▶  문맥 임베딩
 (파라미터)        (계산된 비율)                (계산된 벡터)

    attention weight는 이 화살표 위에 있는 연산이지, 화살표 양쪽의 벡터가 아님.

    구분이 실제로 문제가 되는 곳

    • 파라미터 수를 셀 때 — attention weight는 포함되지 않음. $(T \times T)$ 는 입력 길이에 따라 생겼다가 사라지는 값이라 모델 크기와 무관함. 모델 크기에 들어가는 것은 $W_Q, W_K, W_V$ 쪽임 (Dimension §3 )
    • attention map 시각화 — “모델이 무엇을 배웠나"가 아니라 “이 입력에서 무엇을 봤나” 를 그린 것임. 입력이 바뀌면 그림도 바뀜
    • 메모리 — 임베딩은 고정 비용이지만 attention weight는 $T^2$ 이라 긴 입력에서 폭증함. 긴 문맥이 비싼 이유가 여기 있음
    • “attention weight를 저장해 두고 재사용"은 성립하지 않음 — 입력이 달라지면 무의미한 값이 됨. 반면 KV cache가 재사용하는 것은 weight가 아니라 K·V 벡터임

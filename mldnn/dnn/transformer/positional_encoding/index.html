    Positional Encoding

    Positional Encoding — 왜 하필 sin / cos 인가

    결론부터 아주 쉽게: attention은 순서를 모름. 그래서 위치 정보를 벡터로 만들어 더해 줘야 함. 그런데 그냥 0, 1, 2, 3… 을 쓰면 값이 무한히 커지고, 길이를 정해 학습시키면 그보다 긴 문장에 못 씀. 여러 주기의 sin/cos을 겹쳐 쓰면 값은 항상 $[-1, 1]$ 이면서, 위치마다 다르고, 상대 거리까지 표현됨.

    1. 왜 위치 정보가 필요한가

    Self-Attention 의 계산을 다시 보면, 각 토큰은 다른 토큰들과 내적을 해서 참고 비율을 정함.

    이 연산에는 순서가 들어갈 자리가 없음. 입력 토큰을 뒤섞어도 (permutation) 각 토큰이 받는 결과는 그대로임.

    "나는 사과를 먹었다"   →  attention  →  결과 A
"먹었다 나는 사과를"   →  attention  →  결과 A  (순서만 따라 이동할 뿐 값은 동일)

    RNN은 앞에서부터 차례로 읽으니 순서가 구조에 내장돼 있었지만, Transformer는 전부 동시에 보기 때문에 순서를 따로 알려줘야 함. 그래서 입력에 위치 벡터를 더함.

    $$ \text{입력} = \text{Embedding} + \text{PositionalEncoding} $$

    곱하지 않고 더함. 같은 $d_{model}$ 차원이라 그냥 더해지고, 이후 $W_Q, W_K$ 가 “의미 성분"과 “위치 성분"을 알아서 분리해 쓰도록 학습됨.

    2. 단순한 방법들이 왜 실패하나

    방법문제
    위치를 그대로 0, 1, 2, …문장이 길면 값이 무한정 커짐. 임베딩 값($\approx[-1,1]$)을 덮어버려 의미가 사라짐
    pos / T 로 정규화범위는 잡히지만 같은 위치가 문장 길이마다 다른 값이 됨. 10토큰의 3번째와 100토큰의 3번째가 달라짐
    위치마다 학습되는 벡터잘 동작하지만, 학습 때 본 최대 길이까지만 가능. 더 긴 입력엔 값이 없음
    이진수 비트 패턴아이디어는 맞음 (자리마다 주기가 다름). 다만 값이 이산적이라 미분이 안 됨

    마지막 줄이 힌트임. 이진수를 보면 자리마다 뒤집히는 주기가 다름.

    0 → 000
1 → 001     맨 오른쪽 자리: 1마다 반전  (주기 2)
2 → 010     가운데 자리   : 2마다 반전  (주기 4)
3 → 011     맨 왼쪽 자리  : 4마다 반전  (주기 8)
4 → 100

    이걸 연속 함수로 바꾼 것이 sin/cos임. 차원마다 다른 주기를 주면, 그 조합으로 위치를 식별할 수 있음.

    3. 논문의 정의

    $$ PE_{(pos,\ 2i)} = \sin\!\left(\frac{pos}{10000^{2i/d_{model}}}\right) \qquad PE_{(pos,\ 2i+1)} = \cos\!\left(\frac{pos}{10000^{2i/d_{model}}}\right) $$
    • $pos$ : 토큰의 위치 (0, 1, 2, …)
    • $i$ : 차원 인덱스. 짝수 차원엔 sin, 홀수 차원엔 cos을 넣고 쌍으로 묶음
    • $10000^{2i/d}$ : 차원이 뒤로 갈수록 주기가 길어지게 만드는 값

    파장으로 보면 $2\pi$ 부터 $2\pi \cdot 10000$ 까지 기하급수적으로 늘어남.

    차원 0,1    ▁▂▃▅▆▇█▇▆▅▃▂▁▂▃▅▆▇█▇▆▅▃▂▁   빠르게 진동 (짧은 주기)
차원 2,3    ▁▁▂▃▄▅▆▇█▇▆▅▄▃▂▁▁▂▃▄▅▆▇█
차원 4,5    ▁▁▁▂▂▃▄▅▆▇███▇▆▅▄▃▂▂▁▁▁▁
  …
차원 d-2,d-1 ▁▁▁▁▁▁▂▂▂▃▃▃▄▄▄▅▅▅▆▆▆▇▇▇   거의 변하지 않음 (긴 주기)

    앞쪽 차원은 바로 옆 토큰을 구분하고, 뒤쪽 차원은 문장의 앞/뒤 대역을 구분함. 시계의 초침·분침·시침과 같은 구조임.

    4. sin/cos이 주는 성질 네 가지

    $d_{model}=128$ 로 실제 계산해서 확인한 값임.

    4.1 값이 항상 $[-1, 1]$

    위치가 5000이든 50000이든 범위가 그대로임. 임베딩 값과 크기가 비슷해서 더해도 의미를 덮지 않음.

    덤으로, 모든 위치 벡터의 노름이 동일함 ($\sqrt{d/2}$, $d=128$ 이면 정확히 8.0). $\sin^2 + \cos^2 = 1$ 인 쌍이 $d/2$ 개 있기 때문임. 즉 “어느 위치냐"에 따라 더해지는 크기가 달라지지 않음.

    4.2 학습 때 안 본 길이에도 그대로 씀

    함수일 뿐이라 $pos = 5000$ 을 넣으면 그냥 계산됨. 학습을 512토큰으로 했어도 정의상 더 긴 입력에 값을 만들 수 있음 — 학습되는 위치 임베딩에는 없는 장점임.

    다만 “값이 나온다"와 “성능이 유지된다"는 다름. 실제로는 학습 길이를 크게 넘어가면 품질이 떨어지고, 그래서 이후 RoPE·ALiBi 같은 방식이 나옴.

    4.3 내적이 상대 거리에만 의존함

    이게 핵심임. 두 위치 벡터의 내적 $PE_{pos} \cdot PE_{pos+k}$ 는 $pos$ 와 무관하고 $k$ 에만 의존함.

    $d=128$, $k=5$ 로 계산하면:

    $pos$05102040
    $PE_{pos} \cdot PE_{pos+5}$47.18547.18547.18547.18547.185

    전부 같은 값임. 덧셈정리 때문임.

    $$ \sin a \sin b + \cos a \cos b = \cos(a - b) $$

    쌍으로 묶인 (sin, cos) 차원들의 내적을 더하면 $\sum_i \cos\big(k \cdot \omega_i\big)$ 가 되어 $pos$ 가 사라지고 $k$ 만 남음.

    attention은 Q와 K의 내적으로 점수를 내므로, 이 성질 덕에 모델이 “몇 번째인가"가 아니라 “몇 칸 떨어졌는가” 를 보고 학습할 수 있음.

    그리고 거리가 멀수록 내적이 작아짐 — 가까운 토큰이 자연스럽게 더 비슷하게 취급됨.

    $k$012481632
    내적64.062.157.448.645.739.735.7

    4.4 $k$ 칸 이동이 선형 변환으로 표현됨

    논문이 sin/cos을 고른 이유로 직접 든 성질임 — 어떤 고정된 offset $k$ 에 대해, $PE_{pos+k}$ 는 $PE_{pos}$ 의 선형 함수임.

    $$ PE_{pos+k} = PE_{pos} \cdot R_k $$

    2차원 쌍마다 보면 그냥 회전 행렬임.

    $$ \begin{bmatrix} \sin(\omega(pos+k)) \\ \cos(\omega(pos+k)) \end{bmatrix} = \begin{bmatrix} \cos \omega k & \sin \omega k \\ -\sin \omega k & \cos \omega k \end{bmatrix} \begin{bmatrix} \sin(\omega\, pos) \\ \cos(\omega\, pos) \end{bmatrix} $$

    $k=7$ 로 실제 $R$ 을 풀어 맞춰 보면 최대 오차가 $8.2 \times 10^{-6}$ — 수치 오차 수준으로 정확히 성립함.

    $W_Q, W_K$ 가 선형 변환이므로, 모델이 “$k$ 칸 뒤를 본다"는 규칙을 가중치 하나로 학습할 수 있다는 뜻임.

    이 “회전으로 위치를 표현한다"는 발상을 더 밀어붙인 것이 RoPE(Rotary Position Embedding)임. 위치 벡터를 더하는 대신 Q·K를 직접 회전시킴. LLaMA 계열이 전부 이걸 씀.

    5. 코드

    import math
import torch


def sinusoidal_pe(max_len, d_model):
    pe = torch.zeros(max_len, d_model)
    pos = torch.arange(max_len).unsqueeze(1).float()          # (max_len, 1)
    i = torch.arange(0, d_model, 2).float()                   # 짝수 차원 인덱스
    div = torch.exp(-math.log(10000.0) * i / d_model)         # 1 / 10000^(2i/d)

    pe[:, 0::2] = torch.sin(pos * div)                        # 짝수 차원 → sin
    pe[:, 1::2] = torch.cos(pos * div)                        # 홀수 차원 → cos
    return pe                                                 # (max_len, d_model)


pe = sinusoidal_pe(64, 128)
print(pe.shape)                       # torch.Size([64, 128])
print(pe.min().item(), pe.max().item())   # -1.0 1.0
print(pe.norm(dim=1)[0].item())           # 8.0  = sqrt(128/2), 모든 위치 동일

# 내적이 상대 거리에만 의존
print((pe[0] @ pe[5]).item(), (pe[20] @ pe[25]).item())   # 47.185 47.185

    div 를 exp(-log(10000) * i / d) 로 쓰는 이유는 $10000^{2i/d}$ 를 직접 계산하면 오버플로가 나기 때문임. 로그 공간에서 계산해 되돌리는 표준 트릭임.

    방식쓰는 곳특징
    고정 sin/cos원 Transformer, DETR학습 파라미터 없음, 길이 외삽 가능
    학습되는 위치 임베딩ViT , BERT, GPT-2단순하고 성능 좋음. 최대 길이 고정
    상대 위치 인코딩Swin, T5절대 위치 대신 거리 $i-j$ 를 attention score에 직접 더함
    RoPELLaMA, QwenQ·K를 회전시킴. §4.4의 성질을 극단화
    ALiBiBLOOM거리에 비례한 페널티를 score에 더함. 외삽에 강함

    ViT 가 학습되는 1D 위치 임베딩을 쓴다는 점이 눈에 띔 — 이미지는 2D인데도 1D로 충분했고, 논문이 2D 버전과 비교했지만 큰 차이가 없었음.

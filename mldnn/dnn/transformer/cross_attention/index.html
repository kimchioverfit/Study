    Cross-Attention

    Cross-Attention (Encoder-Decoder Attention)

    결론부터 아주 쉽게: 한 시퀀스가 다른 시퀀스를 참조하는 attention임. Self-Attention 이 “문장이 자기 자신을 보는 것"이라면, Cross-Attention은 “번역문이 원문을 보는 것"임. 연산은 완전히 똑같고, Q를 어디서 가져오고 K·V를 어디서 가져오는지만 다름.

    1. 무엇이 다른가 — 딱 한 줄

    $$ \text{Self: } Q, K, V \leftarrow \text{같은 시퀀스} \qquad\qquad \text{Cross: } Q \leftarrow \text{A}, \quad K, V \leftarrow \text{B} $$

    수식도, softmax도, $\sqrt{d_k}$ 도 전부 동일함.

    $$ \text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V $$

    바뀌는 것은 입력의 출처뿐임. 그래서 Self-Attention을 이해했다면 Cross-Attention은 새로 배울 연산이 없음.

    [Self-Attention]                    [Cross-Attention]

  문장                                 번역문(디코더)     원문(인코더)
   │                                      │                  │
   ├─ Q                                   └─ Q          K, V ─┘
   ├─ K                                          \      /
   └─ V                                           Attention
       \                                              │
        Attention                              "원문의 어디를 볼까?"

    2. 왜 필요한가

    번역 I love machine learning → 나는 머신 러닝을 좋아한다 를 생각해 봄.

    디코더가 나는 머신 까지 만들었을 때, 다음 단어를 정하려면 두 가지를 봐야 함.

    무엇을 보나담당
    지금까지 내가 만든 출력Masked Self-Attention
    원문에서 아직 안 옮긴 부분Cross-Attention

    Cross-Attention이 없으면 디코더는 원문을 전혀 못 봄. 그러면 번역기가 아니라 그냥 language model이 됨 — 그럴듯한 한국어 문장을 만들지만 입력과 아무 상관이 없어짐.

    실제로 GPT 같은 decoder-only 모델에는 Cross-Attention이 없음. 원문을 참조할 일이 없고, 조건은 프롬프트로 같은 시퀀스 안에 넣기 때문임.

    3. Self-Attention과의 비교

    Self-AttentionCross-Attention
    Q 출처자기 시퀀스디코더 (참조하는 쪽)
    K, V 출처자기 시퀀스인코더 (참조당하는 쪽)
    $QK^\top$ shape$(T, T)$ — 정사각형$(T_{dec}, T_{enc})$ — 직사각형
    causal mask디코더에서는 씀 (미래 가림)안 씀 (원문은 다 봐도 됨)
    K·V 재계산매 스텝 새로한 번만 계산해 계속 재사용
    질문 형태“이 문장 안에서 서로 어떤 관계지?”“원문의 어디를 봐야 다음 단어가 나오지?”
    없으면문맥을 못 잡음입력과 무관한 문장을 생성함
    쓰이는 곳인코더, 디코더 ①번디코더 ②번, DETR , EoMT

    핵심은 위에서 굵게 표시한 세 줄임. 나머지는 전부 같음.

    3.1 score 행렬이 정사각형이 아님

    Self-Attention에서 $QK^\top$ 은 항상 $(T, T)$ 정사각 행렬이었음. 같은 시퀀스끼리 비교하니 당연함.

    Cross-Attention은 길이가 다른 두 시퀀스를 비교하므로 직사각형이 됨.

    원문 4토큰, 생성한 번역 3토큰인 경우

          I  love machine learning     ← T_enc = 4 (K, V)
 <BOS>  [                        ]
 나는    [        QKᵀ  (3 × 4)    ]    ← T_dec = 3 (Q)
 머신    [                        ]

    행은 “지금 만들고 있는 토큰”, 열은 “원문의 각 토큰"임. 행 방향으로 softmax를 하므로, 각 디코더 토큰마다 원문 전체에 대한 참고 비율이 나옴.

    3.2 K·V는 한 번만 계산함

    인코더는 입력 문장에 대해 딱 한 번 실행됨. 그 출력 $H$ 로 만든 $K = HW_K$, $V = HW_V$ 도 당연히 고정임.

    • 디코딩 스텝이 100번이어도 K·V는 처음 것 그대로 씀
    • 디코더 레이어마다 $W_K, W_V$ 는 다르지만, 입력 $H$ 는 전부 같음

    그래서 추론 최적화에서 인코더 K·V는 캐싱 1순위임. 디코더 self-attention의 KV cache와는 성격이 다름 — 이쪽은 스텝마다 늘어나지만, cross-attention K·V는 처음부터 끝까지 변하지 않음.

    4. 숫자로 따라가기

    5. 디코더 블록에서의 위치

    출력 토큰 임베딩 + PE
        ↓
① Masked Self-Attention     Q·K·V = 출력 시퀀스   (미래 가림)
        ↓  Add & Norm
② Cross-Attention           Q = 디코더, K·V = 인코더 출력 H
        ↓  Add & Norm
③ FFN
        ↓  Add & Norm

    ①과 ③은 인코더 블록에도 있음. ②만 디코더에 있는 것이고, 그래서 “인코더 블록 + Cross-Attention = 디코더 블록"으로 외우면 편함.

    자세한 흐름은 Attention Is All You Need §10 참고.

    6. 번역 말고 어디에 쓰이나

    Cross-Attention은 “A가 B를 참조한다"는 일반 구조라서 번역 밖에서도 계속 나옴.

    모델Q (참조하는 쪽)K·V (참조당하는 쪽)
    Transformer 번역기디코더 출력 토큰인코더가 만든 원문 표현
    DETRobject query 100개인코더가 만든 이미지 feature
    EoMTobject query K개이미지 패치 토큰
    Stable Diffusion이미지 latent텍스트 프롬프트 임베딩

    DETR 이 좋은 예임 — “쿼리 100개가 이미지를 보고 각자 물체 하나를 집어 온다"는 게 정확히 Cross-Attention임. Q가 단어가 아니라 학습되는 벡터라는 점만 다름.

    EoMT 는 이 구조를 아예 없애고, 쿼리를 패치 토큰 열에 concat해서 self-attention 하나로 처리함. query→patch 구역이 cross-attention 역할을 대신하는 셈임.

    7. 코드

    import torch
import torch.nn as nn
import torch.nn.functional as F


class MultiHeadCrossAttention(nn.Module):
    """Self-Attention과 다른 점은 forward가 x 하나가 아니라 (x, memory) 둘을 받는 것뿐임."""

    def __init__(self, d_model=512, num_heads=8):
        super().__init__()
        self.h = num_heads
        self.d_k = d_model // num_heads
        self.q_proj = nn.Linear(d_model, d_model)      # 디코더 쪽에서
        self.kv_proj = nn.Linear(d_model, d_model * 2)  # 인코더 출력에서
        self.proj = nn.Linear(d_model, d_model)

    def forward(self, x, memory, pad_mask=None):
        # x      : (B, T_dec, D)  디코더 상태
        # memory : (B, T_enc, D)  인코더 출력 — 매 스텝 동일
        B, Td, D = x.shape
        Te = memory.shape[1]

        q = self.q_proj(x).view(B, Td, self.h, self.d_k).transpose(1, 2)
        k, v = self.kv_proj(memory).chunk(2, dim=-1)
        k = k.view(B, Te, self.h, self.d_k).transpose(1, 2)
        v = v.view(B, Te, self.h, self.d_k).transpose(1, 2)

        scores = (q @ k.transpose(-2, -1)) / self.d_k ** 0.5   # (B, h, T_dec, T_enc) — 직사각형
        if pad_mask is not None:                                # causal mask가 아니라 padding mask임
            scores = scores.masked_fill(pad_mask == 0, float('-inf'))
        out = F.softmax(scores, dim=-1) @ v                     # (B, h, T_dec, d_k)

        return self.proj(out.transpose(1, 2).reshape(B, Td, D)) # (B, T_dec, D)

    Self-Attention 구현과 비교하면 qkv 를 하나로 묶지 못하고 Q와 K·V를 따로 뽑는다는 것만 차이임. memory 가 스텝마다 안 바뀌므로, 실제 추론 코드는 kv_proj(memory) 결과를 밖에서 한 번만 계산해 넘김.

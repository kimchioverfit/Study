FFN

FFN (Position-wise Feed-Forward Network)

Transformer 블록의 두 번째 절반. attention이 토큰끼리 정보를 섞는 단계라면, FFN은 토큰 하나하나를 따로 가공하는 단계임. 논문에 따라 FFN, MLP, MLP block이라고 부르는데 전부 같은 것임 (Attention Is All You Need 는 FFN, ViT ·EoMT 는 MLP).

1. 정의

$$ \text{FFN}(x) = \sigma(xW_1 + b_1)\,W_2 + b_2 $$
  • $W_1 \in \mathbb{R}^{D \times D_{ff}}$ : 차원을 키움 (보통 $D_{ff} = 4D$)
  • $\sigma$ : 활성함수. 원조 Transformer는 ReLU, ViT/BERT/GPT-2 이후는 GELU, LLaMA 계열은 SwiGLU
  • $W_2 \in \mathbb{R}^{D_{ff} \times D}$ : 다시 줄임
(B, N, D) ─ Linear(D→4D) ─ 활성함수 ─ Linear(4D→D) ─▶ (B, N, D)

입출력 shape가 같아서 residual로 더할 수 있음: $x + \text{FFN}(\text{LN}(x))$

2. “Position-wise"의 뜻

같은 $W_1, W_2$ 를 모든 토큰(위치)에 독립적으로 적용한다는 뜻임. 토큰 $i$의 출력은 토큰 $i$의 입력에만 의존하고, 옆 토큰은 전혀 안 봄.

  • 시퀀스 길이 $N$이 얼마든 파라미터 수는 같음
  • 구현상 kernel 1×1 conv와 완전히 동일함. EfficientFormer 가 FFN을 Conv1x1-BN으로 바꿔 쓸 수 있는 이유
  • 토큰 간 정보 교환은 attention이 이미 했으므로, FFN은 그 결과를 각자 소화하는 역할임

3. 왜 4배로 키우나

  • 한 번 넓은 공간으로 펼쳐서 비선형을 먹여야 표현력이 생김. $D \to D$ 두 층이면 사실상 선형 변환 하나와 별 차이 없음
  • 4는 원조 논문의 경험적 선택($D=512, D_{ff}=2048$)이고 이후 대부분 관례로 따름. SwiGLU를 쓰는 모델은 게이트 때문에 $\tfrac{8}{3}D$ 정도로 줄여 파라미터 수를 맞춤

4. 알아두면 좋은 점

  • 파라미터의 2/3가 FFN에 있음 — 블록 하나에서 attention $4D^2$ vs FFN $8D^2$. 그래서 Structured Pruning 이나 양자화에서 FFN 차원($D_{ff}$)이 주요 타깃임
  • key-value 메모리 해석 — $W_1$의 각 행이 “패턴 감지기(key)”, $W_2$의 각 열이 “그 패턴에 대응하는 출력(value)“처럼 동작한다는 분석이 있음. LLM의 사실 지식이 주로 FFN에 저장된다는 연구가 여기서 나옴
  • MoE (Mixture of Experts) — FFN을 여러 개 두고 토큰마다 일부만 골라 쓰는 구조. attention이 아니라 FFN을 여러 개로 만드는 이유가 바로 “토큰별 독립 + 파라미터 대부분이 여기 있음” 때문임

5. 코드

import torch.nn as nn

class FFN(nn.Module):
    def __init__(self, dim, mlp_ratio=4.0, drop=0.0):
        super().__init__()
        hidden = int(dim * mlp_ratio)
        self.fc1 = nn.Linear(dim, hidden)     # D -> 4D
        self.act = nn.GELU()
        self.fc2 = nn.Linear(hidden, dim)     # 4D -> D
        self.drop = nn.Dropout(drop)

    def forward(self, x):                     # x: (B, N, D) — 토큰마다 독립 적용
        return self.drop(self.fc2(self.drop(self.act(self.fc1(x)))))

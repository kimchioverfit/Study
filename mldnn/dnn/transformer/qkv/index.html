    W_Q / W_K / W_V

    $W_Q$ / $W_K$ / $W_V$ — 어떻게 나뉘고 어떻게 학습되는가

    결론부터 아주 쉽게: $W_Q, W_K, W_V$ 는 그냥 nn.Linear 세 개임. 역전파로 갱신되는 평범한 가중치고, 특별한 학습 규칙 같은 건 없음. head 로 “나눈다"는 것도 새 가중치를 만드는 게 아니라 같은 $W$ 의 행을 연속 블록으로 자르는 것뿐임.

    Self-Attention 문서는 $Q = XW_Q$ 라는 정의와 “학습되는 가중치"라는 사실까지만 다룸. 이 문서는 그 뒤를 봄 — 세 $W$ 가 어떻게 쪼개져서 head 로 들어가고, backward 때 gradient 가 어느 경로로 돌아오는지.

    📌 이 문서의 코드는 q_proj / k_proj / v_proj 세 개로 분리해서 씀. 실제 구현은 nn.Linear(d_model, 3 * d_model) 하나로 합치는 게 보통인데(§6 ), 그러면 세 $W$ 가 한 텐서 안에 숨어서 무엇이 무엇인지 안 보임. 셋이 서로 다른 가중치라는 걸 눈으로 보려고 일부러 떼어 놓은 것임.

    1. 세 $W$ 는 무엇이 다른가

    같은 입력 $X$ 를 세 번, 서로 다른 가중치로 선형변환한 결과가 $Q, K, V$ 임.

    $$ Q = XW_Q, \qquad K = XW_K, \qquad V = XW_V $$
    class MultiHeadSelfAttention(nn.Module):
    """실제 구현은 q/k/v 를 Linear 하나로 합치지만, 여기서는 셋이 서로 다른
    가중치라는 걸 눈으로 보려고 일부러 따로 뒀음."""

    def __init__(self, d_model, num_heads):
        super().__init__()
        self.h = num_heads
        self.d_k = d_model // num_heads
        self.q_proj = nn.Linear(d_model, d_model, bias=False)   # W_Q
        self.k_proj = nn.Linear(d_model, d_model, bias=False)   # W_K
        self.v_proj = nn.Linear(d_model, d_model, bias=False)   # W_V
        self.o_proj = nn.Linear(d_model, d_model, bias=False)   # W_O
    항목값
    q_proj.weight$(64, 64)$
    k_proj.weight$(64, 64)$
    v_proj.weight$(64, 64)$

    셋 다 nn.init.kaiming_uniform_ 로 각각 따로 초기화됨. 처음부터 다른 난수로 시작하고, 이게 뒤에서 head 가 서로 다른 곳으로 갈라지는 출발점이 됨(§5 ).

    ⚠️ nn.Linear 는 $y = xW^\top$ 로 계산함. 그래서 q_proj.weight 의 shape 은 수식의 $W_Q$ 와 전치 관계임 (왜 그렇게 저장하는지는 nn Function §2 ). 수식에서 $W_Q \in \mathbb{R}^{d_{model} \times d_k}$ 라고 쓰면 코드에서는 weight 가 $(d_k, d_{model})$ 로 잡힘.

    2. head 는 어떻게 나뉘는가

    head 개수만큼 nn.Linear 를 더 만드는 게 아님. 출력 $d_{model}$ 차원을 $h$ 등분해서 쓰는 것뿐임.

        def split_heads(self, t):
        B, T, _ = t.shape
        # (B, T, d_model) -> (B, T, h, d_k) -> (B, h, T, d_k)
        return t.view(B, T, self.h, self.d_k).transpose(1, 2)
    단계shape
    q_proj(x)$(B, T, d_{model})$ = $(2, 5, 64)$
    .view(B, T, h, d_k)$(2, 5, 4, 16)$
    .transpose(1, 2)$(2, 4, 5, 16)$

    transpose 로 head 축을 앞으로 올리는 이유는, 뒤의 $QK^\top$ 를 배치 행렬곱 한 번으로 끝내기 위해서임. $(B, h)$ 가 배치 축이 되면 head 들이 서로 간섭 없이 병렬로 돌아감.

    여기서 중요한 건, head $i$ 가 보는 것이 결국 $W_Q$ 의 행 블록 하나라는 점임.

    W_Q = mha.q_proj.weight                       # (64, 64)
blk = W_Q[i * d_k:(i + 1) * d_k]              # head i 가 쓰는 행 (16, 64)
torch.allclose(qh[:, i], x @ blk.T)           # -> True
    head쓰는 행확인
    0W_Q[0:16]True
    3W_Q[48:64]True

    즉 “head 가 8개"는 가중치가 8개라는 뜻이 아니라, 가중치 하나를 8조각으로 읽는다는 뜻임. 논문이 $d_k = d_{model}/h$ 로 잡아서 연산량이 single-head 와 비슷해지는 것도 이 구조 때문임(Self-Attention §7 ).

    3. 틀리기 쉬운 지점 — view → transpose 순서

    view 로 먼저 쪼개고 transpose 로 축을 올려야 함. 순서를 바꾸면 shape 은 그대로 통과하는데 값만 틀어짐.

    right = q.view(B, T, h, d_k).transpose(1, 2)     # (2, 4, 5, 16)
wrong = q.transpose(0, 1).reshape(B, h, T, d_k)  # (2, 4, 5, 16) — shape 동일

right.shape == wrong.shape                        # True
torch.allclose(right, wrong)                      # False

    assert q.shape == (B, h, T, d_k) 같은 검사로는 절대 안 잡힘. 학습이 터지지도 않고 그냥 “성능이 좀 덜 나오는” 형태로만 드러나서 찾기 어려움. shape 이 아니라 값으로 검증해야 함 — 위 allclose 처럼 head 0 이 W_Q[0:d_k] 와 맞는지 보는 게 제일 확실함.

    4. gradient 는 어디서 오는가

    세 $W$ 는 전부 같은 loss 에서 gradient 를 받지만, 거쳐 오는 경로가 다름.

    out = mha(x)
loss = out.pow(2).mean()
loss.backward()
    가중치grad norm경로
    $W_V$8.80e-02attn @ V — 선형 경로로 그대로 받음
    $W_O$6.01e-02출력 직전 선형
    $W_K$1.66e-02softmax 를 거쳐서 들어옴
    $W_Q$1.49e-02〃

    $W_V$ 의 gradient 가 $W_Q$ 의 약 5.9배임. $V$ 는 attention weight 가 곱해진 뒤 바로 더해지는 선형 경로라 gradient 가 거의 그대로 돌아오지만, $Q$ 와 $K$ 는 softmax 의 Jacobian 을 한 번 통과하면서 줄어든 채 도착하기 때문임. softmax 가 포화될수록(한 토큰에 확률이 쏠릴수록) 이 차이는 더 벌어짐. $\sqrt{d_k}$ 로 나누는 scaling 이 바로 이 포화를 막으려는 것임(Self-Attention §5 ).

    그리고 $W_Q$ 와 $W_K$ 의 gradient 는 같지 않음.

    torch.allclose(q_proj.weight.grad, k_proj.weight.grad)   # -> False

    $\text{scores} = QK^\top$ 이므로 미분하면 이렇게 됨.

    $$ \frac{\partial \mathcal{L}}{\partial W_Q} = X^\top \frac{\partial \mathcal{L}}{\partial Q}, \qquad \frac{\partial \mathcal{L}}{\partial Q} = \frac{1}{\sqrt{d_k}}\,\frac{\partial \mathcal{L}}{\partial S}\,K $$

    $W_Q$ 쪽 gradient 에는 $K$ 가, $W_K$ 쪽에는 $Q$ 가 들어감. 서로가 서로의 gradient 통로라서 둘이 같이 움직이되 절대 같은 값이 되지는 않음. $Q$ 와 $K$ 를 굳이 따로 두는 이유도 여기 있음 — 하나로 묶으면 $\text{scores}$ 가 대칭이 돼서 “A가 B를 참조하는 정도"와 “B가 A를 참조하는 정도"를 구분 못 하게 됨(Self-Attention §2 ).

    5. head 마다 다르게 학습되는 이유

    $W_Q$ 하나의 gradient 를 head 블록별로 끊어서 norm 을 재 보면 전부 다름.

    headgrad norm
    06.12e-03
    16.96e-03
    27.76e-03
    38.78e-03

    같은 텐서 안에 있어도 각 블록이 받는 gradient 가 달라서 서로 다른 방향으로 갈라짐. 원인은 단순함 — 초기화 난수가 블록마다 달랐고, 그래서 처음 뽑는 attention 패턴이 달랐고, 그 차이가 gradient 차이로 이어진 것임.

    사람이 “head 1은 문법, head 2는 의미” 식으로 지정한 게 아님. 그래서 학습이 끝난 뒤 보면 역할이 겹치는 head 도 있고, 기여가 거의 없어서 잘라내도 성능이 안 떨어지는 head 도 있음.

    한 step 돌려 보면 세 $W$ 가 각자 자기 gradient 만큼만 움직이는 것도 확인됨.

    torch.optim.SGD(mha.parameters(), lr=0.1).step()

    6. 실제 구현은 왜 하나로 합치나

    위에서 셋으로 떼어 놓은 건 설명을 위한 것이고, 실전 코드는 보통 이렇게 씀.

    self.qkv = nn.Linear(d_model, 3 * d_model, bias=False)   # W_Q | W_K | W_V
...
q, k, v = self.qkv(x).chunk(3, dim=-1)

    행렬곱을 한 번에 몰아 하면 GPU 가 훨씬 효율적으로 돌아서 그럼. 결과는 완전히 같고, 합친 버전에서도 $W_Q$ 는 그냥 qkv.weight.chunk(3, dim=0)[0] 로 꺼내 볼 수 있음.

    처음 읽을 때는 분리된 쪽이 훨씬 이해하기 쉬우니, 구조를 파악할 때는 세 개로 보고 성능이 필요할 때 합치면 됨.

    7. 전체 코드

    import torch
import torch.nn as nn
import torch.nn.functional as F


class MultiHeadSelfAttention(nn.Module):
    """실제 구현은 q/k/v 를 Linear 하나로 합치지만, 여기서는 셋이 서로 다른
    가중치라는 걸 눈으로 보려고 일부러 따로 뒀음."""

    def __init__(self, d_model, num_heads):
        super().__init__()
        assert d_model % num_heads == 0
        self.h = num_heads
        self.d_k = d_model // num_heads
        self.q_proj = nn.Linear(d_model, d_model, bias=False)   # W_Q
        self.k_proj = nn.Linear(d_model, d_model, bias=False)   # W_K
        self.v_proj = nn.Linear(d_model, d_model, bias=False)   # W_V
        self.o_proj = nn.Linear(d_model, d_model, bias=False)   # W_O

    def split_heads(self, t):
        B, T, _ = t.shape
        # (B, T, d_model) -> (B, T, h, d_k) -> (B, h, T, d_k)
        return t.view(B, T, self.h, self.d_k).transpose(1, 2)

    def forward(self, x, mask=None):                 # x: (B, T, d_model)
        B, T, D = x.shape
        q = self.split_heads(self.q_proj(x))         # (B, h, T, d_k)
        k = self.split_heads(self.k_proj(x))
        v = self.split_heads(self.v_proj(x))

        scores = (q @ k.transpose(-2, -1)) / self.d_k ** 0.5    # (B, h, T, T)
        if mask is not None:
            scores = scores.masked_fill(mask == 0, float('-inf'))
        out = F.softmax(scores, dim=-1) @ v                     # (B, h, T, d_k)

        out = out.transpose(1, 2).reshape(B, T, D)              # Concat
        return self.o_proj(out)                                 # (B, T, d_model)


torch.manual_seed(0)
B, T, d_model, h = 2, 5, 64, 4
d_k = d_model // h

mha = MultiHeadSelfAttention(d_model, h)
x = torch.randn(B, T, d_model)

# [2] head 는 W_Q 의 행 블록임
q = mha.q_proj(x)
qh = mha.split_heads(q)
W_Q = mha.q_proj.weight
for i in (0, 3):
    blk = W_Q[i * d_k:(i + 1) * d_k]
    assert torch.allclose(qh[:, i], x @ blk.T, atol=1e-6)

# [3] 순서를 바꾸면 shape 은 통과하는데 값이 다름
wrong = q.transpose(0, 1).reshape(B, h, T, d_k)
assert wrong.shape == qh.shape
assert not torch.allclose(wrong, qh, atol=1e-6)

# [4] gradient 경로 비교
loss = mha(x).pow(2).mean()
loss.backward()
for n in ("q_proj", "k_proj", "v_proj", "o_proj"):
    g = getattr(mha, n).weight.grad
    print(f"grad {n:7s} norm {g.norm().item():.6e}")

# [5] head 블록별 gradient
for i in range(h):
    blk = mha.q_proj.weight.grad[i * d_k:(i + 1) * d_k]
    print(f"head {i}: {blk.norm().item():.6e}")

    실행 결과(seed 0, CPU)는 위 §4·§5 표의 숫자와 같음.

    8. 한 줄 요약

    $W_Q, W_K, W_V$ 는 따로 초기화된 평범한 선형층 세 개고, head 는 그 가중치의 행 블록임. backward 때 $V$ 는 선형 경로로 gradient 를 그대로 받고 $Q, K$ 는 softmax 를 통과해 줄어든 채 받으며, $Q$ 와 $K$ 는 서로를 통로 삼아 다른 값으로 갱신됨.

    참고

    • Self-Attention — $Q/K/V$ 정의와 전체 수식. 이 문서의 전제
    • Multi-Head Attention — head 를 왜 여러 개 두는지
    • Dimension — $d_{model}$ 과 $d_k$ 를 정하는 기준
    • Embedding Layer — 입력 $X$ 가 만들어지기까지
    • Cross-Attention — $K, V$ 만 다른 시퀀스에서 오는 경우
    • Attention Is All You Need — 원 논문 정리
    • FFN (MLP) — attention 다음 단계

    Token (토큰)

    결론부터 아주 쉽게: 모델은 글자를 직접 보지 않음. 문장을 잘게 자른 조각이 토큰이고, 모델이 실제로 받는 건 그 조각에 붙은 정수 ID임. 어떻게 자를지는 tokenizer가 정하는데, tokenizer는 회사·모델마다 다름. 그래서 같은 문장도 모델이 바뀌면 토큰이 달라짐.

    1. 토큰이란

    문장을 모델이 다룰 수 있는 단위로 쪼갠 것임. 단어와 같지 않음 — 단어보다 작을 수도 있고, 흔한 단어는 통째로 하나가 되기도 함.

    "나는 학교에 간다"
        ↓ tokenizer
["나", "##는", "학교", "##에", "간", "##다"]
        ↓ vocabulary
[102, 450, 630, 231, 901, 250]

    여기까지가 모델에 들어가기 전 단계임. 이후 각 ID가 Embedding Layer 에서 벡터로 바뀜.

    위 예시의 ## 는 WordPiece 표기로 “앞 토큰에 이어붙는 조각"이라는 뜻임. 표기법은 도구마다 다름 (§3).

    2. 왜 단어 단위로 자르지 않나

    방식문제
    단어 단위사전이 끝없이 커짐. 사전에 없는 단어(OOV)가 나오면 처리 불가. 한국어는 조사·어미가 붙어 학교, 학교에, 학교에서가 전부 다른 단어가 됨
    글자 단위사전은 작아지지만 시퀀스가 너무 길어짐. attention 비용이 길이의 제곱이라 치명적임
    subword둘의 절충. 흔한 것은 통째로, 드문 것은 조각으로

    그래서 요즘 모델은 대부분 subword 방식을 씀. 처음 보는 단어도 조각으로 쪼개서 표현할 수 있으므로 OOV가 없어짐.

    3. Tokenizer가 하는 일

    두 가지임.

    1. 자르기 — 문장을 토큰 열로 분할
    2. 번호 매기기 — vocabulary를 보고 각 토큰을 정수 ID로 변환

    여기서 자주 헷갈리는 부분:

    • vocabulary 내용은 사람이 만들지 않음. 말뭉치의 빈도를 보고 “어떤 조각을 토큰으로 둘지” 알고리즘이 학습함
    • 사람이 정하는 것은 알고리즘과 vocab size(예: 32,000개) 같은 설정값임

    주요 알고리즘 세 가지임.

    알고리즘만든 곳표기 방식
    BPE (Byte-Pair Encoding)—자주 붙어 나오는 쌍을 반복해서 병합
    WordPieceGoogle이어붙는 조각에 ## 를 붙임 (##는)
    SentencePieceGoogle공백까지 기호로 다룸. 공백을 ▁ 로 표시 (▁학교)

    같은 문장이라도 어느 쪽을 쓰느냐에 따라 결과가 다르게 나옴.

    WordPiece      ["나", "##는", "학교", "##에", "간", "##다"]
SentencePiece  ["▁나", "는", "▁학교", "에", "▁간", "다"]

    4. Tokenizer는 회사마다 다름

    표준이 없음. 모델을 만드는 쪽에서 자기 말뭉치로 직접 학습시켜 씀.

    모델 계열tokenizer
    BERT (Google)WordPiece
    T5 (Google)SentencePiece
    GPT (OpenAI)BPE — GPT-3.5·4는 cl100k_base, GPT-4o 이후는 o200k_base
    LLaMA 1·2 (Meta)SentencePiece
    LLaMA 3 이후 (Meta)tiktoken 계열 BPE, 더 큰 vocab
    Claude (Anthropic) · Gemini (Google)각자 자체 tokenizer

    같은 회사라도 모델 세대가 바뀌면 tokenizer가 바뀌기도 함. 위 GPT와 LLaMA가 그런 경우임.

    그래서 실제로 무엇이 달라지나

    • 같은 문장의 토큰 수가 모델마다 다름. 토큰 수는 글자 수도 단어 수도 아님
    • 비용과 컨텍스트 길이가 토큰 단위로 계산됨 — 모델을 갈아타면 같은 입력이라도 토큰 수를 다시 세야 함
    • 한국어는 영어보다 토큰이 많이 나오는 경향이 있음. 대부분의 tokenizer가 영어 말뭉치 비중이 큰 상태로 학습됐기 때문임. 최근 모델들은 다국어 비중을 늘려 이 격차를 줄이는 추세임
    • 모델과 tokenizer는 한 쌍임. 다른 tokenizer로 자른 ID를 넣으면 임베딩 행렬의 엉뚱한 행을 집어오므로 출력이 망가짐

    토큰 수가 궁금하면 각 모델이 제공하는 도구로 직접 세는 수밖에 없음 (OpenAI는 tiktoken, HuggingFace 모델은 AutoTokenizer). 어림짐작한 숫자는 모델이 바뀌면 그대로 틀림.

    5. 특수 토큰

    문장 조각 말고도, 모델이 구조를 알아보려고 쓰는 토큰이 따로 있음. 이름은 계열마다 다름.

    역할예
    시작 / 끝<BOS>, <EOS>
    길이 맞추기용 빈칸<PAD>
    사전에 없음<UNK>
    문장 전체 요약 자리[CLS] — ViT 의 [class] 토큰이 같은 아이디어임
    가려놓고 맞히기[MASK]

    디코더 가 <BOS> 에서 시작해 <EOS> 가 나올 때까지 한 토큰씩 생성하는 것이 대표적인 쓰임임.

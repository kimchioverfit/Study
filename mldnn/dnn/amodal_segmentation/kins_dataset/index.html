    Amodal Instance Segmentation With KINS Dataset

    📄 논문: Amodal Instance Segmentation With KINS Dataset — Qi et al., CVPR 2019 · 데이터셋/코드

    Lu Qi et al., CVPR 2019. 결론부터 아주 쉽게: “자율주행 사진(KITTI)에 가려진 부분까지 라벨링한 대규모 데이터셋 KINS를 만들고, 여러 단계의 특징(feature)을 한꺼번에 활용해서 가려진 부분을 더 잘 맞추는 MVC 구조를 제안한 논문.” 앞선 COCOA(5,000장, 일반 사진)보다 훨씬 크고, 실전 위험이 직결되는 자율주행 도메인에 amodal segmentation을 처음 본격적으로 적용했음.

    전체 계보 속 위치는 Amodal Segmentation 개요 참고.

    1. 왜 자율주행에서 amodal이 특히 중요한가

    도로 사진에서는 가림(occlusion)이 일상적임.

    [도로 사진 예시]

  큰 트럭 뒤에 절반 가려진 보행자
       ↓
  "보이는 부분만" 인식하면 → 다리 두 개만 보고 "이게 뭐지?" 헷갈릴 수 있음
  "전체 모양(amodal)"까지 예측하면 → "사람 한 명이 트럭 뒤에서 나오려 한다"를 미리 파악 가능

    자율주행차가 가려서 일부만 보이는 보행자/차량의 전체 형태와 위치를 미리 알아야 급정거·회피 판단을 더 빨리, 더 안전하게 내릴 수 있음. 즉 amodal segmentation이 학문적 흥미를 넘어 안전과 직결되는 실전 문제가 됨.

    2. 핵심 기여 1 — KINS 데이터셋

    KINS (KITTI INStance dataset): 자율주행 데이터셋으로 유명한 KITTI에 amodal instance 라벨을 새로 추가한 것.

    • 차량, 보행자, 자전거 등 8개 카테고리에 대해 픽셀 단위 instance 라벨을 대규모로 라벨링
    • 실제 도로 위 사진이라 자연스러운(인위적이지 않은) 가림 패턴이 풍부함 — Li & Malik(2016) 의 인위적 합성 가림, COCOA의 일반 스냅샷과는 다른, 실전에 가까운 데이터
    • 이후 amodal segmentation 연구의 주요 벤치마크로 자리잡음 — BCNet(2021) 을 포함한 다수의 후속 논문이 KINS로 성능을 검증

    3. 핵심 기여 2 — MVC (Multi-view/level Coding)

    이 논문의 모델 구조 이름이 MVC다. 아이디어를 아주 쉽게 풀면:

    “가려진 부분을 맞추려면, 딱 한 종류의 정보만 봐서는 부족함. 여러 층위(level)의 정보를 같이 봐야 함.”

    낮은 레벨 정보: 이 픽셀 근처의 색깔/질감 (지엽적)
   +
중간 레벨 정보: 이 물체의 부분들이 어떻게 이어지는지 (부분-전체 관계)
   +
높은 레벨 정보: 이게 "자동차"라는 걸 알면 자동차의 전형적인 전체 형태를 앎 (카테고리 지식)
   ↓
이 세 가지를 결합(coding)해서 가려진 부분의 모양을 추론
    • 여러 recognition level의 특징을 하나의 멀티태스크 프레임워크로 결합해서, amodal 마스크와 modal(visible) 마스크를 동시에 더 정확히 예측하도록 학습
    • “그냥 마스크 헤드 하나 더 붙이자”(ORCNN )는 접근보다 한 단계 더 정교하게, 어떤 정보를 어떻게 결합해야 가려진 부분을 더 잘 맞히는지에 집중한 구조

    4. 의의와 한계

    의의:

    • amodal segmentation을 자율주행이라는 실전 응용과 직접 연결
    • KINS는 이후 연구들의 표준 벤치마크가 되어, “COCOA에서만 잘 되는 방법"이 아니라 “실제 도로 상황에서도 되는 방법"인지 검증하는 기준을 제공

    한계: KINS든 COCOA든 여전히 사람이 직접 amodal 마스크를 라벨링해야 했음 — 라벨링 비용이 크다는 근본적 문제는 그대로 남아 있었음. 이 문제를 정면으로 다룬 것이 바로 다음 논문 Zhan et al.(2020)의 self-supervised 접근 임.

1.Overfeat

OverFeat (2013)

📄 논문: OverFeat: Integrated Recognition, Localization and Detection using Convolutional Networks — Sermanet et al., ICLR 2014

Sermanet et al., 2013. Region proposal 없이 CNN을 이미지 전체에 sliding window처럼 돌려서, 분류(classification)·위치추정(localization)·검출(detection)을 하나의 통합 프레임워크로 동시에 수행한 초기 모델. ILSVRC 2013 localization 트랙 우승작. 시기상 R-CNN 보다 먼저 나왔고 접근 방식도 정반대(“이미지 전체를 훑기” vs “후보 영역만 골라내기”)다. 여기서 쓰인 “FC layer를 conv로 바꿔서 통째로 한 번에 처리” 트릭은 이후 Faster R-CNN의 RPN , SSD/YOLO 같은 One-stage detector의 뿌리와 맞닿아 있다.

🔷 1. 이 논문 이전 상황 — Sliding Window는 원래 “못 쓰는” 방법이었다

물체 검출의 가장 단순한 발상은 이렇다.

이미지 위에서 작은 창(window)을 조금씩 옮겨가며, 그 창 안에 물체가 있는지 매번 분류기로 확인
[이미지]
┌─────────────────────────┐
│ [□]→[□]→[□]→[□]→ ...     │   ← 창을 한 칸씩 옮기며
│ 여러 크기(scale)로도 반복    │      전부 분류기에 통과시켜야 함
└─────────────────────────┘

문제는 창의 개수가 위치 × 스케일 조합으로 수만~수십만 개가 된다는 점이다. 이걸 창 하나하나마다 CNN에 새로 통과시키면 계산량이 감당이 안 된다 — R-CNN 이 굳이 Selective Search로 후보를 ~2000개까지 미리 걸러낸 것도 바로 이 “다 훑으면 너무 느리다"는 문제 때문이다.

OverFeat의 질문: “굳이 창마다 따로 돌려야 하나? 한 번에 다 계산할 방법은 없을까?”

🔷 2. 핵심 아이디어 — FC layer를 1×1 Conv로 바꿔서 “통째로 한 번에”

CNN 구조를 떠올려보면, 보통 conv layer들로 특징을 뽑은 뒤 마지막에 FC(fully connected) layer로 분류 결과를 낸다. FC layer는 입력 크기가 고정되어 있어야 하고, 한 번에 하나의 결과만 낸다.

OverFeat의 트릭: 이 FC layer를 1×1 conv로 재해석한다.

[기존 방식]                              [OverFeat 방식]

 고정 크기 입력(예: 224×224)              임의 크기 입력(예: 큰 이미지 그대로)
        │                                        │
   conv layers                              conv layers
        │                                        │
  Flatten → FC layer                    FC를 1×1 conv로 재해석
        │                                        │
   결과 1개                          위치별 결과가 격자(grid)로 한꺼번에 출력
   (창 하나에 대한 답)                  (모든 "창"에 대한 답을 한 번의 forward로)
  • FC layer의 가중치 자체는 1×1 conv 필터와 수학적으로 동일하게 표현할 수 있다 — 파라미터를 바꾸는 게 아니라, 같은 연산을 다르게 재해석하는 것
  • 이렇게 바꾸면 네트워크가 입력 이미지 크기에 더 이상 얽매이지 않는다. 큰 이미지를 그대로 넣으면, conv 연산이 슬라이딩하며 훑고 지나간 것과 똑같은 효과로 여러 “창"에 대한 결과가 격자 형태로 한꺼번에 나온다
  • 핵심 이득: 창들끼리 겹치는 영역의 연산이 자동으로 재사용된다 (conv 연산 자체가 원래 이런 식으로 동작하니까). 창 하나하나를 처음부터 다시 계산하지 않아도 된다는 뜻
  • 이 “FC를 conv로 바꿔서 이미지 전체를 한 번에 처리"하는 아이디어는 이후 semantic segmentation의 FCN, 그리고 Faster R-CNN의 RPN 이 conv feature map 위에서 슬라이딩하는 방식에도 그대로 이어진다

🔷 3. Multi-scale — 여러 배율로 돌려서 크기가 다른 물체까지 잡기

물체는 사진마다 크기가 제각각이다. 하나의 스케일만 보면 너무 작거나 너무 큰 물체는 놓치기 쉽다.

원본 이미지
   ├─► 작게 리사이즈  → 네트워크 통과 → 예측 결과 A
   ├─► 중간 크기      → 네트워크 통과 → 예측 결과 B
   └─► 크게 리사이즈  → 네트워크 통과 → 예측 결과 C

              A + B + C를 종합 → 최종 예측
  • 같은 이미지를 여러 스케일로 리사이즈해서 각각 네트워크에 통과시키고, 그 결과들을 나중에 합친다
  • 스케일마다 “잘 잡히는 물체 크기"가 다르기 때문에, 여러 스케일을 합치면 다양한 크기의 물체를 놓치지 않고 잡을 수 있다

🔷 4. 세 가지 task를 한 프레임워크에서 — Classification + Localization + Detection

OverFeat은 같은 backbone (conv feature 추출부)을 공유하는 두 개의 head로 세 가지 task를 전부 처리한다.

                    conv feature map (공유)
                          │
            ┌─────────────┴─────────────┐
            ▼                           ▼
    Classification head           Regression head
   "여기에 어떤 클래스의        "물체의 정확한 위치는
    물체가 있는가?"              (x, y, w, h) 얼마인가?"
Task하는 일
Classification이미지(또는 위치)에 어떤 클래스가 있는지 예측
Localization그 물체의 bounding box 좌표를 회귀(regression)로 예측
Detection위 둘을 합쳐서 “어디에 무엇이 있는지"까지 한 번에 출력
  • Classification head와 Regression head가 같은 conv feature를 공유하고, 마지막 부분만 갈라진다 — 이후 Fast R-CNN의 multi-task loss 나 Faster R-CNN의 RPN 도 “하나의 feature를 공유해서 분류+회귀를 동시에 예측"하는 같은 설계 철학을 따른다
  • 하나의 학습된 네트워크로 세 가지 대회 트랙(classification/localization/detection)에 모두 출전할 수 있었다는 것이 당시로서는 상당히 새로운 접근이었다

🔷 5. Greedy Box Merging — 겹치는 예측들을 하나로 합치기

여러 위치, 여러 스케일에서 쏟아지는 예측 결과에는 같은 물체를 가리키는 중복된 박스가 많다. 이를 하나로 정리하는 후처리가 필요하다.

여러 위치·스케일에서 나온 겹치는 박스들
   [□] [□] [□]
     [□] [□]         →  greedy하게 누적·병합  →  최종 박스 1개
       [□]
  • 예측된 박스들을 신뢰도(confidence) 순으로 보면서, 충분히 겹치는(가까운) 박스들끼리는 좌표를 평균 내듯 누적·병합해나가는 방식
  • 이후 R-CNN 계열 이후 detection에서 표준으로 자리잡은 NMS(Non-Maximum Suppression) 와 목적은 같다(“중복된 박스를 하나로 정리”) — 다만 OverFeat은 NMS처럼 겹치는 박스를 단순히 억제/제거하는 대신, 여러 박스의 정보를 합쳐서(merge) 더 정확한 박스를 만들어내는 방식을 썼다는 점이 차이

🔷 6. 의의와 한계

의의:

  • 분류·위치추정·검출을 하나의 CNN으로 통합한 초기 사례로, ILSVRC 2013 localization 트랙에서 우승
  • “FC를 conv로 바꿔 이미지 전체를 한 번에 처리한다"는 아이디어는 이 논문만의 것으로 끝나지 않고, 이후 segmentation(FCN)과 detection(Faster R-CNN의 RPN , SSD, YOLO) 전반에 걸쳐 반복적으로 재사용되는 핵심 개념이 됐다

한계:

  • 이미지를 촘촘히 훑는 sliding window 방식은, 물체가 없는 배경 위치까지 굉장히 많이 평가하게 만든다 — 분류기가 “이 중 극소수만 진짜 물체"인 상황에서 학습·추론해야 해서 비효율적이었다
  • 곧이어 등장한 R-CNN 이 Selective Search로 후보 영역을 미리 ~2000개로 걸러내는 방식을 들고나오면서 detection 정확도(mAP)에서 크게 앞서, 한동안 region proposal 기반 접근(two-stage) 이 대세가 됐다
  • 하지만 이후 SSD·YOLO 같은 One-stage detector들이 다시 “이미지 전체를 촘촘히 훑어 한 번에 예측"하는 방향으로 돌아오면서, OverFeat의 아이디어가 재조명됐다 — 결국 OverFeat은 R-CNN 계열(two-stage) 과 One-stage 계열 양쪽 모두의 뿌리에 걸쳐 있는 초기 모델로 평가된다

🔷 7. 정리 — 한 문장씩

질문답
무엇을 없앴나창(window)마다 CNN을 따로 돌리는 반복 연산
어떻게 없앴나FC layer를 1×1 conv로 바꿔 이미지 전체를 한 번의 forward로 처리
크기가 다른 물체는 어떻게이미지를 여러 스케일로 리사이즈해서 각각 돌리고 결과를 합침
세 가지 task를 어떻게 통합했나같은 conv feature 위에 classification head + regression head
중복 예측은 어떻게 처리greedy box merging (겹치는 박스들을 누적·병합)
왜 이후 R-CNN에 밀렸나배경 위치를 너무 많이 평가해 비효율적 — region proposal이 이 문제를 해결
왜 다시 중요해졌나SSD/YOLO 같은 One-stage detector, Faster R-CNN의 RPN이 같은 “conv로 슬라이딩” 아이디어를 계승

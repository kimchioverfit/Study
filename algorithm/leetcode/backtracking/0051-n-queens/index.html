    51. N-Queens

    51. N-Queens

    문제 원문 — LeetCode

    n × n 체스판에 퀸 n개를 서로 공격할 수 없도록 배치하는 모든 방법을 구하는 문제임. 퀸은 같은 행, 같은 열, 대각선에 있는 다른 퀸을 공격할 수 있음.

    각 배치는 문자열 배열로 반환하며, 'Q'는 퀸, '.'은 빈칸을 의미함. 정답의 순서는 상관없으며, 입력 범위는 1 <= n <= 9임.

    핵심은 한 행에 퀸 하나를 배치한 뒤 다음 행으로 내려가고, 탐색이 끝나면 방금 놓은 퀸을 제거하는 것임. 충돌하는 위치는 다음 행을 탐색하기 전에 제외함.

    예시

    n = 4일 때 정답은 다음 두 배치임.

    첫 번째 배치       두 번째 배치
.Q..              ..Q.
...Q              Q...
Q...              ...Q
..Q.              .Q..
    Input: n = 4
Output: [[".Q..", "...Q", "Q...", "..Q."],
         ["..Q.", "Q...", "...Q", ".Q.."]]

Input: n = 1
Output: [["Q"]]

    n = 2, n = 3은 조건을 만족하는 배치가 없으므로 빈 배열을 반환함.

    행마다 퀸 하나만 배치하는 이유

    퀸 n개가 같은 행에서 충돌하지 않으려면, n개의 행에 정확히 하나씩 배치되어야 함. 따라서 모든 칸에서 퀸을 놓을지 말지 결정하는 대신, 현재 행의 어느 열에 놓을지만 결정하면 됨.

    dfs(row, n)에 들어왔을 때의 상태는 다음과 같음.

    • 0부터 row - 1까지의 행에는 퀸이 하나씩 있으며, 서로 공격하지 않음.
    • row부터 n - 1까지의 행은 비어 있음.
    • 현재 호출에서는 row행에 놓을 퀸의 열을 선택함.

    이 조건을 유지하면서 내려가기 때문에 같은 행은 검사할 필요가 없음. 아래쪽 행에는 아직 퀸이 없으므로, 위쪽 행의 같은 열과 양쪽 대각선만 검사하면 됨.

    Solution

    class Solution {
public:
    vector<vector<string>> results;
    vector<string> board;
    vector<vector<bool>> visited;

    bool isValid(int row, int col, int n) {
        for (int i = 0; i < row; i++) {
            int diff = row - i;

            // 같은 열 검사
            if (visited[i][col])
                return false;

            // 왼쪽 위 대각선 검사
            if (col - diff >= 0 && visited[i][col - diff])
                return false;

            // 오른쪽 위 대각선 검사
            if (col + diff < n && visited[i][col + diff])
                return false;
        }

        return true;
    }

    void dfs(int row, int n) {
        if (row == n) {
            results.push_back(board);
            return;
        }

        for (int col = 0; col < n; col++) {
            if (!isValid(row, col, n))
                continue;

            // Q 배치
            board[row][col] = 'Q';
            visited[row][col] = true;

            // 다음 행 탐색
            dfs(row + 1, n);

            // Backtracking
            board[row][col] = '.';
            visited[row][col] = false;
        }
    }

    vector<vector<string>> solveNQueens(int n) {
        results.clear();
        board = vector<string>(n, string(n, '.'));
        visited = vector<vector<bool>>(n, vector<bool>(n, false));

        dfs(0, n);

        return results;
    }
};

    상태를 저장하는 변수

    변수역할
    results완성된 모든 정답 체스판을 저장함
    board현재 탐색 중인 체스판을 문자열 배열로 저장함
    visited현재 퀸이 놓인 칸을 true로 표시함

    여기서 visited는 현재 퀸의 위치를 나타냄. 과거에 한 번 방문한 모든 칸이나 퀸이 공격하는 모든 칸을 표시하는 배열은 아님. 퀸을 제거하면 해당 칸도 다시 false가 됨.

    board[row][col] == 'Q'를 검사해도 같은 정보를 얻을 수 있으므로, visited 없이 구현하는 것도 가능함. 이 풀이에서는 출력용 체스판과 충돌 검사에 쓰는 배열을 함께 갱신함.

    solveNQueens()에서 결과를 비우고 두 배열을 초기화하므로, 같은 Solution 객체로 다시 호출해도 이전 결과나 배치가 남지 않음.

    대각선 검사에서 diff를 사용하는 이유

    현재 놓으려는 위치가 (row, col)이고, 검사할 위쪽 행이 i라면 두 행의 거리는 diff = row - i임.

    대각선은 행이 한 칸 바뀔 때 열도 한 칸 바뀜. 따라서 위로 diff칸 이동했을 때 확인할 위치는 다음과 같음.

    방향확인할 위치배열 범위 조건
    같은 열(i, col)col이 이미 0부터 n - 1 범위임
    왼쪽 위 대각선(i, col - diff)col - diff >= 0이어야 함
    오른쪽 위 대각선(i, col + diff)col + diff < n이어야 함

    예를 들어 n = 4에서 (3, 2)에 퀸을 놓으려 하면 다음 칸들을 검사함. 좌표는 모두 0부터 시작함.

    위쪽 행 idiff같은 열왼쪽 위오른쪽 위
    03(0, 2)범위 밖범위 밖
    12(1, 2)(1, 0)범위 밖
    21(2, 2)(2, 1)(2, 3)

    이 중 하나라도 퀸이 있으면 현재 위치는 사용할 수 없음. 범위를 먼저 검사하는 && 조건 덕분에 음수 인덱스나 n 이상의 인덱스로 배열에 접근하지 않음.

    배치하고 탐색한 뒤 원상 복구하기

    백트래킹의 핵심은 다음 세 단계임.

    // 1. 현재 선택을 상태에 반영
board[row][col] = 'Q';
visited[row][col] = true;

// 2. 이 선택을 유지한 채 다음 행 탐색
dfs(row + 1, n);

// 3. 다음 후보를 시도할 수 있도록 현재 선택 취소
board[row][col] = '.';
visited[row][col] = false;

    재귀 호출마다 row와 반복문의 col은 별도로 유지되지만, board와 visited는 모든 호출이 공유하는 멤버 변수임. 따라서 함수에서 돌아왔다고 퀸이 자동으로 사라지지 않음. 직접 두 배열을 복원해야 다음 열을 같은 조건에서 시도할 수 있음.

    다음 행에서 가능한 열을 하나도 찾지 못하면 반복문이 끝나면서 호출한 곳으로 돌아옴. 호출한 곳은 자신이 놓았던 퀸을 제거하고, col을 증가시켜 다음 후보를 탐색함. 답을 찾은 뒤에도 같은 복원 과정을 거쳐 다른 배치를 계속 찾음.

    isValid()가 false인 후보에서 재귀 호출을 건너뛰는 부분은 가지치기임. 현재 퀸끼리 이미 충돌한다면 아래쪽에 퀸을 더 놓아도 해결되지 않으므로, 그 선택으로 시작하는 탐색을 진행할 필요가 없음.

    n이 4일 때 탐색 과정

    각 행에서 선택한 열을 순서대로 적으면 [1, 3, 0, 2]는 (0, 1), (1, 3), (2, 0), (3, 2)에 퀸을 놓은 상태임.

    열을 0부터 시도하므로 첫 번째 탐색은 [0]에서 시작함.

    현재 선택다음 행에서 일어나는 일
    [0]1행의 열 0, 1은 충돌하므로 건너뛰고 열 2를 선택함
    [0, 2]2행에 가능한 열이 없어 돌아온 뒤, 1행의 열 2에 놓은 퀸을 제거함
    [0, 3]1행의 다음 후보인 열 3을 선택하고, 2행의 열 1까지 진행함
    [0, 3, 1]3행에 가능한 열이 없어 돌아가며 선택을 취소함
    []0행의 열 0에서 시작한 모든 경우가 끝나면 첫 퀸도 제거함
    [1] → [1, 3] → [1, 3, 0] → [1, 3, 0, 2]각 단계의 충돌 검사를 통과하여 첫 번째 정답을 완성함

    네 개의 퀸을 놓은 뒤 dfs(4, 4)가 호출되면 row == n이므로 results.push_back(board)를 실행함. 이 조건은 마지막 행까지 배치가 끝났음을 의미하며, board[4]에는 접근하지 않음.

    push_back(board)는 현재 체스판의 복사본을 저장함. 이후 탐색 중인 board에서 퀸을 제거해도 이미 저장된 정답은 유지됨.

    탐색을 계속하면 [2, 0, 3, 1]도 찾게 되며, 모든 경우를 확인한 뒤 두 개의 체스판을 반환함. 각 배치는 행별 열 선택의 경로 하나에 대응하므로, 같은 배치가 중복 생성되지 않음.

    시간 및 공간 복잡도

    isValid(row, col, n)은 위쪽 행을 최대 row개 검사하므로 한 번에 O(n) 시간이 걸림. dfs() 한 호출에서는 열 n개를 시도하므로 후보 검사 비용의 상한은 O(n²)임.

    같은 열을 다시 선택할 수 없으므로, 깊이 r에서 가능한 부분 배치의 수는 최대 n! / (n - r)!개임. 모든 깊이의 부분 배치 수를 합하면 O(n!)이고, 대각선 조건이 실제 탐색 수를 더 줄임.

    따라서 **이 코드의 탐색 시간에 대한 느슨한 상한은 O(n² · n!)**으로 볼 수 있음. 정답 수를 S라고 하면 체스판을 복사해 저장하는 비용 O(S · n²)도 발생함. 열과 대각선을 별도 배열로 관리해 충돌을 O(1)에 확인하는 구현과는 검사 비용이 다름.

    보조 공간은 board와 visited에 O(n²), 재귀 호출 스택에 O(n)이 필요하므로 **출력 저장 공간을 제외하면 O(n²)**임. results의 저장 공간은 별도로 O(S · n²)임.

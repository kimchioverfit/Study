    207. Course Schedule

    핵심은 지금 들을 수 있는 과목부터 하나씩 수강하고, 모든 과목을 처리했는지 확인하는 것임. 아직 이수하지 않은 선수 과목 수를 indegree로 관리하면, 값이 0인 과목만 큐에 넣어 순서대로 처리할 수 있음. 이것이 Kahn의 위상 정렬 알고리즘임.

    1. 문제를 방향 그래프로 바꾸기

    과목은 0부터 numCourses - 1까지 있음. prerequisites[i] = [a, b]는 a를 듣기 전에 b를 먼저 들어야 함을 의미함. 따라서 간선 방향은 다음과 같음.

    입력 [a, b] → b를 먼저 이수 → a 수강 가능
간선 방향  → b → a

    예를 들어 [1, 0]이면 0 → 1임. 코드에서 pre는 선수 과목, post는 그 뒤에 들을 과목임.

    입력해석결과
    numCourses = 2, [[1,0]]0 다음에 1을 들으면 됨true
    numCourses = 2, [[1,0],[0,1]]0은 1을 기다리고, 1은 0을 기다림false

    두 번째처럼 서로를 기다리는 방향 사이클이 있으면 모든 과목을 이수할 수 없음. 따라서 이 문제는 방향 그래프의 사이클 유무를 판별하는 문제로 바꿔 볼 수 있음.

    1.1. 위상 정렬은 무엇을 정렬하는가

    위상 정렬(Topological Sort)은 방향 그래프의 모든 정점을 나열하되, 모든 간선 u → v에 대해 u가 v보다 먼저 나오도록 만드는 것임. 숫자의 크기로 정렬하는 것이 아니라, 선행 조건이 정한 순서를 지키는 것임.

    Course Schedule에서는 정점이 과목이고 간선이 선수 조건이므로, 위상 정렬 결과가 곧 가능한 수강 순서임. 예를 들어 0 → 1, 0 → 2라면 0은 반드시 먼저 나와야 하지만 1과 2 사이에는 순서 제약이 없음.

    나열한 순서위상 정렬 여부이유
    [0,1,2]가능함두 선수 조건을 모두 만족함
    [0,2,1]가능함1과 2의 상대 순서는 자유로움
    [1,0,2]불가능함0 → 1을 어김

    따라서 위상 정렬 결과는 여러 개일 수 있음. 번호가 작은 과목부터 듣는 것이 목적도 아님. 예를 들어 간선이 2 → 0이면 2를 0보다 먼저 처리해야 함.

    위상 정렬이 가능한 그래프는 DAG(Directed Acyclic Graph, 방향 비순환 그래프)임. 0 → 1 → 0처럼 사이클이 있으면 0이 1보다 먼저이면서 동시에 1이 0보다 먼저여야 하므로 유효한 순서를 만들 수 없음. 그래프가 여러 연결 요소로 나뉘어 있어도 전체에 방향 사이클이 없으면 위상 정렬이 가능함.

    1.2. 일반 BFS는 어떤 순서로 탐색하는가

    BFS(Breadth-First Search, 너비 우선 탐색)는 시작 정점에서 가까운 정점부터 탐색하는 방식임. 일반적으로 FIFO 큐를 사용하며, 간선을 따라 아직 발견하지 않은 이웃을 찾으면 방문 표시와 함께 큐에 넣음.

    1. 시작 정점을 방문 표시하고 큐에 넣음.
    2. 큐의 앞에서 정점 하나를 꺼냄.
    3. 아직 방문하지 않은 이웃을 방문 표시하고 큐의 뒤에 넣음.
    4. 큐가 빌 때까지 반복함.

    모든 간선의 비용이 같다면 시작점에서의 최소 간선 수, 즉 최단 거리 순서로 탐색됨. 여러 시작점을 동시에 큐에 넣는 다중 시작점 BFS도 가능하며, 이때는 가장 가까운 시작점까지의 거리가 기준임. 큐에 넣을 때 방문 표시하면 같은 정점의 중복 삽입을 막을 수 있음.

    하지만 시작점에서 가까운 순서와 모든 선수 과목을 먼저 끝내는 순서는 다름. 일반 BFS로 한 번 발견했다고 해서 그 과목의 모든 선수 조건을 만족한 것은 아님.

    1.3. 이 코드가 BFS 방식의 위상 정렬로 불리는 이유

    이 코드의 정확한 알고리즘 이름은 Kahn 알고리즘임. 진입 차수가 0인 정점을 꺼내고, 그 정점의 후속 정점 중 새롭게 진입 차수가 0이 된 정점을 처리 후보에 추가함.

    일반 BFS처럼 큐의 앞에서 꺼내고, 다음에 처리할 정점을 뒤에 넣는 형태로 구현했기 때문에 흔히 BFS 기반 위상 정렬이라고 부름. 다만 핵심은 큐 자체보다 큐에 넣는 조건이 indegree == 0이라는 점임.

    비교 항목일반 BFS이 코드의 Kahn 위상 정렬
    주된 목적도달 가능한 정점 탐색, 같은 비용 간선의 최단 거리 계산선행 관계를 지키는 전체 순서 구성, 사이클 판별
    초기 큐지정한 시작점 하나 또는 여러 개그래프 전체에서 진입 차수가 0인 모든 정점
    이웃을 넣는 조건아직 발견하지 않았음남은 선수 조건이 모두 없어져 진입 차수가 0이 됨
    관리하는 상태보통 visited, distance 등indegree, 처리한 정점 수
    사이클이 있을 때방문 표시로 재방문을 막으며 탐색할 수 있음사이클에 막힌 정점들을 처리하지 못함
    얻는 순서시작점까지의 최단 거리 기준 탐색 순서모든 간선의 출발점이 도착점보다 앞서는 순서

    위상 정렬은 만들어야 하는 순서의 조건이고, BFS는 탐색 방식이며, Kahn은 위상 정렬을 구하는 알고리즘임. 세 용어가 완전히 같은 뜻은 아님.

    1.4. 일반 BFS를 그대로 쓰면 틀리는 예제

    다음 그래프에서 과목 2는 0과 3을 모두 먼저 이수해야 함.

    numCourses = 4
prerequisites = [[1,0], [2,0], [3,1], [2,3]]

0 → 1 → 3 → 2
└──────────→ 2

    graph[0] = [1,2] 순서로 이웃을 확인한다고 가정하면, 일반 BFS는 0을 꺼내면서 1과 2를 모두 발견함. 하지만 2를 발견한 시점에는 선수 과목 3을 아직 이수하지 않았음.

    처리 단계일반 BFSKahn 알고리즘
    초기 큐[0][0], 초기 진입 차수는 [0,1,2,1]
    0 처리 후1과 2를 발견해 큐가 [1,2]가 됨1은 차수가 0, 2는 아직 1이므로 큐는 [1]임
    1 처리 후3을 발견해 큐가 [2,3]이 됨3의 차수가 0이 되어 큐가 [3]이 됨
    이후 처리2를 먼저 꺼내고 3을 꺼냄3을 처리해야 2의 차수가 0이 됨
    최종 순서[0,1,2,3][0,1,3,2]

    일반 BFS의 결과는 3 → 2 조건을 어김. 0에서 2까지의 최단 거리는 간선 하나이지만, 과목 2를 이수하려면 더 긴 선수 경로 0 → 1 → 3 → 2도 만족해야 하기 때문임.

    그래서 이 문제에서는 처음 발견했을 때 넣는 visited 조건을 그대로 가져오면 안 되고, 모든 선수 조건이 없어졌는지 indegree로 확인해야 함.

    1.5. 큐의 레벨을 학기처럼 볼 수 있는가

    각 과목을 이수하는 데 한 학기가 걸리고 한 학기에 과목을 제한 없이 들을 수 있다고 가정하면, Kahn 알고리즘을 레벨 단위로 묶어 해석할 수 있음.

    0 → 1 → 3 → 2 예제의 수강 단계
1학기: [0]
2학기: [1]
3학기: [3]
4학기: [2]

    한 단계가 시작할 때의 q.size()만큼만 처리하고, 그 과정에서 새로 들어온 정점은 다음 단계에서 처리하면 됨. 이때 과목의 단계는 모든 선수 과목이 끝난 다음 단계이므로 가장 늦게 끝나는 선수 과목의 영향을 받음. 일반 BFS의 최단 거리 레벨과는 다른 기준임.

    현재 샘플 코드는 이수 가능 여부만 필요하므로 학기별로 나누지 않고 count만 셈. 실제로 학기 수를 구하거나 한 학기에 들을 수 있는 과목 수에 제한이 생기면 그 요구에 맞는 추가 처리가 필요함.

    1.6. 위상 정렬을 하려면 반드시 BFS를 써야 하는가

    반드시 그럴 필요는 없음. 대표적인 방법으로 진입 차수를 사용하는 Kahn 방식과 DFS 종료 순서를 이용하는 방식이 있음.

    • Kahn 방식: 남은 진입 차수가 0인 정점을 계속 제거함. 현재 코드는 FIFO 큐를 사용하지만, 후보 중 무엇을 먼저 꺼낼지에 따라 스택이나 우선순위 큐를 사용할 수도 있음. 진입 차수 0 조건을 지키면 여전히 유효한 위상 순서를 얻을 수 있음.
    • DFS 방식: 후속 정점 탐색을 끝낸 뒤 현재 정점을 결과에 넣고, 최종 결과를 뒤집음. 이때 미방문·탐색 중·탐색 완료 상태를 구분하여 현재 재귀 경로로 돌아오는 간선이 있는지 확인해야 함. 사이클이 있으면 위상 순서를 반환할 수 없음.

    우선순위 큐를 사용하면 가능한 후보 중 번호가 가장 작은 과목부터 선택할 수 있지만, 힙 연산 비용이 추가됨. 현재 문제는 특정 순서나 가장 작은 순서를 요구하지 않으므로 단순 큐로 충분함.

    이 풀이의 핵심 연결: 수강 순서는 위상 정렬로 표현할 수 있음 → Kahn 알고리즘으로 진입 차수 0인 과목을 차례로 제거함 → 이를 FIFO 큐로 구현한 형태를 BFS 기반 위상 정렬이라고 부름.

    2. 샘플 코드

    LeetCode 제출용 코드임. 별도 C++ 파일로 실행할 때는 <vector>, <queue> 헤더와 std 네임스페이스 처리가 필요함.

    class Solution {
public:
    bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
        // 1. Count numbers of all node's indegree
        vector<int> indegree(numCourses, 0);
        vector<vector<int>> graph(numCourses);
        for(int i=0; i<prerequisites.size(); i++){
            int pre = prerequisites[i][1];
            int post = prerequisites[i][0];
            graph[pre].push_back(post);
            indegree[post]++;
        }

        // insert 0 indegree Node into queue
        queue<int> q;
        for(int i=0; i<indegree.size(); i++){
            if(indegree[i]==0) q.push(i);
        }

        int count = 0;

        while(!q.empty()){
            int temp = q.front();
            q.pop();
            count++;

            for(int i = 0; i < graph[temp].size(); i++){
                int next = graph[temp][i];

                indegree[next]--;

                if(indegree[next] == 0){
                    q.push(next);
                }
            }
        }

        return count == numCourses;
    }
};

    3. 각 자료구조가 나타내는 것

    변수의미예시
    graph[pre]pre를 선수 과목으로 요구하는 후속 과목 목록graph[0] = {1, 2}이면 0 이수 후 1과 2의 조건을 갱신함
    indegree[v]v의 아직 이수하지 않은 선수 과목 수2이면 선수 과목 두 개가 더 남아 있음
    q수강 조건을 모두 만족했고 아직 처리하지 않은 과목큐에 들어갈 때 진입 차수가 0임
    temp이번에 큐에서 꺼내 이수 처리하는 과목temp의 후속 과목들을 확인함
    nexttemp를 선수 과목으로 요구하는 과목temp를 이수했으므로 남은 조건 하나를 줄임
    count큐에서 꺼내 이수 처리한 과목 수마지막에 전체 과목 수와 비교함

    처음의 indegree는 원래 그래프의 진입 차수임. 처리가 진행될수록 의미는 아직 제거되지 않은 간선 수, 즉 남아 있는 선수 조건 수로 바뀜.

    4. 그래프와 진입 차수 만들기

    int pre = prerequisites[i][1];
int post = prerequisites[i][0];
graph[pre].push_back(post);
indegree[post]++;

    graph[pre].push_back(post)는 pre를 이수했을 때 어느 과목을 갱신할지 저장하는 코드임. indegree[post]++는 post에 선수 조건이 하나 더 있다는 뜻임. 진입 차수는 간선이 도착하는 post 쪽에 더함.

    다음 입력을 예제로 사용함.

    numCourses = 4
prerequisites = [[1,0], [2,0], [3,1], [3,2]]
    flowchart LR
    C0["0"] --> C1["1"]
    C0 --> C2["2"]
    C1 --> C3["3"]
    C2 --> C3

    구성 결과는 다음과 같음.

    과목graph[과목]초기 indegree의미
    0[1, 2]0바로 수강 가능함
    1[3]10을 먼저 들어야 함
    2[3]10을 먼저 들어야 함
    3[]21과 2를 모두 들어야 함

    graph는 후속 과목, indegree는 남은 선수 조건 수를 저장함. 둘을 함께 써야 어떤 조건을 누구에게서 제거할지 빠르게 찾을 수 있음.

    5. 처음 수강 가능한 모든 과목을 큐에 넣기

    queue<int> q;
for(int i=0; i<indegree.size(); i++){
    if(indegree[i]==0) q.push(i);
}

    선수 과목이 없는 과목은 다른 과목을 기다릴 필요가 없으므로 바로 후보가 됨. 예제에서는 indegree = [0, 1, 1, 2]이므로 q = [0]으로 시작함.

    시작 과목은 하나일 필요가 없음. 서로 독립적인 과목이 여러 개면 모두 큐에 들어감. prerequisites에 한 번도 등장하지 않는 과목도 진입 차수가 0이므로 처리 대상에 포함됨. 이것이 간선에 등장하는 과목만 검사하지 않고 전체 과목 번호를 순회하는 이유임.

    6. 과목 하나를 이수하고 후속 과목의 조건 갱신하기

    int temp = q.front();
q.pop();
count++;

    큐에서 꺼낸 과목은 이미 선수 조건을 만족했으므로 이수 처리할 수 있음. count는 이렇게 실제로 꺼내 처리한 과목 수임.

    int next = graph[temp][i];
indegree[next]--;
if(indegree[next] == 0){
    q.push(next);
}

    temp → next 간선은 next가 temp를 기다린다는 의미였음. temp를 이수했으므로 그 조건은 충족되었고, indegree[next]--로 남은 조건을 하나 줄임.

    이것을 간선 제거라고 부르지만 graph에서 원소를 실제로 삭제하지는 않음. 진입 차수만 줄여 제거 효과를 반영함.

    특히 indegree[next]가 2에서 1로 줄었다면 아직 다른 선수 과목이 남아 있음. 0이 된 순간에만 큐에 넣어야 함. 하나의 선수 과목을 이수했다고 후속 과목을 무조건 큐에 넣으면 조건을 어기게 됨.

    7. 성공 예제를 끝까지 따라가기

    큐는 왼쪽이 front임. 아래 진입 차수는 각 단계에서 후속 과목 갱신까지 마친 값임.

    단계꺼낸 temp갱신 내용indegree [0,1,2,3]갱신 후 큐count
    초기없음처음 0인 과목을 삽입함[0,1,1,2][0]0
    101과 2의 차수가 각각 1 → 0[0,0,0,2][1,2]1
    213의 차수가 2 → 1[0,0,0,1][2]2
    323의 차수가 1 → 0[0,0,0,0][3]3
    43후속 과목 없음[0,0,0,0][]4

    과목 3은 1을 이수했을 때 바로 들어가지 않고, 2까지 이수한 뒤에야 큐에 들어감. 마지막에는 count == numCourses, 즉 4 == 4이므로 true임.

    이 입력과 코드의 처리 순서는 0 → 1 → 2 → 3임. 0 → 2 → 1 → 3도 유효한 위상 순서임. 문제는 가능한지 여부만 요구하므로 실제 순서를 별도 벡터에 저장할 필요는 없음.

    8. 사이클이 있으면 왜 일부 과목이 남는가

    시작부터 아무 과목도 들을 수 없는 경우

    numCourses = 2, prerequisites = [[1,0],[0,1]]이면 0 → 1 → 0 사이클이 생김. 초기 진입 차수는 [1,1]이므로 큐가 처음부터 비어 있음. while은 실행되지 않고 count = 0이므로 false임.

    일부 과목은 들어도 전체 이수는 불가능한 경우

    numCourses = 4
prerequisites = [[1,0], [2,1], [1,2], [3,2]]

0 → 1 → 2 → 3
    ↑   │
    └───┘

    1과 2 사이에 사이클이 있음. 초기 진입 차수는 [0,2,1,1], 큐는 [0]임. 0을 처리하면 1의 진입 차수가 2에서 1로 줄지만 여전히 2를 기다려야 함. 큐는 비고 count = 1에서 멈춤.

    이때 과목 3은 사이클 자체에 속하지 않아도 사이클에 막힌 2를 기다리므로 처리되지 못함. 따라서 남아 있는 모든 노드가 사이클 위에 있다는 해석은 틀림. 남은 노드는 사이클에 속하거나 그 영향을 받는 노드일 수 있음.

    9. count == numCourses가 정답인 이유

    알고리즘이 유지하는 핵심 조건은 큐에 들어가는 과목의 남은 선수 조건이 0이라는 것임. 초기에는 실제 진입 차수가 0인 과목만 넣고, 이후에는 선수 과목을 이수할 때마다 차수를 줄여 0이 된 과목만 넣으므로 이 조건이 유지됨.

    • 모든 과목을 처리했다면: 각 과목을 처리할 당시 모든 선수 조건을 만족했음. 꺼낸 순서가 유효한 수강 순서이므로 true임.
    • 처리하지 못한 과목이 남았다면: 큐가 비었으므로 남은 모든 과목은 남은 선수 과목을 하나 이상 기다리고 있음. 그 선수 관계를 계속 거슬러 올라가면 유한한 노드 중 하나를 다시 만나게 되므로 방향 사이클이 존재함. 따라서 false임.

    방향 사이클이 없는 그래프를 DAG라고 부름. 위상 정렬이 가능한 조건은 DAG인 것임. 이 문제에서는 위상 순서 전체를 반환하는 대신 위상 정렬로 모든 노드를 제거할 수 있는지만 확인함.

    10. visited 배열이 없어도 되는 이유

    처리 중 진입 차수는 감소만 함. 초기 차수가 0인 과목은 초기 순회에서 한 번 들어가고, 양수였던 과목은 마지막 선수 조건이 제거되어 처음 0이 되는 순간 한 번 들어감.

    각 과목을 한 번 처리하면서 각 outgoing edge도 한 번 처리하므로 같은 조건을 중복 제거하지 않음. 따라서 이 구현은 큐 중복 삽입을 막기 위한 별도 visited 배열이 필요 없음.

    일반 BFS에서 거리 계산이나 방문 여부를 관리하는 것과 목적이 다름. 이 큐는 현재 모든 선행 조건을 만족한 작업 목록임.

    11. 시간 복잡도와 공간 복잡도

    $V$는 numCourses, $E$는 prerequisites.size()임.

    작업비용
    그래프와 진입 차수 초기화·구성$O(V+E)$
    초기 진입 차수 0 탐색$O(V)$
    큐에서 과목 처리각 과목 최대 한 번이므로 $O(V)$
    후속 간선 순회각 간선 최대 한 번이므로 $O(E)$
    전체 시간$O(V+E)$
    추가 공간graph, indegree, q를 합쳐 $O(V+E)$

    while 안에 for가 있어도 $O(VE)$가 아님. 매번 전체 간선을 확인하는 것이 아니라 graph[temp]만 확인하므로 전체 반복에 걸쳐 간선 하나를 최대 한 번 방문함.

    반대로 과목을 꺼낼 때마다 전체 prerequisites를 다시 훑어 후속 과목을 찾으면 최악의 경우 $O(VE)$가 될 수 있음. 인접 리스트를 만드는 이유가 여기에 있음.

    12. 자주 헷갈리는 점

    질문설명
    [a,b]인데 왜 b → a임?b가 a의 선수 과목이기 때문임
    큐가 비면 항상 성공임?실패해도 큐가 비므로 반드시 처리 개수를 확인해야 함
    처음 진입 차수 0인 과목이 있으면 성공임?다른 연결 요소나 뒤쪽에 사이클이 남을 수 있음
    연결되지 않은 과목은 어떻게 처리함?초기 진입 차수 0 탐색에서 큐에 들어감
    선수 조건이 하나도 없으면?모든 과목이 초기 큐에 들어가므로 true임
    후속 과목이 없는 노드도 세어야 함?큐에서 꺼내 이수한 과목이므로 count에 포함됨
    매번 전체 진입 차수를 다시 검사해야 함?temp의 후속 과목만 변하므로 그 과목들만 갱신하면 됨
    Union-Find로 풀 수 있음?일반적인 Union-Find 사이클 검사는 방향성을 구분하지 못하므로 이 문제에 그대로 적용할 수 없음

    DFS로도 방향 사이클을 찾을 수 있음. 이때 단순 방문 여부뿐 아니라 현재 재귀 경로에 있는 노드인지, 처리를 끝낸 노드인지를 구분해야 함. Kahn 방식은 재귀 없이 진입 차수와 처리 개수로 같은 가능 여부를 판별함.

    관련 개념: 위상 정렬 .

    정리: 선수 과목 → 후속 과목으로 간선을 만들고, 진입 차수가 0인 과목을 처리하면서 후속 과목의 진입 차수를 줄임. 마지막에 처리한 과목 수가 전체 과목 수와 같으면 모두 이수 가능함.

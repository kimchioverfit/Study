    547. Number of Provinces

    547. Number of Provinces

    핵심은 직접 또는 간접적으로 이어진 도시들을 한 묶음으로 보고, 묶음의 수를 세는 것임. 아직 방문하지 않은 도시에서 BFS를 한 번 시작하면 그 도시와 연결된 모든 도시를 방문할 수 있음. 따라서 새로운 BFS를 시작한 횟수 = province의 수임.

    1. Province는 무방향 그래프의 연결 요소임

    도시 n개가 있고, 두 도시 사이의 직접 연결 여부가 isConnected에 주어짐. A와 B가 직접 연결되고 B와 C가 직접 연결되면, A와 C도 간접적으로 같은 묶음에 속함.

    Province는 이렇게 직접 또는 간접적으로 연결된 도시를 모두 포함하는 하나의 묶음임. 그래프 용어로는 연결 요소(Connected Component)임. 다른 묶음까지 이어지는 경로는 없음.

    flowchart LR
    subgraph P1["Province 1"]
        A["도시 0"] --- B["도시 1"]
        B --- C["도시 2"]
    end
    subgraph P2["Province 2"]
        D["도시 3"]
    end

    위 그래프에서는 {0,1,2}가 하나의 province이고, 혼자 있는 {3}도 하나의 province임. 따라서 정답은 2임. 다른 도시와 연결되지 않은 도시도 자기 자신만으로 하나의 연결 요소를 이룸.

    2. 입력 행렬을 읽는 방법

    입력은 n × n 크기의 인접 행렬(Adjacency Matrix)임. isConnected[i][j]는 도시 i와 도시 j 사이의 직접 연결 여부를 나타냄.

    값 또는 조건의미
    isConnected[i][j] == 1도시 i와 도시 j가 직접 연결됨
    isConnected[i][j] == 0직접 연결은 없음. 다른 도시를 통한 간접 연결은 가능함
    isConnected[i][j] == isConnected[j][i]연결이 양방향이므로 행렬이 대칭임
    isConnected[i][i] == 1자기 자신에 해당하는 대각선 값임. 별도 도시나 province를 추가하는 값은 아님

    행렬의 칸 하나가 도시 하나인 것이 아님. 도시 개수는 n이고, n²개의 칸은 도시 쌍의 연결 정보를 저장함.

    예제 1

    isConnected = [
    [1, 1, 0],
    [1, 1, 0],
    [0, 0, 1]
]

도시 연결: 0 — 1     2
Province: {0,1}, {2}
정답: 2

    0번 행의 [1,1,0]은 도시 0이 자기 자신과 도시 1에 연결되어 있다는 의미임. 도시 2와는 직접 연결되지 않음. 예제에서는 다른 도시를 통해 2까지 가는 경로도 없으므로 별도의 province임.

    예제 2

    isConnected = [
    [1, 0, 0],
    [0, 1, 0],
    [0, 0, 1]
]

도시 연결: 0     1     2
Province: {0}, {1}, {2}
정답: 3

    대각선에만 1이 있으면 서로 다른 도시 사이의 연결이 하나도 없는 것임. 각 도시가 별도의 province가 됨.

    200. Number of Islands 와 이 문제는 모두 연결 요소의 개수를 세는 문제임. 다만 이웃을 찾는 방법이 다름.

    이웃을 찾는 방법상하좌우 칸을 확인함isConnected[city][next]가 1인 도시를 확인함

    이 문제에서 (i,j) 칸을 기준으로 상하좌우를 움직이면 도시 간 연결을 탐색하는 것이 아님. 도시 i를 꺼내면 i번째 행 전체를 읽어 연결된 도시 j를 찾는 것임.

    인접 행렬이 이미 주어져 있으므로 별도의 인접 리스트를 만들 필요는 없음. BFS가 도시 번호를 큐에 넣고, 해당 도시의 행에서 이웃을 찾으면 됨.

    4. BFS로 연결 요소를 세는 원리

    BFS(Breadth-First Search, 너비 우선 탐색)는 시작점에서 가까운 정점부터 큐를 이용해 탐색하는 방식임. 이 문제에서는 최단 거리를 구할 필요 없이, 시작 도시에서 어디까지 도달할 수 있는지를 모두 확인하는 데 사용함.

    한 번의 BFS로는 시작 도시가 속한 province만 탐색할 수 있음. 다른 province는 연결된 경로가 없으므로 같은 BFS로 방문할 수 없음. 그래서 바깥 반복문이 모든 도시를 검사해야 함.

    1. visited를 모두 0으로 초기화함.
    2. 도시 start를 아직 방문하지 않았다면 새로운 province를 발견한 것이므로 provinces++함.
    3. start를 방문 표시하고 큐에 넣음.
    4. 큐에서 도시를 꺼내 그 도시의 행 전체를 확인함.
    5. 직접 연결되어 있고 아직 방문하지 않은 도시를 방문 표시한 뒤 큐에 넣음.
    6. 큐가 비면 해당 province 탐색이 끝난 것임. 바깥 반복문에서 다음 미방문 도시를 찾음.

    이전에 방문한 도시라면 이미 어떤 province에 포함되었으므로 다시 세지 않음. 도시마다 1을 더하는 것이 아니라, 아직 탐색하지 않은 묶음에서 탐색을 시작할 때만 1을 더함.

    5. BFS 샘플 코드

    LeetCode 제출용 코드임. 별도 C++ 파일에서 실행하려면 <vector>, <queue>와 std 네임스페이스 처리가 필요함.

    class Solution {
public:
    int findCircleNum(vector<vector<int>>& isConnected) {
        int n = static_cast<int>(isConnected.size());
        vector<int> visited(n, 0);
        int provinces = 0;

        for (int start = 0; start < n; start++) {
            if (visited[start]) continue;

            // 미방문 도시에서 시작하는 BFS 하나가 province 하나임.
            provinces++;
            queue<int> q;
            visited[start] = 1;
            q.push(start);

            while (!q.empty()) {
                int city = q.front();
                q.pop();

                // city와 직접 연결된 모든 도시를 찾음.
                for (int next = 0; next < n; next++) {
                    if (isConnected[city][next] == 1 && !visited[next]) {
                        visited[next] = 1;
                        q.push(next);
                    }
                }
            }
        }

        return provinces;
    }
};
    코드역할
    for (int start = 0; start < n; start++)서로 다른 province까지 빠짐없이 확인함
    if (visited[start]) continue이미 탐색한 province를 다시 세지 않음
    provinces++새로운 연결 요소를 하나 셈
    visited[start] = 1; q.push(start)시작 도시도 방문 표시한 뒤 큐에 넣음
    isConnected[city][next] == 1두 도시 사이에 직접 연결이 있는지 확인함
    !visited[next]자기 자신과 이미 발견한 도시의 재삽입을 막음

    6. 간접 연결이 있는 예제를 끝까지 따라가기

    다음 행렬은 앞의 그림과 같은 0 — 1 — 2와 고립된 도시 3을 나타냄.

    isConnected = [
    [1, 1, 0, 0],
    [1, 1, 1, 0],
    [0, 1, 1, 0],
    [0, 0, 0, 1]
]

    0과 2는 직접 연결되어 있지 않아서 isConnected[0][2] == 0임. 하지만 도시 1을 거쳐 도달할 수 있으므로 같은 province임.

    큐는 왼쪽이 front이며, visited는 도시 [0,1,2,3] 순서임. 방문 표시는 큐에 넣을 때 이루어짐.

    단계수행 내용수행 후 큐visitedprovinces
    초기아직 탐색하지 않음[][0,0,0,0]0
    start = 0미방문이므로 1을 더하고 0을 큐에 넣음[0][1,0,0,0]1
    city = 00번 행에서 도시 1을 발견함[1][1,1,0,0]1
    city = 11번 행에서 도시 2를 발견함[2][1,1,1,0]1
    city = 2새로운 도시가 없어 첫 BFS가 끝남[][1,1,1,0]1
    start = 1, 2이미 방문했으므로 건너뜀[][1,1,1,0]1
    start = 3미방문이므로 1을 더하고 3을 큐에 넣음[3][1,1,1,1]2
    city = 3새로운 도시가 없어 두 번째 BFS가 끝남[][1,1,1,1]2

    도시는 총 4개를 처리했지만, BFS를 새로 시작한 횟수는 2번이므로 정답은 2임. 행렬에서 1의 개수를 세거나 큐에서 꺼낸 횟수를 반환하면 정답이 아님.

    7. 방문 표시는 왜 큐에 넣을 때 하는가

    삼각형처럼 0 — 1, 0 — 2, 1 — 2가 모두 연결된 경우를 생각하면 됨. 도시 0을 처리할 때 도시 1과 2가 큐에 들어감.

    도시 2를 큐에 넣고도 방문 표시하지 않으면, 도시 1을 처리할 때 도시 2가 아직 미방문인 것처럼 보여 다시 넣을 수 있음. 큐에 들어갈 때 표시하면 발견한 순간부터 해당 도시가 탐색 대상으로 예약되었다는 사실을 공유할 수 있음.

    visited[next] = 1;
q.push(next);

    시작 도시에도 같은 규칙을 적용해야 함. 대각선 값은 1이지만 시작 도시는 이미 방문 표시되어 있으므로 자기 자신을 다시 큐에 넣지 않음. 반대 방향 간선을 통해 이전 도시로 돌아오는 것도 같은 조건으로 막힘.

    꺼낼 때 방문 표시하는 구현도 별도의 중복 처리 방지 조건을 두면 가능하지만, 현재 구현은 삽입 시 표시하여 각 도시가 큐에 최대 한 번만 들어가도록 함.

    8. BFS 시작 횟수가 정답인 이유

    두 가지 사실을 확인하면 됨.

    하나의 BFS가 방문하는 도시는 모두 같은 province임. 시작 도시에서 출발해 연결이 1인 간선만 따라가므로, 큐에 들어간 모든 도시는 시작 도시와 직접 또는 간접적으로 연결되어 있음. 다른 province로 넘어갈 수 없음.

    하나의 BFS가 끝나면 그 province의 모든 도시를 방문함. 같은 province에 미방문 도시가 남아 있다고 가정하면 시작 도시에서 그 도시까지 경로가 있음. 그 경로에서 처음 미방문 도시로 넘어가는 간선을 생각하면, 바로 앞의 방문 도시는 자신의 행을 확인할 때 그 도시를 발견했어야 하므로 모순임.

    따라서 바깥 반복문에서 미방문 도시를 만나면, 그 도시는 앞에서 탐색한 province에 속하지 않음. 새 province를 정확히 한 번 세게 되므로 마지막 provinces가 전체 연결 요소의 수임.

    9. 시간 복잡도와 공간 복잡도

    도시 개수를 n이라고 할 때 BFS 풀이의 복잡도는 다음과 같음.

    작업비용
    바깥 반복문에서 모든 도시 확인$O(n)$
    큐에 넣고 꺼내기각 도시 최대 한 번이므로 전체 $O(n)$
    한 도시의 이웃 확인해당 행의 n개 칸을 확인하므로 $O(n)$
    모든 도시의 이웃 확인n개 행을 한 번씩 확인하므로 $O(n^2)$
    전체 시간$O(n^2)$
    추가 공간visited와 큐를 합쳐 $O(n)$

    for 안에 while이 있고 그 안에 또 for가 있어도 $O(n^3)$이 아님. 바깥 반복문이 방문한 도시를 건너뛰고, 방문 표시로 큐 중복 삽입을 막으므로 모든 BFS를 합쳐 city를 꺼내는 횟수가 n번임. 각 도시를 꺼낼 때 행 하나, 즉 n개 칸을 확인하여 총 n²칸을 확인함.

    일반적인 인접 리스트 BFS의 시간은 $O(V+E)$임. 여기서는 이웃 목록 대신 인접 행렬의 행 전체를 읽기 때문에 연결이 적어도 n²개의 칸을 확인함. 입력 행렬 자체의 $O(n^2)$ 저장 공간은 추가 공간 계산에서 제외함.

    10. DFS로도 같은 연결 요소를 셀 수 있음

    DFS(Depth-First Search, 깊이 우선 탐색)는 한 경로를 따라 깊게 탐색한 뒤 돌아오는 방식임. 연결 요소에 속한 도시를 모두 찾는 목적은 BFS와 같으므로, 바깥 반복문의 원리는 그대로 사용함.

    class Solution {
private:
    void dfs(int city, const vector<vector<int>>& isConnected,
             vector<int>& visited) {
        visited[city] = 1;
        int n = static_cast<int>(isConnected.size());

        for (int next = 0; next < n; next++) {
            if (isConnected[city][next] == 1 && !visited[next]) {
                dfs(next, isConnected, visited);
            }
        }
    }

public:
    int findCircleNum(vector<vector<int>>& isConnected) {
        int n = static_cast<int>(isConnected.size());
        vector<int> visited(n, 0);
        int provinces = 0;

        for (int city = 0; city < n; city++) {
            if (visited[city]) continue;
            provinces++;
            dfs(city, isConnected, visited);
        }

        return provinces;
    }
};

    재귀 함수에 들어오면 먼저 방문 표시함. 행렬과 방문 배열은 참조로 넘겨 모든 재귀 호출이 같은 방문 상태를 공유하도록 함. 값으로 복사하면 불필요한 복사가 생기고, 방문 상태의 갱신도 호출 사이에 제대로 공유되지 않음.

    시간은 $O(n^2)$, 추가 공간은 방문 배열과 최악 $O(n)$ 깊이의 재귀 스택을 합쳐 $O(n)$임. 같은 연결 요소 안에서 방문하는 순서는 달라도 최종 province 수는 같음.

    11. Union-Find로 연결된 도시를 합치는 풀이

    Union-Find는 각 도시가 어느 집합에 속하는지 관리하는 자료구조임. 처음에는 모든 도시가 별도의 집합이므로 provinces = n으로 시작함. 연결된 두 도시가 서로 다른 집합에 속할 때만 두 집합을 합치고 1을 뺌.

    무방향 그래프이므로 isConnected[i][j]와 isConnected[j][i]는 같은 연결 정보임. 대각선과 중복 방향을 제외한 j > i 부분만 확인하면 됨.

    class Solution {
private:
    int findRoot(int city, vector<int>& parent) {
        if (parent[city] != city) {
            parent[city] = findRoot(parent[city], parent);
        }
        return parent[city];
    }

public:
    int findCircleNum(vector<vector<int>>& isConnected) {
        int n = static_cast<int>(isConnected.size());
        vector<int> parent(n);
        vector<int> size(n, 1);
        for (int city = 0; city < n; city++) {
            parent[city] = city;
        }

        int provinces = n;
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                if (isConnected[i][j] == 0) continue;

                int rootA = findRoot(i, parent);
                int rootB = findRoot(j, parent);
                if (rootA == rootB) continue;

                // 작은 집합을 큰 집합에 붙임.
                if (size[rootA] < size[rootB]) {
                    int temp = rootA;
                    rootA = rootB;
                    rootB = temp;
                }
                parent[rootB] = rootA;
                size[rootA] += size[rootB];
                provinces--;
            }
        }

        return provinces;
    }
};

    findRoot에서 경로 압축을 적용하고, 합칠 때는 집합 크기를 기준으로 작은 트리를 큰 트리에 붙임. 바로 위 부모가 같은지 대신, 최종 대표인 root가 같은지 비교해야 함.

    삼각형 0 — 1 — 2 — 0에서는 간선이 세 개지만 집합을 합치는 횟수는 두 번임. 마지막 간선은 이미 같은 집합 안의 연결이므로 provinces--를 실행하지 않음. 따라서 도시 수 - 간선 수로 정답을 계산할 수는 없음.

    상삼각의 n(n−1)/2개 칸을 확인하고 연결된 쌍에 대해 find를 수행함. 서로 다른 도시 사이의 연결 수를 E라고 하면 시간은 $O(n^2+E\alpha(n))$로 표현할 수 있으며, 흔히 느슨한 상한으로 $O(n^2\alpha(n))$이라고 씀. $\alpha$는 역 아커만 함수이고 두 최적화를 적용한 집합 연산의 분할 상환 비용에 나타남. 추가 공간은 $O(n)$임.

    구하는 것연결 요소의 개수모든 선수 조건을 만족하는 이수 순서의 존재 여부
    큐에 넣는 조건직접 연결되어 있고 아직 발견하지 않은 도시남은 진입 차수가 0이 된 과목
    세는 횟수미방문 도시에서 새로운 탐색을 시작한 횟수큐에서 꺼내 이수 처리한 과목 수
    사이클있어도 같은 province로 묶으면 됨있으면 전체 이수가 불가능함

    547에서는 한 간선을 통해 처음 발견한 도시를 바로 방문 대상으로 삼아도 됨. 선행 작업을 모두 마쳐야 하는 문제가 아니기 때문임. 삼각형처럼 사이클이 있어도 visited로 재방문을 막으면 정상적으로 탐색할 수 있음. 이 문제를 푸는 데 진입 차수나 위상 정렬은 필요하지 않음.

    13. 풀이 선택과 자주 헷갈리는 점

    방법핵심이 문제에서의 특징
    BFS미방문 도시에서 큐로 연결 요소 전체를 탐색함재귀 없이 구성할 수 있음
    DFS미방문 도시에서 재귀 또는 스택으로 탐색함재귀 구현이 짧지만 호출 스택을 사용함
    Union-Find연결된 도시의 집합을 합침서로 다른 집합을 합쳤을 때만 개수를 줄임

    세 방법 모두 가능하며, 인접 행렬과 연결 요소 개념을 익히려면 BFS나 DFS로 시작하기 좋음. 연결을 하나씩 추가하면서 집합을 관리하는 문제로 확장하면 Union-Find의 역할이 더 드러남.

    Hungarian Algorithm

    Hungarian Algorithm (헝가리안 알고리즘)

    결론부터 아주 쉽게: “n명을 n개 일에 1:1로 배정할 때, 총비용이 최소인 짝을 찾는 알고리즘” 임. 모든 경우를 따지면 $n!$ 인데, 이 알고리즘은 $O(n^3)$ 에 끝냄. 핵심 아이디어 하나 — 어떤 행(또는 열) 전체에서 같은 수를 빼도 최적 배정은 바뀌지 않음.

    1. 무슨 문제인가 — 할당 문제(Assignment Problem)

    사람 3명에게 일 3개를 하나씩 맡김. 사람마다 일마다 드는 비용이 다름.

    ABC
    민수428
    지현437
    태훈316

    조건은 두 가지뿐임.

    • 한 사람은 일 하나만
    • 한 일은 한 사람만

    이때 합이 최소인 배정을 찾는 것임.

    그냥 다 해보면 안 되나

    3×3이면 배정이 $3! = 6$ 가지라 전부 계산해도 됨.

    민수→A 지현→B 태훈→C   합 13
민수→A 지현→C 태훈→B   합 12   ← 최소
민수→B 지현→A 태훈→C   합 12   ← 최소
민수→B 지현→C 태훈→A   합 12   ← 최소
민수→C 지현→A 태훈→B   합 13
민수→C 지현→B 태훈→A   합 14

    문제는 $n!$ 이 금방 터진다는 것임.

    $n$$n!$$n^3$
    5120125
    103,628,8001,000
    20약 $2.4\times10^{18}$8,000
    100—1,000,000

    $n = 20$ 이면 완전탐색은 이미 불가능하고, 헝가리안은 8,000번 수준임.

    2. 핵심 아이디어

    한 행 전체에서 같은 수를 빼도, 최적 배정은 그대로임.

    당연함 — 민수는 어차피 일 하나를 맡고, 그게 무엇이든 뺀 만큼 똑같이 깎임. 순위가 안 바뀜. 열도 마찬가지임.

    이걸 반복해서 행렬에 0을 최대한 많이 만들고, 0끼리만 골라서 1:1 배정이 되면 그게 최적임. 0은 “그 행/열 기준으로 가장 싼 선택"이라는 뜻이기 때문임.

    3. 절차

    1단계 — 행마다 최솟값 빼기

    각 행에서 2, 3, 1을 뺌.

    ABC
    민수206
    지현104
    태훈205

    2단계 — 열마다 최솟값 빼기

    각 열에서 1, 0, 4를 뺌.

    ABC
    민수102
    지현000
    태훈101

    여기서 0만 골라 1:1 배정이 되면 끝남. 그런데 이 경우는 안 됨 — 민수도 태훈도 0이 B에만 있어서 둘 중 하나는 자리가 없음.

    3단계 — 0을 전부 덮는 최소 개수의 선 긋기

    가로줄·세로줄을 그어 0을 전부 덮되, 선을 최대한 적게 씀.

            A    B    C
민수     1  │ 0 │  2
지현   ──0────0────0──   ← 지현 행
태훈     1  │ 0 │  1
             ↑
            B 열

    선 2개로 충분함. 선의 개수가 $n = 3$ 보다 적으면 아직 최적이 아님.

    선 개수가 $n$ 이 되는 순간이 끝나는 시점임. 선 개수 = 0만으로 만들 수 있는 1:1 배정의 최대 크기이기 때문임 (쾨니그 정리).

    4단계 — 조정

    덮이지 않은 값 중 최솟값을 찾음. 여기서는 $\{1, 1, 1, 2\}$ 중 1.

    • 덮이지 않은 칸: 빼기
    • 선이 두 번 지나간 칸: 더하기
    • 한 번 덮인 칸: 그대로
    ABC
    민수001
    지현010
    태훈000

    이제 0만으로 1:1 배정이 됨. 2단계로 돌아가 될 때까지 반복하는 구조임.

    결과

    0만 골라 만들 수 있는 배정이 3가지 나옴.

    배정원래 비용
    민수→A, 지현→C, 태훈→B4 + 7 + 1 = 12
    민수→B, 지현→A, 태훈→C2 + 4 + 6 = 12
    민수→B, 지현→C, 태훈→A2 + 7 + 3 = 12

    전부 12이고, §1의 완전탐색 결과와 일치함. 최적해가 여러 개일 수 있음이 여기서 드러남.

    4. 알아둘 것

    최대화 문제

    이익을 최대화하고 싶으면 부호를 뒤집거나, 행렬 전체 최댓값에서 각 값을 빼서 비용 문제로 바꾼 뒤 그대로 돌리면 됨.

    정사각형이 아닐 때

    행과 열 개수가 다르면 더미 행/열을 0으로 채워 정사각형으로 만듦. 더미에 배정된 쪽은 “아무것도 안 맡음"이 됨.

    DETR 에서 정답 개수보다 쿼리가 많을 때 정답 쪽을 ∅(no object)로 채우는 것이 정확히 이 처리임.

    복잡도

    구현복잡도
    완전탐색$O(n!)$
    기본 헝가리안$O(n^4)$
    Jonker-Volgenant 등 개선판$O(n^3)$

    보통 “헝가리안 $O(n^3)$” 이라고 하면 개선판을 가리킴. scipy 구현도 이쪽임.

    비용 행렬만 주면 됨

    이 알고리즘은 비용이 어디서 왔는지 모름. 거리든, 확률이든, 두 값을 섞은 것이든 상관없이 $n \times n$ 숫자판만 주면 됨. 딥러닝에서 쓰기 편한 이유가 이것임.

    5. 직접 구현하지 말 것

    실무에서는 scipy 한 줄이면 됨.

    import numpy as np
from scipy.optimize import linear_sum_assignment

cost = np.array([
    [4, 2, 8],
    [4, 3, 7],
    [3, 1, 6],
])

row_idx, col_idx = linear_sum_assignment(cost)

print(list(zip(row_idx, col_idx)))   # [(0, 0), (1, 2), (2, 1)]
print(cost[row_idx, col_idx].sum())  # 12

# 최대화 문제면 부호만 뒤집음
row_idx, col_idx = linear_sum_assignment(cost, maximize=True)

    linear_sum_assignment가 Jonker-Volgenant 계열이라 직접 짠 $O(n^4)$ 구현보다 빠르고, 직사각형 행렬도 그대로 받음.

    위 예제는 최적해가 3가지라 구현에 따라 다른 짝이 나올 수 있음. 총합 12는 같음.

    6. 어디에 쓰이나

    고전적으로는 작업 배정, 배송 기사–주문 매칭, 선수–포지션 배정 같은 운영 문제에 쓰였음.

    요즘은 딥러닝 쪽에서 더 자주 보임.

    쓰임비용 행렬의 내용
    DETR — 집합 예측예측 N개 × 정답 N개. 클래스 확률 + 박스 거리(L1 + GIoU)
    Mask2Former · EoMT쿼리 × 정답 마스크
    다중 객체 추적 (MOT)이전 프레임 추적 대상 × 현재 프레임 검출 결과

    DETR 이 대표적임. 검출 결과 100개와 정답을 1:1로 짝지어야 “같은 물체를 두 번 예측하는 것"에 벌을 줄 수 있는데, 그 짝짓기가 바로 이 알고리즘임. 덕분에 NMS 같은 후처리 없이 학습만으로 중복을 없앰.

    학습 루프 안에서 매 스텝마다 돌리므로 속도가 중요함. N=100이면 100×100 행렬이고, $O(n^3)$ 라 감당됨.

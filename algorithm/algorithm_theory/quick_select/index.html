Quick Select

정렬되지 않은 배열에서 k번째로 작은(또는 큰) 원소를 찾는 알고리즘. 전체를 정렬하면 O(N log N)이지만, Quick Select는 평균 O(N) 에 찾는다.

Quick Sort의 partition 아이디어를 그대로 쓰되, 양쪽을 모두 재귀하지 않고 k가 속한 쪽 한 곳만 파고드는 것이 핵심 차이다.

1. 아이디어

Quick Sort의 partition을 한 번 수행하면 pivot은 자기의 최종 정렬 위치에 놓인다.

partition 후:  [ pivot보다 작은 것들 ]  pivot  [ pivot보다 큰 것들 ]
                                        ↑
                                  인덱스 p 확정
  • p == k → pivot이 곧 k번째 원소. 끝
  • p > k → 왼쪽 구간만 다시 탐색
  • p < k → 오른쪽 구간만 다시 탐색

Quick Sort는 양쪽을 모두 재귀해서 O(N log N)이지만, Quick Select는 매번 한쪽만 보므로 평균적으로 N + N/2 + N/4 + ... = 2N → O(N).

2. 구현 (C++)

#include <vector>
#include <algorithm>

// [lo, hi] 구간을 arr[hi]를 pivot으로 분할하고, pivot의 최종 위치를 반환
int partition(std::vector<int>& arr, int lo, int hi) {
    int pivot = arr[hi];
    int i = lo;                       // pivot보다 작은 원소들이 쌓이는 경계
    for (int j = lo; j < hi; j++) {
        if (arr[j] < pivot)
            std::swap(arr[i++], arr[j]);
    }
    std::swap(arr[i], arr[hi]);       // pivot을 경계 위치로
    return i;
}

// k는 0-indexed: k=0이면 최솟값, k=n-1이면 최댓값
int quick_select(std::vector<int>& arr, int k) {
    int lo = 0, hi = (int)arr.size() - 1;
    while (lo < hi) {
        int p = partition(arr, lo, hi);
        if (p == k) return arr[p];
        else if (p > k) hi = p - 1;   // 왼쪽만
        else lo = p + 1;              // 오른쪽만
    }
    return arr[lo];
}
  • 재귀 없이 while 루프로 쓸 수 있다 (한쪽만 파고들기 때문에 tail-call과 동일한 구조)
  • 주의: 원본 배열이 부분적으로 섞인다 (in-place partition). 원본 보존이 필요하면 복사본으로 수행

3. 시간복잡도

케이스복잡도조건
평균O(N)pivot이 적당히 중간을 나눌 때
최악O(N²)이미 정렬된 배열 + 끝 원소 pivot처럼 매번 최솟/최댓값이 pivot일 때
공간O(1)in-place, 루프 구현 시

최악을 피하는 방법:

  • 랜덤 pivot: pivot을 무작위로 골라 최악 케이스가 입력에 의해 강제되지 않게 함 — 실전에서 가장 흔한 선택
  • Median of Medians: 5개씩 묶어 중앙값들의 중앙값을 pivot으로 선택 → 최악까지 O(N) 보장. 다만 상수가 커서 실전에선 랜덤 pivot이 보통 더 빠르다

4. std::nth_element

C++ 표준 라이브러리에 Quick Select가 이미 들어있다 (introselect: quick select + 최악 방어).

std::vector<int> v = {7, 4, 6, 3, 9, 1};
std::nth_element(v.begin(), v.begin() + 2, v.end());
// v[2]에 3번째로 작은 원소(0-indexed로 k=2)가 확정됨
// 왼쪽엔 그보다 작거나 같은 것들, 오른쪽엔 크거나 같은 것들 (내부 순서는 미정)
int kth = v[2];
  • 평균 O(N). “k번째 값만 필요한데 sort를 쓰고 있다면” 이걸 먼저 떠올릴 것
  • 중앙값 구하기: nth_element(v.begin(), v.begin() + v.size()/2, v.end())

5. 언제 쓰나

  • k번째 최솟값/최댓값, 중앙값: 전체 정렬이 필요 없을 때
  • 상위 k개 구하기: nth_element로 경계를 확정한 뒤 앞 k개만 사용 (순서 필요하면 그 k개만 정렬 → O(N + k log k))
  • 스트리밍으로 데이터가 계속 들어오는 상황이라면 Quick Select보다 힙 기반 top-k가 적합 (Quick Select는 전체 데이터가 메모리에 있어야 함)
문제도구
전체 순서가 필요sort — O(N log N)
k번째 하나만 필요 (배열 보유)quick select / nth_element — 평균 O(N)
top-k, 데이터가 스트림min heap 크기 k 유지 — O(N log k)

Error Pointer

3종의 Error pointer

아래의 3가지 포인터 종류를 숙지해야 디버깅이 쉬워짐

종류정의원인접근 시 결과예시 코드
Dangling Pointer
(댕글링 포인터)		이미 해제되었거나 범위를 벗어난 메모리를 가리키는 포인터- free() 후 포인터 그대로 둠
- 함수 종료 후 지역 변수 주소 사용		Undefined Behavior (쓰레기 값, crash, 보안 취약점)c<br>int *p = malloc(sizeof(int));<br>free(p);<br>*p = 10; // ❌<br>
NULL Pointer어떤 것도 가리키지 않는 포인터 (주소가 0)- int *p = NULL;
- free() 후 p=NULL;		접근 시 무조건 crash (segfault) → 오류 조기 발견 가능c<br>int *p = NULL;<br>*p = 10; // ❌ 즉시 crash<br>
Wild Pointer
(야생 포인터)		초기화되지 않아 쓰레기 주소를 가진 포인터- 포인터 선언 후 초기화 안 함접근 시 Undefined Behavior (댕글링보다 더 위험)c<br>int *p; // 초기화 X<br>*p = 10; // ❌<br>

dangling pointer → segmentation fault → 보안 취약점

1. 댕글링 포인터에서 시작

#include <stdio.h>
#include <stdlib.h>

int main() {
    int *p = malloc(sizeof(int));
    *p = 42;

    free(p);   // 메모리 해제

    printf("%d\n", *p); // ❌ 댕글링 포인터 접근

    return 0;
}

free(p)로 OS에 메모리를 반환했지만,

p에는 여전히 예전 주소가 남아 있음.

이제 그 주소는 “내 것"이 아님 → 접근하면 위험.

2. 세그멘테이션 폴트 (Segmentation Fault) 발생

OS는 프로세스마다 메모리 접근 권한을 철저히 관리함.

해제된 메모리 주소를 접근하려 하면, 그 주소가 다른 영역에 속할 가능성이 높음.

접근 권한이 없는 영역이면 OS가 즉시 프로세스 강제 종료 → Segmentation fault 발생.

💡 하지만 운 나쁘게:

해당 주소가 아직 접근 가능한 영역이면, 세그폴트 없이 그냥 잘못된 값을 읽거나 씀. (데이터 오염)

이 경우 버그가 조용히 숨어 있다가 나중에 문제 터짐 → 디버깅 지옥.

3. 보안 취약점으로 이어지는 과정

댕글링 포인터가 해제된 heap 공간을 가리키는 경우,

다른 코드가 그 heap 공간을 재사용할 수 있다.

예를들어, 공격자가 strcpy(evil, “root; rm -rf /”); 이런걸 넣으면 그냥 골로가는거임

4. 안전 대책

  • free() 후 즉시 NULL로 초기화
  • 여러 포인터가 동일 메모리를 가리키면 참조 관리 철저히
  • 메모리 해제 전에 모든 참조를 끊고, 참조 수를 관리(참조 카운팅)
  • C++이라면 스마트 포인터(unique_ptr, shared_ptr) 사용
  • 보안에 민감한 시스템은 ASLR(Address Space Layout Randomization), Heap poisoning 활성화

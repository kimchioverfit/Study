    Package and Setup

    Package와 setup.py

    1. Package — 모듈들의 묶음

    모듈(module) 은 .py 파일 하나, 패키지(package) 는 그 모듈들을 묶은 디렉토리임.

    mypackage/
├── __init__.py       ← 이 파일이 있어야 "패키지"로 인식됨
├── core.py
└── subpkg/
    ├── __init__.py
    └── helper.py
    • __init__.py: 디렉토리를 단순 폴더가 아니라 import 가능한 패키지로 표시하는 파일. 비어있어도 되고, 하위 모듈을 미리 import해 from mypackage import *처럼 쓰기 편하게 하는 역할도 함 (Python 3.3+는 없어도 namespace package로 동작하지만 관례상 명시적으로 둠)
    import mypackage
from mypackage.subpkg import helper

    2. setup.py — 설치 가능하게 만드는 설명서

    내가 만든 패키지를 pip install로 설치하거나 PyPI에 배포하려면 “어떻게 설치해야 하는지"를 적어둔 파일이 필요함. 그게 setup.py.

    # setup.py
from setuptools import setup, find_packages

setup(
    name="mypackage",
    version="0.1.0",
    packages=find_packages(),      # 하위 패키지들을 자동으로 찾음
    install_requires=["numpy>=1.20", "requests"],
    python_requires=">=3.8",
)
    • pip install . — 설치, pip install -e . — editable install (코드 수정이 바로 반영, 개발 중에 사용)
    • python setup.py sdist bdist_wheel — 배포용 패키지(.tar.gz, .whl) 생성 → PyPI 업로드
    • 패키지 이름, 버전, 의존성, 포함할 하위 패키지, 실행 스크립트(entry_points) 등 “설치 메타데이터"를 정의

    3. pyproject.toml — 요즘의 대체재

    최근(PEP 517/518 이후)에는 setup.py 대신 pyproject.toml 하나로 같은 걸 선언하는 방식이 표준으로 자리잡고 있음.

    # pyproject.toml
[build-system]
requires = ["setuptools>=61.0"]
build-backend = "setuptools.build_meta"

[project]
name = "mypackage"
version = "0.1.0"
dependencies = ["numpy>=1.20", "requests"]
    • setup.py는 파이썬 코드라 임의 로직(동적 버전 읽기 등)을 넣을 수 있지만, 그만큼 설치 시 임의 코드가 실행된다는 보안/재현성 문제가 있었음
    • pyproject.toml은 순수 선언형(TOML)이라 더 안전하고, poetry/flit/hatch 등 여러 빌드 도구가 공통으로 이해할 수 있는 표준 포맷
    • 신규 프로젝트는 pyproject.toml 권장, 기존 라이브러리 다수는 여전히 setup.py 사용

    정리

    개념역할

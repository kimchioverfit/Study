# Linux의 경우는?

리눅스는 모놀리식 커널.

| 구분         | 장점                                                                                   | 단점                                                                      |
| ---------- | ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| **성능**     | - 모든 커널 서비스가 같은 주소 공간에서 실행되어 **함수 호출로 직접 통신** → 빠른 시스템 호출 처리 속도<br>- 모듈 간 데이터 교환이 간단 | - 커널 크기가 커질수록 **캐시 미스 증가** 가능<br>- 커널 전체를 다시 빌드해야 하는 경우가 많음             |
| **구조**     | - 구현이 비교적 단순 (처음 설계는 명확)<br>- 드라이버, 파일시스템, 메모리관리 등 모든 기능이 하나의 큰 커널에 통합               | - 한 부분의 버그가 **커널 전체를 다운**시킬 수 있음<br>- 코드량 증가로 유지보수 어려움                  |
| **안정성/보안** | - 권한 관리가 일관적 (모든 모듈이 커널 모드)                                                          | - 하나의 모듈 결함이 전체 시스템에 영향 (fault isolation 부족)<br>- 보안 취약점이 커널 전역으로 확산 가능 |
| **확장성**    | - 동적 로딩(Loadable Kernel Module, LKM) 기능 지원 시 모듈 추가/제거 가능                             | - 마이크로커널에 비해 구조적 확장이 어려움 (핵심 부분 수정 시 전체 커널 영향)                          |
| **디버깅**    | - 단일 주소 공간에서 추적 가능                                                                   | - 문제 원인 분리 어려움, 작은 버그도 커널 크래시 유발                                        |


### 예시

Process/ Thread 관리

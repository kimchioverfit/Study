OSI 7 Layer

OSI 7계층 — 패킷이 지나는 층을 나누는 이유

네트워크를 7개의 층으로 나눠 각 층이 바로 아래층만 의존하게 만든 참조 모델. 실제 인터넷은 이걸 그대로 구현한 게 아니라 TCP/IP 4층 모델에 가깝지만, “이 문제는 몇 계층 문제인가"를 말하는 공용어로 쓰임.

결론부터 아주 쉽게: 편지를 보낼 때 내용(7)·봉투(4)·주소(3)·우체부(2)·도로(1)가 따로 있듯, 각 층은 자기 일만 하고 아래층에 넘김. 받는 쪽은 거꾸로 벗겨 냄. 그래서 와이파이를 이더넷으로 바꿔도(1~2층) 웹 브라우저(7층)는 아무것도 몰라도 됨.

관련: Tailscale — 이 문서의 예시가 나온 곳

🔷 1. 7개 층

층이름단위하는 일대표 예주소
7응용 (Application)데이터사용자가 쓰는 프로토콜HTTP, SSH, RDP, DNS—
6표현 (Presentation)데이터인코딩·암호화·압축TLS, JPEG, UTF-8—
5세션 (Session)데이터대화의 시작·유지·종료(실무에선 7과 뭉뚱그림)—
4전송 (Transport)세그먼트프로세스 간 전달, 신뢰성TCP, UDP포트 (22, 3389)
3네트워크 (Network)패킷네트워크 간 경로 선택IP, ICMPIP 주소
2데이터링크 (Data Link)프레임같은 링크 안의 기기 간 전달이더넷, Wi-Fi, ARPMAC 주소
1물리 (Physical)비트전기·빛·전파로 바꿈UTP 케이블, 광, 2.4/5GHz—

외우는 법: 위에서부터 All People Seem To Need Data Processing.

실무에서 실제로 구분해 부르는 건 L2(스위치, MAC), L3(라우터, IP), L4(포트, TCP/UDP), L7(앱) 네 개임. 5·6층은 대부분 앱 안에 녹아 있음.

🔷 2. 캡슐화 — 내려갈 때 씌우고 올라올 때 벗김

보내는 쪽은 위층 데이터 앞에 자기 헤더를 붙여 아래로 넘김. 받는 쪽은 반대로 벗기며 올림.

L7  [RDP: 클릭 (412,300)]
L4  [TCP 헤더: dst port 3389][RDP: ...]
L3  [IP 헤더: dst 100.101.1.1][TCP ...][RDP ...]
L2  [이더넷 헤더: dst MAC][IP ...][TCP ...][RDP ...][FCS]
L1  0101101001...

각 층은 자기 헤더만 보고 나머지는 그냥 짐(payload)으로 취급함. 라우터(L3)는 IP 헤더만 보고 포트나 내용은 안 봄. 스위치(L2)는 MAC만 봄.

🔷 3. 예시 — 원격 데스크톱 한 번 클릭

Tailscale 문서의 8절 상황. 카페 노트북에서 집 PC로 RDP 클릭을 보내면:

층밖(실제 인터넷)안(터널 속)
L7—RDP “클릭”
L4UDP, dst 56926 (WireGuard)TCP, dst 3389 (RDP)
L3IP 58.x.x.x → 211.x.x.x (공인)IP 100.101.1.2 → 100.101.1.1 (tailnet)
L2Wi-Fi (카페) → … → 이더넷 (집)(없음 — 가상 어댑터는 L3부터)

터널 = L3 패킷을 통째로 L4 UDP 페이로드에 넣는 것. 그래서 안쪽 스택(L3~L7)이 한 번 더 있음. VPN, VXLAN, GRE 모두 이 구조임.

🔷 4. “몇 계층 문제인가"로 디버깅하기

증상계층확인
케이블 뽑힘, 와이파이 안 잡힘L1링크 LED, Get-NetAdapter Status
같은 공유기 기기끼리도 안 됨L2arp -a, MAC 필터
공유기는 되는데 인터넷이 안 됨L3ping 8.8.8.8 (IP), tracert
ping은 되는데 접속 안 됨L4Test-NetConnection -Port 3389, 방화벽, 서비스가 LISTEN 중인지
포트는 열렸는데 로그인 실패L7계정·비밀번호, 프로토콜 버전(NLA 등)

위에서 아래로가 아니라 아래에서 위로 올라가며 확인하는 게 빠름. 아래층이 죽으면 위층은 전부 죽으니까.

🔷 5. 한 줄 요약

각 층은 자기 헤더만 보고 나머지는 짐으로 넘기는 구조. 터널은 그 짐 안에 스택이 하나 더 들어 있는 것.
